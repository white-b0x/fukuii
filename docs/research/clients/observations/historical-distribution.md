## Best-practice synthesis
fukuii already ships a **checkpoint-service + checkpoint-sync skill** (`fukuii-checkpoint-service`): point a fresh ETC/Mordor node at a trusted checkpoint archive (local file or HTTP URL) so it imports a known pivot and starts SNAP sync immediately — a **state pivot**, not a history transport.

**DEFAULT menu:**
- **Hot/cold freezer split** (geth, reth) — migrate ETC blocks past reorg depth out of the mutable RocksDB working set into an append-only, number-addressed flat cold store. Keeps the hot DB small; ties directly to `storage-persistence`. core-geth confirms the ETC shape: the cold store **must retain total difficulty** (the `diffs` table) — the post-merge ETH freezer table set is the wrong template for a PoW successor.
- **Checkpoint-anchor-as-chain-spec-data** (besu) — a trusted `(number, hash, TD)` triple embedded in config and consumed by whatever sync mode runs. This is the near-exact match to fukuii's existing checkpoint-service and the most transferable single idea.

**OPTIONAL(fast-bootstrap):**
- **era1 verifiable HTTP history bootstrap** (geth-origin, besu prepipeline, nethermind, reth era-downloader) — download accumulator-verified segments instead of P2P-syncing history. **Composes with checkpoint-sync**: checkpoint = state pivot (fast to head), era1 = backfilled history (bodies/receipts for archival/RPC) — the two solve different halves of bootstrap.
- **erigon BitTorrent `.seg` + WebSeed** — content-addressed parallel history distribution with a curated preverified-hash trust list served from CDN/GitHub with a mirror fallback; operators can host frozen ETC history on any HTTP/S3 endpoint.
- **nethermind `Init.Snapshot`** — resumable DB-tarball bootstrap (Range + stage-checkpoint + atomic-rename) for a trust-for-speed cold start.

**OPTIONAL(light/custody):**
- **EIP-4444 history-expiry** — drop pre-cutoff bodies/receipts, retain headers+genesis.

**Cross-cutting note:** fixed-block-range file shards make **transport AND expiry fall out of one design** (reth static files, erigon `.seg`) — the same whole-file granularity that lets you seed/copy one file also lets you `rm` it for expiry. Choosing a fixed-range sharded cold format buys both capabilities at once.

## fukuii implications (forward-ref to Phase 3–4, do NOT act here)
Seeds, not verdicts:
- **fukuii checkpoint-service ≈ besu checkpoint-anchor.** The existing checkpoint-service already occupies besu's "ship a trusted pointer, not the history" niche; besu's `Checkpoint (number, hash, TD)` → `SyncState` → SNAP path is the closest reference alignment for hardening/formalizing it.
- **era1/EraE HTTP history bootstrap + BitTorrent snapshots = Phase-4 OPTIONAL fast-bootstrap** that **composes with the existing checkpoint pivot** — checkpoint delivers a recent state root fast; verifiable history segments backfill bodies/receipts for archival/RPC without days of reverse P2P sync. For ETC, the minimal target is the *original* pre-merge era1 (accumulator-committed, checksum-in-filename); geth's later execdb/EIP-4444 and nethermind's EraE beacon machinery are PoS-specific and unneeded.
- **Hot/cold freezer split = a storage-lifecycle adopt** that ties to the `storage-persistence` observation — keep RocksDB's working set small by migrating reorg-safe ETC blocks (with TD retained, per core-geth) into an append-only cold store.
