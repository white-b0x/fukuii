## 1. Scope & modules

L5 builds the consensus **framework** — how fukuii keys a consensus mechanism, dispatches forks,
produces/seals blocks, drives the merge, and admits a *new network or family* without editing shared
code. It sits above execution (L4) and below networking (L6); it **calls down into** `execution`, never
the reverse (inverting the old `ledger ↔ consensus` cycle, §6).

### Three modules (mechanism-category split — OPEN #3 resolved: split now)

`com.chipprbots.fukuii.consensus.*`, three sbt modules, each with explicit `.dependsOn` (an upward edge
is a compile error):

| Module | sbt id | Package | Depends on (down only) | Delivers |
|---|---|---|---|---|
| **consensus-api** | `fukuii-consensus-api` | `…consensus.api` | `execution`, `evm`, `domain` | `ConsensusEngine` trait, `EngineId` marker (**shipped**, not dormant), unified `ForkActivation` dispatch (the L3-owned type), `ProtocolSpec` bundle, the `given NetworkFamily` typeclass + its `given` instances (the registry *definition*; L10 wires it *live* — §"registry ownership"), the consensus-blind assembly pipeline + the narrow `Sealer`/`ValidatorProvider`/`BlockInterface` seams, the conditional merge `EngineSchedule` |
| **consensus-pow** | `fukuii-consensus-pow` | `…consensus.pow` | `consensus-api`, `execution` | Ethash + ETChash seal, ECIP-1010/1041 difficulty-bomb ladder, ECIP-1099 DAG-epoch parameter, ECIP-1100 **MESS** (relocated from ledger), getWork/submitWork sealing + internal CPU miner |
| **consensus-pos** | `fukuii-consensus-pos` | `…consensus.pos` | `consensus-api`, `execution` | Engine-API driver (`newPayload`/`forkchoiceUpdated`/`getPayload`), timestamp-fork dispatch, withdrawals (EIP-4895), blobs (EIP-4844/7691), the fork-choice head/safe/finalized tracker, the PoS payload factory |

**Why split now (not "one `consensus` module, split later").** OPEN #3 in
`.local/docs/phase4/target-architecture.md` was reopened by the multi-network mandate and resolves to
split-from-day-one on two grounds:

1. **besu — our JVM implementation guide — splits consensus per-mechanism from the start**
   (`clients/besu/consensus/{common,clique,ibft,qbft,merge}/` are separate Gradle modules). The
   target-architecture note: *"besu … splits consensus PER-MECHANISM from the start … That is strong
   evidence to do the mechanism-category split now rather than defer it."*
2. **The DAG enforces the family-neutrality invariant structurally.** With `pow` and `pos` as separate
   modules that cannot see each other (both depend only on `consensus-api`), a PoW file physically
   *cannot* import an Engine-API type and vice-versa — the "keep Engine-API/merge concepts out of
   `consensus/pow/`" guard from `cl-engine.md` becomes a compile error, not a review note.

The `poa` mechanism leaf (`EngineId.Clique/Qbft/Bor`) is **enumerated in `consensus-api` but unbuilt** —
it hardens into "add `fukuii-consensus-poa` as a fourth module when NET-02 lands" (§7).

**Layer boundaries** — see §10.

## 4. besu structural mirror (the concrete shapes to follow)

besu is the JVM implementation guide throughout — read its Java alongside geth's Go from line one (the
L0 lesson: the besu lens caught B-BLS-1). The four shapes L5 mirrors:

### 4a. `ProtocolSpec` / `ProtocolSchedule` — fork ruleset ⊥ mechanism (decorate, don't subclass)

besu defines the ~20 forks once as a mechanism-agnostic `ProtocolSchedule`; a mechanism supplies a
`Map<activation, specModifier>` overriding only the 4–6 spec fields that differ (header validator,
difficulty calc, block reward, mining beneficiary). fukuii's L5 mirror:

- **`ProtocolSpec` bundle** (immutable, per-fork) lives in `consensus-api`, assembled from L3 `evm`
  (opcode/fee schedule) + L4 `execution` (reward/finalize) + the mechanism's header validator. This is
  the *"immutable per-fork `ProtocolSpec`-style bundle the actor references; no mutable fork state"*
  target from `.local/docs/phase4/target-architecture.md` principle #3.
- A mechanism (`Ethash`, `EngineApi`, later `Clique`) is a **decorator supplying the field-overrides**,
  not a subclass of a monolithic engine. It gets EVM/gas/fork currency for free.

### 4b. The three PoA seams (G1/G2/G3) — enumerated now, occupied at Batch 7

The SR maps fukuii's designed seams 1:1 onto besu:

| fukuii seam | besu class (path) | Role |
|---|---|---|
| **Sealer** (G1) | `BftBlockCreatorFactory.java` (`.../common/bft/blockcreation/`) | block production / authorization |
| **ValidatorProvider** (G2) | `ValidatorProvider.java` (`.../common/validator/`) | who may seal |
| **BlockInterface** (G3) | `BlockInterface.java` (`.../common/`) + `CliqueBlockInterface.java` (`.../clique/`) | extraData / vote codec |

L5 defines these three traits in `consensus-api` as the narrow seal seam (replacing the old
`sealer: Option[Mining]` coarse handle, §6). PoW occupies `Sealer` with the Ethash getWork strategy;
PoS leaves it `None` (the CL proposes). **Clique/QBFT occupancy is Batch-7/NET-02** — Clique *sealing*
sourced from core-geth (besu stubbed it to `NoopMiningCoordinator`), `ValidatorProvider` + `BlockInterface`
from besu.

### 4c. `TransitionProtocolSchedule` — the merge, as a conditional wrapper

besu's `TransitionProtocolSchedule` + `TransitionUtils<T>(pre, post, flag)` + `MergeCoordinator` route
by one TTD-derived latch. fukuii's L5 merge is a **conditional `EngineSchedule`** (erigon `merge.New`
shape) that:

- wraps the base engine only when `terminalTotalDifficulty.isDefined` — **ETC (no TTD) is never wrapped**
  and stays permanently PoW-legal;
- routes content-derived on `difficulty == 0` (geth `beacon` heuristic), relocating the logic fukuii
  already has in `TransitionBlockHeaderValidator` into a reusable wrapper rather than a header-validator
  object. **Mechanism clarity — content-first, not latch-first:** besu routes on an externally-managed
  `mergeContext.isPostMerge()` **latch** (`TransitionUtils.java:64,77`); geth routes **content-derived on
  `difficulty == 0`** (`consensus/beacon/consensus.go:106,126`) — two distinct mechanisms. fukuii takes
  **geth's content test** to *set* the erigon-style conditional (TTD-gated) latch, **not** besu's
  externally-set `mergeContext` latch.

This is the modest relocation the SR names (B7.0-c Option 2), **not** the per-block config schedule
Batch 5 rightly rejected. besu's `Map<block, builder>` is the reference only for the general
mechanism-migration case (IBFT→QBFT, Batch-7).

### 4d. Private-net origination (data side, Batch 7)

besu's `GenerateBlockchainConfig.java` (`operator generate-blockchain-config`) generates N validator
keypairs and bakes their addresses into genesis `extraData`. This is the NET-02 reference for the
`fukuii-custom-networks` origination path — the data complement to the mechanism seams in 4b.

## 5. Scala 3 idiom targets (native to us — no reference client uses it)

The reference clients inform *structure*; the idiom is ours. L5's specific shapes:

- **`given NetworkFamily` typeclass registry** (the B7.0.5 target). A `trait NetworkFamily` capturing what
  varies per family (engine, fork-schedule axis defaults, reward/finalize hook, seal seam, injected
  oracles). Each family a `given` instance (`given NetworkFamily = PowEtcFamily`, `given …= PosEthFamily`),
  auto-derived + type-checked, discovered through a **static registry** (`ServiceLoader`-style, mirroring
  nethermind's explicit `EmbeddedFamilies` list) — reth's compile-time safety *inside* nethermind's
  single-binary runtime selection, **without** reth's one-crate-per-family or nethermind's reflection.
  The two current families flow through the typeclass; the registry is populated speculatively no
  further (YAGNI — §7). **But the *seam depth* is sized now, even though occupancy defers**
  ([[planned-work-is-scope-floor]]): the `NetworkFamily` fields must be able to express the full SR
  family-size spectrum (`consensus-engines.md:72-73`) — thin (Gnosis: engine reuse + spec overlay) →
  heavy sidechain (Bor: engine + injected Heimdall/bridge oracles) → **rollup (OP/Taiko: a new tx-type
  `DepositTx 0x7E` + a swapped block-processor/header-validator/fee-calculator cluster)** → **alt-BFT
  (XDC: a custom domain block-header type *and* a custom block tree — the stress case)**. The SR target

   NetworkFamily` typeclass registry yet; engine dispatch is a hand-maintained `match`."* L5 defines the

   the typeclass, not read from a shared `networkType` enum (family-neutrality invariant, §3).

4. **Break the `consensus ↔ ledger` cycle — invert it (MESS/branch-resolution moves into L5).** AS-IS:
   *"`consensus → ledger` 17 edges, and the reverse … Mechanism seam and block pipeline are not cleanly
   layered — they reach into each other."* Target DAG (`.local/docs/phase4/target-architecture.md`):
   *"consensus CALLS execution; MESS/branch-resolution moves to L5."* L5 owns `evaluateBranch` /
   branch-resolution and the MESS compute; `execution` (L4) no longer holds a `ConsensusEngine`.
   `finalizeBlock` calls **down** into `execution`'s reward primitive, never the reverse. (The Olympia
   ECIP-1111 basefee→Treasury **redirect** lands at this same L4 finalize hook — a state-root-affecting
   beneficiary credit, **not** ETH's London burn to `address(0)`; §3.)
   - **Cross-layer wiring — PoW seal validation is the anti-spoof foundation of the L6 §5 TD-sourcing
     invariant.** L5's `EthashBlockHeaderValidator.verifySeal` (core-geth `ethash.verifySeal`, §"per-concern
     authorities") is *what makes a header's `difficulty` real*: a header's difficulty counts toward
     chain-weight **only if its Ethash seal hashes below that difficulty target**, so a peer cannot
     fabricate weight (the fake-heaviest-chain / network-steering attack) without doing the PoW.
     Consequently L5's `evaluateBranch` / MESS chain-weight comparison reads **locally-stored,
     PoW-validated chain-weight** (the L2 first-class `chain-weight` CF) and **never** a wire `Status.td`
     field — which is exactly why PoW fork choice survives eth/69+'s removal of TD (L6 §5). **End-to-end
     wiring: L1 `difficulty` → L5 `verifySeal` → L2 atomic `chain-weight` write → L7 `PivotBlockSelector`
     sums only L5-validated headers → L5 MESS scores only validated branches — no link reads TD from the
     wire.** **forge owns the seal-validation end** (Ethash PoW / state-root-adjacent); the **MESS end is
     banksy-owned, forge-cosigned** (subjective fork-choice, non-state-root — per §9 and the
     consensus-change protocol), not forge-owned.
5. **Break the `consensus ↔ blockchain/sync` cycle — and make `ConsensusResult` a reorg-aware event
   source, not just internal sync-plumbing. consensus-api is the sole home of the reorg-aware wire ADT.**
   AS-IS: *"`ConsensusAdapter` imports `blockchain.sync.regular.*` result types … the branch-import
   driver is entangled with the sync layer's message types."* L5's branch-import driver speaks a
   consensus-owned result ADT (`ConsensusResult`); the sync layer (L7) adapts *to* it, depending
   **up→down** only. **The reorg-aware event source is L5's, because L5 owns reorg authority**
   (fork-choice / `evaluateBranch` / MESS) — L4 executes blocks and emits per-block
   `BlockExecutionOutcome`s (block + state-diff, `L4.md §5/§7`), and L5's branch-import driver aggregates
   those with its reorg decisions into **the canonical wire ADT defined once in `consensus-api`:**
   `enum ChainNotification { case Committed(chain); case Reorged(old, new); case Reverted(chain) }` (reth
   ExEx 3-case **chain-segment** shape). This is the *one* definition — L4 does **not** define a wire
   `ChainNotification` (its per-block type is `BlockExecutionOutcome`), and L9's `grpc-seam` **imports
   this ADT from `consensus-api`** (depends down on it, §10) rather than redefining it. Adopt reth ExEx

   finished height), and a `FinishedHeight` prune-barrier lets a downstream L2 consumer gate storage
   pruning on `min(consumer heights)` (the R7/L2 hook — designed now even though the consumer is later).

   ad-hoc callback. **One reorg type, not two:** the branch-import driver's internal `ConsensusResult` and
   the external wire `ChainNotification` are a deliberate **internal-result → external-wire pair** (or a
   single type) — *not* two overlapping reorg ADTs; the build must confirm they do not duplicate.

## 9. Risks & consensus-critical flags

**All of L5 is consensus-critical.** Per `.agents/protocols/consensus/consensus-change-protocol.md`, the
mandatory gate applies to every module here:

- **PoW-seal anti-spoof / TD-from-local-chain-weight — see §6 point 4.** `verifySeal` (Ethash PoW) is the
  security boundary that makes a header's `difficulty` real: a peer cannot fabricate chain-weight (the
  fake-heaviest-chain / network-steering attack) without doing the PoW; weight counts only from
  seal-validated headers, and MESS scores only validated branches. Fork choice sources TD from the L2
  local `chain-weight` CF, never a wire `Status.td` (L6 §5). **Seal-validation end is forge-owned; the MESS
  end is banksy-owned/forge-cosigned.** Flagged here for discoverability; the wiring is §6 point 4.

- **forge (PoW: ETC/Mordor)** gates `consensus-pow` *before* implementation: Ethash/ETChash, ECIP-1010/
  1041/1099/1017/1100, difficulty, `forBlock()` block-number dispatch, `EtcOlympiaOpCodes`. Byte-perfect
  vs core-geth (FROZEN).
- **beacon (PoS: ETH/Sepolia)** gates `consensus-pos` *before* implementation: Engine-API driver,
  timestamp-fork dispatch, withdrawals, blobs, `EthOsakaOpCodes`, the timestamp-aware `forBlock()`
  overload. Byte-perfect vs go-ethereum (+besu).
- **Shared (`consensus-api`)** — the `ProtocolSpec` bundle, fork dispatch, and reward-hook wiring touch
  both families → **forge + beacon jointly**.

**The state-root litmus (forge/beacon vs banksy).** *Does the change alter the state root?* YES →
forge/beacon. NO, and operator-tunable without a hard fork → banksy. The **banksy co-review interface**
(bidirectional, not a one-way handoff):

- **MESS / ECIP-1100** — **banksy owns, forge co-signs.** Subjective, non-state-root (changes which valid
  chain a node *prefers*, never whether a block is valid). It relocates into `consensus-pow/mess/` at L5,
  but its call site stays the branch-resolution/fork-choice hook, and **no MESS change lands without a
  forge co-review** (its purpose is reorg/51%-attack resistance).
- **ECIP-1017 emission + ECIP-1111 base-fee floor/Treasury routing** — **forge owns, banksy consults.**
  State-affecting (balances, Treasury credit) → forge's to implement, but they define the security-budget
  economics banksy's ECIP-1122 tip floor is sized against → banksy in the room before either lands.
- **Block-production tx-selection / ECIP-1122 min-tip floor / gas-target schedule** — **banksy owns.**
  `prepareTransactions` ordering and the Olympia-gated min-tip filter are admission/selection policy, not
  consensus (no state-root effect). L5 hosts the consensus-blind assembly pipeline; the *selection policy*
  inside it is banksy's.

**Per-instance isolation — make the immutable-shared ⊥ per-instance split explicit (R2).** L5 runs inside
the concurrent multi-`ChainInstance` runtime (`multi-network.md:99-109` `FukuiiRuntime`/`ChainInstance`),
so every piece of L5 state is classified one of two ways, by construction:

- **Immutable-shared** (safe across instances): the `NetworkFamily` registry and the derived `ForkSchedule`
  — *"derived, never a second source of truth"* (`multi-network.md:213-217`).
- **Per-`ChainInstance` mutable** (never a process-global singleton): the PoW mining bundle / coordinator,
  the Engine-API payload + fork-choice caches, and the 2-entry PoW/DAG `AtomicReference` cache. Each is
  spawned per instance and threaded, never static.

This is R2's *"no global singletons / mutable statics anywhere L0–L9"* invariant applied to consensus (the
SR states the runtime shape; L5 makes the split explicit). The litmus (`grep 'object … { var … }'`) is a
DoD check: a global mining coordinator or a JVM-wide payload cache is an isolation break that fails the gate.

**Known traps to catch at the gate:**

1. **`else-means-ETC` fallthrough** — the whole reason L5 ships `EngineId`. Any code path that resolves a
   family via a network-name default, or a surviving `defaultEngineIdFor` binary, fails the DoD. Positive
   keying only.
2. **Fork-name-for-the-wrong-network** — `Eth*` and `Etc*` opcode/fee-schedule objects must never cross
   (`scala3-style.md` ratchet). The old unprefixed-`OlympiaOpCodes`-was-actually-Cancun trap
   (repaired `b46e21ea1`) is the canonical incident. `EtcOlympiaOpCodes`/`EtcOlympiaFeeSchedule` are
   ETC's; `EthOsakaOpCodes`/`EthCancunFeeSchedule` are ETH's — a fork codename never stands for the wrong
   network.
3. **Family-neutrality leak** — no `isEtc()` / `is_optimism()`-style branch in neutral `consensus-api`
   code; inject through the `NetworkFamily` typeclass. erigon's `FrozenBorBlocks` in a shared reader is
   the counter-example.
4. **The merge wrapper must stay conditional** — ETC has no TTD and must **never** be wrapped by the
   `EngineSchedule`; a mandatory (geth-style) wrap would make ETC PoS-transition-eligible, a chain-split
   risk. core-geth's config-neutralized inertness is the reference (presence ≠ activation).
5. **Engine-API concepts must not bleed into `consensus-pow`** — enforced structurally by the module
   split (§1), but the gate still checks no `pos` type is referenced from `pow`.
6. **only-fcU-moves-head** — the load-bearing Engine-API invariant. `newPayload` validates + inserts
   without advancing the head; only the FCU path moves the best-block pointer. Getting it wrong desyncs
   the EL/CL pair.
7. **Built-but-unshipped** — the dominant old-fukuii failure. The `EngineId` marker, the `NetworkFamily`
   typeclass, and the `ForkActivation` collapse are GREEN **and wired** at the DoD, never "exists but
   dormant" like the AS-IS seam.

**Irreversible = 10× thought — the fork-id `10^18` "Olympia pending" sentinel is byte-exact.** Consensus
rules and the fork-id CRC32 input ordering (`ForkBlockNumbers.all`) are one-way doors — reorder only under
forge/herald review; a wrong fork-id partitions the network. **A specific L5-can't-subsume-L2 trap:** the
`10^18` "Olympia pending" sentinel (`ForkId.scala:81-84`, `knownSentinels:29-31`) must survive *into* the
fork-id CRC32 unchanged. The unified `ForkActivation` derivation's `byBlockIfReal` collapses `10^18 → Never`
(a pending fork is absent *for dispatch*), which is correct for activation but **loses the pending-vs-absent
distinction the fork-id needs** — so the fork-id path reads the sentinel from the L2 field and re-appends
it. This is the one place L3's `ForkActivation` view cannot subsume the raw L2 fork-block data.
**Cross-confirmed against the ETC byte-authority:** core-geth's `olympiaMainnetBlock = 1_000_000_000_000_000_000`
(`config_classic.go:32`) is the **same** 10^18 value — the sentinel is core-geth's own not-yet-scheduled
Olympia placeholder, not a fukuii-internal marker, so the bar is *must match core-geth's placeholder
semantics and flip in lockstep when the real Olympia block is scheduled* (a forge/herald-gated coordinated
change, not an independent fukuii edit). **DoD:** a
proving test that the derived fork-id CRC32 is byte-identical to AS-IS for an Olympia-pending config;
reorder `ForkBlockNumbers.all` only under herald/forge review.

## 10. Layer boundaries

Durable statement of what L5 owns and what it explicitly does not (so L6+ build against a stable seam):

**L5 owns:**
- The `ConsensusEngine` trait, `EngineId`, and the `given NetworkFamily` typeclass + registry (family
  selection, positive-keyed).
- Unified `ForkActivation` fork dispatch (the sole seam; the L4/L3 fork-schedule data feeds it).
- The consensus-blind assembly pipeline + the narrow `Sealer`/`ValidatorProvider`/`BlockInterface` seams.
- PoW seal (Ethash/ETChash), the ECIP difficulty/emission rules' *consensus* invocation, getWork/submitWork.
- The PoS Engine-API **driver** (`newPayload`/`fcU`/`getPayload` semantics, fork-choice application,
  payload factory) and the conditional merge `EngineSchedule`.
- **MESS compute + branch-resolution / branch-import driver** (relocated in from the old ledger).
- **The reorg-aware `ChainNotification` wire ADT** (`Committed(chain)` / `Reorged(old,new)` /
  `Reverted(chain)`, reth 3-case segment shape) — defined **once** in `consensus-api` (§6.5), fed by
  L4's per-block `BlockExecutionOutcome`s, imported downward by L9's `grpc-seam`. L5 also owns the
  replay-by-height + monotonic-ID guarantee L9's resume cursor depends on.

**L5 does NOT own (and why):**
- **Reward/finalize arithmetic, block execution, receipts** — L4 `execution`. L5 `finalizeBlock` calls
  *down* into execution's reward primitive; the ledger↔consensus cycle is inverted.
- **Opcode/gas/fee schedules** — L3 `evm`. A `ProtocolSpec` references them; L5 does not author them.
- **The Engine-API HTTP/JWT/JSON transport** (`EngineApiHttpServer`, `JwtAuthenticator`, the version-vs-
  fork codec matrix) — L9 `rpc`. L5 owns the driver semantics, not the wire transport.
- **getWork/submitWork *RPC method* plumbing** (`eth_getWork`/`eth_submitWork` JSON dispatch) — L9 `rpc`.
  L5 owns the seal seam and the candidate cache the RPC calls into.
- **Tx-selection *policy* (ordering, tip/gas-target floors, ECIP-1122 min-tip)** — banksy's, invoked
  inside L5's consensus-blind pipeline but not authored here (state-root litmus).
- **P2P wire, ForkId gossip, block propagation** — L6 `network`. L5 produces the fork-schedule the
  fork-id CRC32 is computed over; herald owns the wire encoding.
- **Sync strategies (fast/regular/snap/checkpoint), the block-import queue** — L7 `sync`. L7 adapts *to*
  L5's `ConsensusResult` ADT; the consensus↔sync cycle is broken.
- **Actor guardian-tree wiring, the concurrent multi-`ChainInstance` runtime** — L10 `node`. L5 defines
  the `Command` ADTs its actors speak; L10 spawns and injects them.
- **Embedded CL (Caplin / blsync)** — a separately-gated future track (CL-RESEARCH-EMBED-01), not L5.
- **PoA (`Clique`/`Qbft`/`Bor`) implementations, family-ships-own-chainspecs, private-net origination** —
  Batch-7 / NET-01 / NET-02. The `EngineId` cases and the three seams are *enumerated* here; occupancy is
  scheduled, not built at L5.
