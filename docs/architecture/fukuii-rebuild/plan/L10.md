L10 is the **composition root** — the one place that wires everything and the structural fix for the
old 13-package strongly-connected component. `node` depends **down on all of L0–L9 and nothing
depends on it**; that single rule dissolves the `nodebuilder↔consensus` cycle at the root. It is also
where fukuii's **differentiator** lives: the **concurrent multi-`ChainInstance` runtime** — many
networks in one JVM binary, hard-isolated — and where the B7.0.5 `NetworkFamily` `given`-typeclass
registry is finally **wired live** (the dormant `EngineId` marker layer, shipped at L5, is activated
here). `cli` is the key-management / genesis-alloc / address-derivation surface, depending only on
`keystore`/`domain`/`crypto`.

## 2. SR slots & verdicts

### `observations/node-lifecycle.md` (→ node)
- **DEFAULT (container):** ordered-start / reverse-stop `Lifecycle` service container (geth) —
  "registration order *is* the dependency DAG; strict reverse teardown means nothing stops while a
  later-registered dependent still runs." Map to "a top-level Pekko supervisor… with ports/RPC owned
  centrally, and drive registration-order-respecting teardown through **`CoordinatedShutdown`
  phases**"; keep besu's *phases* (external-services before main-loop before plugins) "distributed
  across the supervisor tree rather than a 3000-line god-command." **Split the teardown citation:** the
  mechanical reverse-*order* is **geth's** (`node.go:289`, `for i:=len-1`); besu's `Runner.stopServices`
  is **hand-ordered + per-service-bounded** (30s `waitForServiceToStop`), *not* a mechanical reverse —
  so `CoordinatedShutdown` phases supply the ordering (geth's lesson) while each phase task carries a
  per-task bound (besu's lesson). Do not build a "reverse-order registration list" expectation from
  besu; besu has none.
- **DEFAULT (shutdown, custody-grade):** graceful teardown + an **unclean-shutdown DB marker** (geth
  `ShutdownTracker`) + "**explicitly wait for every fire-and-forget task to release its DB
  transaction *before* closing the DB**" (erigon `WaitIdle` — "the reverse-Lifecycle order alone is
  not enough"). **Ordering (load-bearing):** `MarkStartup` fires **after a successful boot** (not at
  process entry) + a refresh loop → graceful stop phases → **drain: `WaitIdle` over an explicit
  registry of in-flight DB-touching fire-and-forget tasks** (L2 storage commit, L7 sync, L4 execution
  persist) → **pop the marker** → **`dataSource.close()` last**. The drain barrier is only as complete
  as that registry (erigon drains one specific forkchoice goroutine; fukuii must enumerate *which*
  tasks hold DB handles), and a hang mid-drain must leave the marker **set** — correctly signalling
  unclean on the next boot.
- **DEFAULT (config):** layering **CLI > env > HOCON > profile** (besu `CascadingDefaultProvider` +
  shipped named multi-network profiles); core-geth's preset mapping defines "what `--classic`/
  `--mordor`/Sepolia resolve to (chainID/genesis/bootnodes/DNS/datadir/gas-limit)." **Nuance:**
  `CascadingDefaultProvider` orders **defaults only** (env > TOML > profile); the **CLI-wins** tier is
  picocli's *inherent* explicit-arg-over-any-default-provider precedence — which HOCON does **not**
  have. So fukuii must build the CLI/`-D`-override layer **explicitly** above HOCON (it is not free),
  and the DoD precedence test must exercise that CLI-override tier as a *fukuii-built* layer, not an
  assumed one.
- **OPTIONAL(enterprise extension):** a plugin/extension SPI (besu `ServiceLoader` /nethermind
  self-registering) — "the container-side of the **B7.0.5 NetworkFamily registry**"; port the
  *self-declaration* idea as "a Scala 3 `given`-based typeclass registry (compile-checked instances +
  a static `ServiceLoader`-style list), **not** reflection/Autofac."
- **OPTIONAL(product-family / dRPC seam):** erigon embedded-or-remote component wiring
  (one-interface-two-impls, `direct.*` shim vs gRPC client) — "the same binary runs as a **monolith
  OR distributed**"; the DRPC-GATEWAY-01 lever (defined at L9, wired here).
- **DEFAULT (guard, with caveat):** registration-after-start = panic (single-shot FSM); caveat: a
  strict one-shot FSM forbids dynamic service addition (besu had to bolt on `resetState()`). For fukuii
  the caveat is **load-bearing**: `TestNode` per-test fork reconfiguration (the `july-fourth`
  `AtomicReference[BlockchainConfig]`) and ephemery-style in-process restart are exactly besu's
  `resetState()` case — so the single-shot FSM **must ship a guarded reset transition** (the
  `resetState()` analog) or per-test/ephemery reconfig has no home. State it as a DoD vector.
- **OBSOLETE (for multi-node/embedded):** global mutable singletons for log/metrics/config — "fukuii
  should scope observability to the node instance, not the process." **The full `july-fourth` leak-list
  (G-NL1), not just Bug 29:** the shared static metrics registry (Bug 29, the direct L8 dependency);
  `object ShutdownHookBuilder` (`NodeBuilder.scala:1071`, process-scoped); the `ioRuntime` diamond
  (`NodeBuilder.scala:1172` — `PeerDiscoveryManagerBuilder` and `PortForwardingBuilder` both declare
  the same `lazy val`, resolved by a hand override, not structurally); and the **direct `object
  Config` reads that bleed the default instance into per-`ChainInstance` code** —
  `StdNode.loadGenesisData` reads `Config.testmode`, `startPeriodicDBConsistencyCheck` reads
  `Config.Db`, `GraphQLServiceBuilder` reads `Config.config`. Each is an R2 isolation break; the DoD
  grep (§8) is `object … { var … }` + direct `Config.` reads in per-instance code.
  **Retirement homes (owning layer — each must be named so a lower-layer plan carries it, else it
  re-surfaces at integration):** the `ioRuntime` diamond → **L6** (`PeerDiscoveryManager`/
  `PortForwarding` receive a per-instance `IORuntime` **injected at wiring**, not a hand override at
  L10); `GraphQLServiceBuilder`'s `Config.config` → **L9** (an injected `InstanceConfig` at the GraphQL
  service boundary); the `System.setProperty` logback-file sysprop → **L8** (per-instance logback
  config, not a process-global sysprop — two instances cannot each pick a logback config via one
  sysprop); `Metrics.configure` → **L8 Bug-29** (already homed). Keep the grep DoD, but carry these as
  cross-layer coherence assertions.
- **OBSOLETE (consciously ruled out):** nethermind's concurrent topo-sorted step-init (`IStep` +
  `EthereumStepsManager`, Kahn-sorted, independent steps run in parallel) — "declare-deps init that
  **hides undeclared-dependency bugs under races**" (they pass under most scheduling, fail under a
  race; the DAG is only as correct as its declarations). Use **supervised phase-ordering** across the
  guardian tree instead (the geth registration-order DEFAULT, made explicit by `CoordinatedShutdown`
  phases) — never concurrent step init.

## 4. besu structural mirror

- **`ServiceManager` → spawn-time `ActorRef` injection.** besu's `Map<Class,BesuService>` typed
  service container, read/written by core and plugins, is the JVM analog of the Pekko-Typed target:
  dependencies handed to an actor **at spawn** through a typed context (besu's "`register(ctx)` once,
  field-store it, no global singleton lookup"), never a late global lookup — the direct counter to
  nethermind's `INethermindApi` god-context and to fukuii's `july-fourth` cake god-trait.
- **`Lifecycle` FSM → behavior-as-state-machine.** besu's explicit FSM (`UNINITIALIZED→…→STOPPED`,
  `checkState`-guarded) maps to distinct Pekko-Typed `Behaviors` (Initializing → Starting → Running →
  Stopping → Stopped); an illegal transition is a wrong-state message, not a silent no-op.
- **Phase-ordered `Runner` → phases distributed across the supervisor tree.** Keep besu's phase
  ordering (external-services before main-loop before plugins) but **distribute it across the
  supervisor tree, not a 3000-line `BesuCommand`** — explicitly avoiding both besu's god-command and
  fukuii's `july-fourth` 1181-line `Node` god-trait (the two named anti-patterns).

## 5. Scala 3 idiom targets

- **Typed guardian tree.** A top-level `Behavior[GuardianCommand]` (sealed ADT) spawns one child per
  subsystem, each constructed with its `ActorRef[Command]` dependencies **injected at spawn** (besu
  `ServiceManager` shape); no `actorSelection`/global lookup, no `Behavior[Any]`.
- **Lifecycle FSM as Behaviors.** `Initializing`/`Starting`/`Running`/`Stopping`/`Stopped` as distinct
  behaviors; `CoordinatedShutdown` phases drive reverse-order teardown + the clean-shutdown DB marker
  + drain-before-close. The single-shot guard (registration-after-start = panic) ships a **guarded
  reset transition** (the besu `resetState()` analog) so `TestNode` per-test fork reconfiguration and
  ephemery in-process restart have a legal path — a DoD vector, not an escape hatch. Replaces the `july-fourth`
  Classic root (one Classic `ActorSystem` +
  `classicSystem.spawn` + `.toTyped` surface) with a **Typed guardian root**. The two `july-fourth`
  **secondary ActorSystems** — today created as *sibling roots outside* the main tree and torn down by a
  hand-ordered `Await` list — are handled **differently, per RX-L10-07** (a second `ActorSystem` cannot
  be a literal child of another guardian, and L9 deliberately **retains** the Engine-API's dedicated
  system as an isolation improvement, `L9.md §1`): the **periodic-DB-consistency check** folds into the
  guardian tree as a child behavior; the **Engine-API server** (port 8551, its own `ActorSystem` +
  `IORuntime`) **keeps its dedicated system** and is shutdown-sequenced by **registering its
  `terminate()` as a `CoordinatedShutdown` phase task** — not by nesting. This preserves the L9 Engine-API
  isolation *and* gives ordered teardown (the L9↔L10 seam, now consistent both ways).
- **`given NetworkFamily` registry.** Compile-checked typeclass instances + a static
  `EmbeddedFamilies` list (the `ServiceLoader`-style enumeration, no reflection); `ForkActivation`
  (`ByBlock`/`ByTimestamp`/`ByTotalDifficulty`/`Never`, the L3-owned type — reth `ForkCondition` is the
  cited prior art, `L3.md §2.1`) as the unified positive-keyed dispatch; the dormant
  `EngineId.fromMarkers` (unknown throws, >1 throws) is wired as the live selection path — **no
  `else`-means-ETC/`else`-means-ethash fallthrough** (the named trap).
- **Per-instance scoping.** Each `ChainInstance` owns its own observability registry (L8 Bug 29 fix),
  its own `InstanceConfig`, its own supervisor subtree, ports, and DB handle — **no process-global
  mutable state**. Retire the whole `july-fourth` leak-set (§2 G-NL1): `object Config` + the direct `Config.`
  reads that bleed it (`loadGenesisData`/`Config.testmode`, `startPeriodicDBConsistencyCheck`/
  `Config.Db`, `GraphQLServiceBuilder`/`Config.config`), the `Metrics.configure` static, `object
  ShutdownHookBuilder`, the `ioRuntime` diamond, and the `System.setProperty` network-selection
  mutation. An **R2 isolation-regression grep** is a standing DoD gate (§8), not a one-time cleanup.
- **Config.** HOCON + a shipped-profile layer beneath + an env layer above (besu
  `CascadingDefaultProvider`: CLI > env > HOCON > profile) — but `CascadingDefaultProvider` orders
  **defaults only** (env > HOCON > profile); the **CLI >** tier is picocli-inherent in besu and has
  **no HOCON equivalent**, so fukuii builds the CLI/`-D`-override layer explicitly. The `july-fourth` network
  swap — a whole conf file
  selected by mutating `config.file`/`config.resource` sysprops + `ConfigFactory.invalidateCaches()`
  (`App.setNetworkConfig`), with `public`/`enterprise` applied as more `System.setProperty` — is
  **itself an R2 break** (two instances cannot each pick a network through a process-global sysprop);
  the profile layer replaces it. core-geth's preset mapping defines what each profile resolves to
  (chainID/genesis/bootnodes/DNS/datadir/gas-limit).
- **cli.** Subcommands as an `enum` with a `given`-dispatched handler; keys are opaque and never
  logged.

## 6. Improvements over old fukuii (`july-fourth` gaps this layer closes)

From `.local/docs/research/clients/fukuii/node-lifecycle.md`:

- **Retire the cake god-trait.** `july-fourth` wires the node with "~60 `*Builder` traits… a single god-trait
  `Node` (`NodeBuilder.scala:1092-1170`) mixes in ~90… one 1181-line file," with a genuine
  `nodebuilder↔consensus` self-type cycle (`MiningBuilder.scala:9-13`) and "nodebuilder sits at the
  coupling apex." The rebuild replaces it with the Typed guardian tree + spawn-time injection, and
  the DAG makes `node` depend down only — **nothing depends on it** (the SCC fix). **VERIFY caveat**
  (SR `clients/fukuii/node-lifecycle.md` §Gotchas): the "13-package strongly-connected component"
  size/centrality asserted elsewhere is *unconfirmed* in `dependency-graph.md` — the verified evidence
  is the **concrete named cycles** (`nodebuilder↔consensus` above, `db↔mpt`, `network→blockchain`,
  `jsonrpc→almost-everything`), so rest the improvement-over-`july-fourth` claim on those, not on the SCC
  figure.
- **Lifecycle FSM, not imperative `start()`/`shutdown()`.** `july-fourth` `BaseNode.start()` is "a hand-ordered
  six-phase method" and `shutdown` "a hand-ordered list of `tryAndLogFailure` steps," with "**no
  `CoordinatedShutdown`**." The rebuild uses the Lifecycle-as-Behavior FSM + `CoordinatedShutdown`
  phases.
- **Custody-grade shutdown.** `july-fourth` has "**No unclean-shutdown DB marker**" (unlike geth
  `ShutdownTracker`) and "`dataSource.close()` is only 'last in the list,' not gated on every
  fire-and-forget task having released its DB handle — the exact hazard erigon's `WaitIdle`… exists
  to prevent." The rebuild adds the boot-time marker and the drain-before-close gate.
- **Retire the `StorageConsistencyChecker` auto-shutdown-on-gap (G-NL2).** `july-fourth`,
  `StorageConsistencyChecker` walks the block-number→hash→header chain and **calls `shutdown()` on any
  gap** — dangerous enough that three skip-guards (post-SNAP, mid-SNAP "Bug 28", Engine-API optimistic
  import) had to be bolted on to stop it turning a *recoverable restart into a wipe-and-resync*. The
  rebuild removes the auto-shutdown: corruption defence is the unclean-shutdown marker (detect) + the
  boot-time `fixDatabase` recovery path (repair), never a self-inflicted stop-on-gap.
- **The concurrent multi-`ChainInstance` runtime — the differentiator, made truly isolated.** `july-fourth`
  `FukuiiRuntime` "runs multiple *whole* nodes/JVM… multi-instance, not one-interface-two-impls," but
  "process-global singletons leak into per-instance code": `object Config`, `Metrics.configure`, and
  `setNetworkConfig`'s `System.setProperty` + `ConfigFactory.invalidateCaches()` mutation "bleed into
  multi-instance runs" and are "in tension with `FukuiiRuntime`'s multi-instance premise." The rebuild
  makes each `ChainInstance` **hard-isolated** — own registry (L8), own config, own supervisor subtree
  — so **one binary runs many networks concurrently with real isolation**. This is the product thesis
  (memory `sr-phase3-fukuii-7th-client`, `fukuii-mission-strategic-context`): the enterprise
  single-binary multi-network runtime.
- **Wire the dormant B7.0.5 registry + positive-keyed `EngineId`.** `july-fourth`: the only config-driven
  component selection is the mining protocol switch (`MiningBuilder.scala:61`) and a degenerate
  `VmSetup` switch; there is **no plugin SPI**. The rebuild wires the `given NetworkFamily` registry
  and activates `EngineId.fromMarkers` — replacing the `else-means-ETC` binary default with positive
  keying (the "SHIP it" the L5 plan carries).

## 9. Risks & consensus-critical flags

- **NOT consensus (composition) — but family dispatch gates *which* consensus engine activates.** The
  `NetworkFamily` registry + `EngineId` marker selection is not itself consensus, but a **wrong
  selection is a chain-split-class hazard** (the `else-means-ETC`/`else-means-ethash` fallthrough the
  risk register flags). The positive-keyed `EngineId.fromMarkers` (unknown throws, >1 throws) **must**
  replace the binary default; **forge/beacon co-review the family-dispatch wiring** even though the
  container itself is non-consensus.
- **The multi-`ChainInstance` isolation invariant.** Two networks in one binary must **not** share
  mutable state — registry, config, DB handles, ports, `ActorSystem`. Bug 29 (the `july-fourth` shared static
  metrics registry) is the canonical violation; the per-instance registry from **L8** is the hard
  precondition. Inject family knobs **through** the typeclass, never into shared readers (no
  `isEtc()`/`is_optimism()` — erigon's `FrozenBorBlocks` leak is the counter-example).
- **Built-but-unshipped is the DOMINANT node-layer risk** — the precise old-fukuii failure mode (a
  mechanism scaffolded, cutover never finished; the `july-fourth` `EngineId` seam is exactly this — built,
  guarded, dormant). The DoD bar is **GREEN and wired**. Do not scaffold the `NetworkFamily`,
  plugin-SPI, or embedded-or-remote seams without a live, tested default.
- **Global mutable singletons must not survive.** The OBSOLETE verdict (process-global log/metrics/
  config) is binding: scope observability, logging, and config to the `ChainInstance`, never the
  process — retire the full G-NL1 leak-set (§2): `object Config` + its direct bleed-through reads
  (`loadGenesisData`/`startPeriodicDBConsistencyCheck`/`GraphQLServiceBuilder`), the
  `Metrics.configure` static, `object ShutdownHookBuilder`, the `ioRuntime` diamond, and the
  `System.setProperty` network-selection mutation. Each leak has a **named retirement home + owning
  layer** (§2): `ioRuntime` → L6, GraphQL `Config.config` → L9, logback sysprop → L8,
  `Metrics.configure` → L8 Bug-29 — carried as cross-layer coherence assertions so a lower layer owns
  each site. The **R2 isolation-regression grep is the standing gate** (§8), not a one-time cleanup.
- **Config/dep changes are gated.** Any new dependency (a CLI-parsing lib, a config-profile lib) routes
  to **sentinel** (evidence-based, operator-gated); no unilateral bumps.

## Layer boundaries

- **L10 owns:** the composition root — the Typed guardian tree, the Lifecycle FSM, the
  `CoordinatedShutdown`/marker/drain shutdown discipline, the concurrent multi-`ChainInstance`
  runtime, the wired `NetworkFamily` registry, and the CLI tool.
- **L10 does NOT own:** any subsystem's *behavior* (it only *wires* L0–L9); the family-*selection*
  logic (`EngineId.fromMarkers` is built at L5 `consensus-api` — L10 *activates* it); consensus rules
  (forge/beacon); the exec-extension framework it may deploy monolith-or-distributed (L9 `grpc-seam`);
  the per-instance `StorageProfile` *selector* (L2 owns it — L10 only wires each instance's chosen
  mode); the auth-gate *mechanism* (L9 owns the `Principal`/`Capability` gate — L10 only scopes it per
  instance). The **CI auto-maintenance hooks** (F12/R10 — the reth `update-book-cli` +
  `git diff --exit-code` regenerate-and-verify gate for the generated CLI/RPC-method reference) are
  **setup-owned and sentinel-governed**; the CLI subcommand surface and the RPC-method registry they
  document live here and at L9, so **L10 exposes the runtime surfaces the gate documents, it does not
  own the gate.**
- **Down-only edges:** `node → {all of L0–L9}`, `cli → {keystore, domain, crypto}`. **Nothing depends
  on `node`** — that is the structural fix for the old 13-package SCC (an upward edge is a compile
  error). `cli` is deliberately *not* downstream of `node`.
- **The dRPC / product-family lever lives here:** L9 *defines* the one-interface seams; L10 *decides*
  the in-proc-shim-vs-gRPC wiring per component and per `ChainInstance` (DRPC-GATEWAY-01, the
  monolith-or-distributed choice).
