## 1. Scope & modules

**Module:** `evm` · **package:** `com.chipprbots.fukuii.evm.*` · **depends on:** `domain`, `crypto`,
`rlp` (down-only DAG edge; the module is already clean at this shape today — keep it that way, no
`storage`/`execution`/`consensus` edge).

What the layer builds — the bytecode machine and everything that is *fork-selected* about it:

- The **opcode set** — behavior-bearing opcode objects (`execute`, stack `delta`/`alpha`, gas), the
  network-prefixed per-fork bundles (`Etc*`/`Eth*`).
- The **gas schedule** — the per-fork cost model injected into every opcode and precompile.
- The **stack/memory/word machine** — the immutable `ProgramState`, 1024-deep stack, memory, the
  `@tailrec` interpreter loop, `call` (Θ) / `create` (Λ) entry points.
- **Fork dispatch** — the **`ForkActivation`/`ForkSchedule` family-blind seam that already exists at
  this layer** (`ForkActivation{ByBlock,ByTimestamp,ByTotalDifficulty,Never}` + `ForkSchedule`,
  reth-`ForkCondition`-cited). The layer's headline structural change is to **collapse the two legacy
  `EvmConfig.forBlock` overloads into one `forBlock(header, schedule)`** — the header carries both
  number and timestamp; the schedule's per-activation axis decides which boundary each fork gates on
  (besu's single `getByBlockHeader` scan over `MilestoneType.{BLOCK_NUMBER,TIMESTAMP}`). The axes stay
  **type-distinct as `ForkActivation` cases** — never folded into a flat geth-style `Rules` bool-struct,
  and never a separate `forTimestamp`.
- **Precompiles** — the `0x01–0x09` classic set plus the `0x0a` KZG point-evaluation wrapper, the
  `0x0b–0x11` BLS12-381 wrappers (EIP-2537 — **seven** precompiles at `0x0b`–`0x11`, **not** `0x12`,
  which is not a precompile), and the `0x0100` **P256VERIFY** wrapper (EIP-7951 secp256r1 — finalized
  in Osaka *and* ETC-Olympia; the AS-IS already ships it, the plan previously omitted it), each a
  gas/decode/dispatch shell **calling down into `crypto` (L0)** for the actual primitive (the L0
  KZG/BLS/P256 precompile-wrapper deferral lands here). Byte-authorities: go-ethereum
  `core/vm/contracts.go:152-172`, besu `OsakaGasCalculator.java:44-56`.
- The **tracer hook** — the all-default `ExecutionTracer` and a branch-free disabled path.

Out of scope (lives elsewhere — see §"Layer boundaries"): block/tx orchestration, receipts, rewards
(all `execution` L4); the KZG/BLS/alt-bn128 cryptographic *primitives* (`crypto` L0); world-state
persistence (`trie`/`storage` L2, reached through the `WorldStateProxy` seam the VM is parameterized
over); **which `ForkSchedule` a network is handed** — the `NetworkFamily` registry that supplies it is
an L5 decision (the *seam* is L3's; the *registry* is L5's — §2.1); the node-side **mining protocol**
(`getWork`/`submitWork`, the internal miner) — block-production is L5, the RPC surface is L9 (§7 routes
the one forge-owned gap so it is not orphaned).

## 2. SR slots & verdicts (binding)

Governing slot: **`observations/evm.md`**. Cross-ref: `observations/consensus-engines.md`
(fork-dispatch unification — the `ForkActivation` seam that collapses the two `forBlock` overloads; reth
`ForkCondition` is the cited prior art). The
verdicts to honor, quoted:

1. **Fork = immutable table built once + cached** — *"Per-fork table built once & cached, indexed
   with no per-step fork branch, is the universal win; the rules-struct half conflates block# +
   timestamp axes … wrong for multi-network."* → **DEFAULT (the table-build half).** Build each
   fork's opcode table once, cache it on the resolved config, index it with **no per-step fork
   branch**. Keep the block-number and timestamp dispatch axes **type-distinct** (do not fold them
   into one geth-style flat `Rules` struct) — but express that distinction as the `ForkActivation`
   enum cases, not as two separate `forBlock` methods (see §2.1).

2. **GasCalculator-as-strategy object per fork (besu)** — *"The single most transferable pattern for
   fukuii … a fork diff is literally the overridden methods; `EtcOlympiaGasCalculator`/
   `EthOsakaGasCalculator` are siblings, no shared mega-switch."* → **DEFAULT.** This is the layer's
   headline structural target (see §5, §6).

3. **Two-layer fork model (nethermind `IReleaseSpec` → intent getters)** — *"`spec.ShiftOpcodesEnabled`
   (intent) over 'is-Constantinople-or-later' (fork name) keeps network-prefixed fork objects from
   leaking fork identity into the loop — matches `scala3-style.md` `Etc*`/`Eth*` anti-conflation."* →
   **DEFAULT (the two-layer model).** Raw-EIP flags → intent-named getters; the interpreter never
   names a fork. The C#-specific JIT specialization does **not** port.

4. **Additive per-EIP construction, no named-fork table (core-geth)** — *"ETC forks activate a
   bespoke subset of ETH EIPs at ETC-specific heights … fukuii must reproduce the effective set at a
   given ETC block."* → **DEFAULT(ETC path).** fukuii's `EvmProposals` fold already realizes this as
   a family-agnostic `ProposalId` registry — keep it (see §6, this is fukuii's own notable pattern,
   endorsed by the SR).

5. **Generic / zero-cost tracer; Inspector hook** → **OPTIONAL(archival/RPC role).** *"The portable
   core on the JVM is besu's monomorphic `NO_TRACING` singleton (branch-free disabled path), not the
   CLR specialization."* We take the branch-free disabled path (an improvement over AS-IS), defer the
   full generic-tracer machinery to the archival/RPC role.

6. **`SpecId` enum + `ConfigureEvm` compile-time family seam (reth/revm)** → **OPTIONAL(SDK/
   multi-family).** *"fukuii's vendored JVM EVM cannot adopt the seam wholesale — it takes the lesson
   (one fork value, resolvers factored out) not the mechanism."*

7. **Multidimensional gas (`MdGas` / `IGasPolicy` state-gas, EIP-8037)** → **OPTIONAL(future-EIP).**
   *"Not yet canonical … do not port erigon's `mdgas`-typed `Run` signature as 'the EVM API'."*
   Single-dimensional `BigInt` gas stays the API; a gas dimension is added later behind a seam — a
   **separate injected `StateGasCostCalculator` strategy with a `NONE`/active pair** (besu
   `StateGasCostCalculator.java` + `Eip8037StateGasCostCalculator.java`), resolved *alongside* `given
   GasCalculator`, **not** a widened `GasCalculator` method and **not** erigon's `mdgas` `Run` signature.
   EIP-8037 is an **Amsterdam** EIP (post-Osaka, not yet mainnet — geth `jump_table.go:100`),
   reinforcing the defer; and the seam sizes `ProgramState` too, not only the gas strategy (§7 F11).

8. **Standalone published EVM library (besu `org.hyperledger.besu:evm` / revm)** → **OPTIONAL(product).**
   A minimal-dependency embeddable EVM artifact is a product decision, deferred.

**Consensus-engines cross-ref (binding, corrects the earlier draft):** *"Unified fork-dispatch:
`MilestoneType` / `AddTransitions` / `ForkCondition` … Collapse the two overloads into one
axis-agnostic activation query. reth's `ForkCondition{Block,Timestamp,TTD,Never}` is the cleanest
single-type form … **Portable to Scala now, independent of the family-registry design.**"* → **DEFAULT,
landing at L3 now** (not deferred to L5 — §2.1).

### 2.1 The `ForkActivation` unification is L3's, now — not an L5 deferral

The earlier draft wrongly deferred the whole fork-dispatch unification to L5. The evidence corrects it:

- **fukuii already built the seam at L3.** `ForkActivation{ByBlock,ByTimestamp,ByTotalDifficulty,Never}`
  + `ForkSchedule` exist today (`ForkActivation.scala:18-32`, reth-`ForkCondition`-cited); the 3-arg
  `forBlock` overload already folds the active set via `ForkSchedule.isActive(id, block, timestamp,
  TTD)` (`EvmConfig.scala:44-49`). The *only* AS-IS residue is that **two legacy `forBlock` overloads**
  remain the production entry point (`:35`, `:44`).
- **The now-L3 change:** collapse the two overloads into one `forBlock(header, schedule)`. The header
  supplies number **and** timestamp; each fork's `ForkActivation` case decides its own boundary
  (`ByBlock` for ETC, `ByTimestamp` for post-merge ETH, `ByTotalDifficulty`/`Never` unused by any EVM
  proposal). besu's `getByBlockHeader` scanning `MilestoneType.{BLOCK_NUMBER,TIMESTAMP}` is the exact
  shape — **one method, two boundaries.** This is `consensus-engines.md`'s explicit *"portable to Scala
  now, independent of the family-registry design."*
- **What still defers to L5:** only *which* `ForkSchedule` a network is handed — the `NetworkFamily`
  typeclass that supplies the schedule per network (R1 §L5). The activation *seam* (the unified query)
  is L3's; the *registry* that selects the schedule is L5's. Keeping the two `forBlock` methods "to stay
  multi-network-safe" was backwards — the single axis-tagged `ForkActivation` enum **is** the
  multi-network-safe form (it keeps the axes distinct as *cases*, which is what "don't conflate the
  axes" actually means; geth's flat `Rules` bool-struct is the thing to avoid, reth's tagged enum is
  the DEFAULT).

## 4. besu structural mirror

The concrete besu shapes to follow (read alongside geth's Go), all under `clients/besu/evm/…`:

- **`GasCalculator` as a subclassable strategy object per fork** — `gascalculator/GasCalculator.java`
  is the interface; `FrontierGasCalculator` → `HomesteadGasCalculator` → … → `OsakaGasCalculator`
  each **override only the methods whose costs changed**, injected into every operation and
  precompile. A fork's gas diff is literally the overridden methods; `EtcOlympiaGasCalculator` and
  `EthOsakaGasCalculator` are **siblings** off a shared base — no shared mega-switch, no fork name in
  the opcode body. `Eip8037StateGasCostCalculator`/`StateGasCostCalculator` show how a *new gas
  dimension* is added as a separate calculator (the OPTIONAL(future-EIP) seam).
- **Single fork-dispatch method — `ProtocolScheduleBuilder.getByBlockHeader` over `MilestoneType`** —
  besu holds one ordered milestone list; each milestone carries its own `MilestoneType.{BLOCK_NUMBER,
  TIMESTAMP}` axis, and a *single* header-keyed scan resolves the active spec. This is the concrete JVM
  form of collapsing fukuii's two `forBlock` overloads into `forBlock(header, schedule)` (§2.1).
- **Incremental per-fork opcode table (`OperationRegistry`), assembled by a factory** — each fork's
  registration calls the prior fork's then `put`s its delta into a dense `Operation[256]`; the table
  is built once and referenced by the `EVM`/`ProtocolSpec`, never rebuilt per instruction. **Validated
  at init — but the two clients do it differently:** **only go-ethereum `validate`s** the assembled
  table (`jump_table.go:76` — it checks nil-op presence + `memorySize ⟹ dynamicGas`, **not**
  `delta`/`alpha`/gas presence), while **besu pre-fills all 256 slots with `InvalidOperation`**
  (`MainnetEVMs.java:205-207`) so an undefined slot loud-fails at dispatch rather than at construction.
  fukuii adopts **both** — geth's build-time `validate` (the AS-IS `validate` gap, §6) *and* besu's
  dense-fill-with-`InvalidOperation` — since either alone leaves a hole.
- **`PrecompileContractRegistry` = `Map<Address, PrecompiledContract>`, incremental per fork** —
  `MainnetPrecompiledContracts.java`; each fork's set is `prior ++ delta`. The `0x0a` KZG and
  `0x0b–0x11` BLS entries are added at the ETH forks that introduce them and **omitted** from the ETC
  set. Precompile inputs are **rejected at entry** (`AbstractBLS12PrecompiledContract.java:159-186`
  throws at the invariant, never silently defaults) — the `fail-loud-invariants.md` tier-2 shape (§5,
  §9).
- **`OperationTracer` all-`default{}` interface + a `NO_TRACING` monomorphic singleton** — the
  branch-free disabled path fukuii's `ExecutionTracer` already cites by name but does not yet realize
  (§6). besu documents the hot loop as *"performance-critical code. Benchmark before refactoring"*
  (`EVM.java:471`) — the `mutable-state-parity.md` witness that bears on the immutable-`ProgramState`
  OPEN (§6).
- **Published `org.hyperledger.besu:evm` standalone lib** — the OPTIONAL(product) reference for an
  embeddable EVM boundary (deferred, §7).

**Ruled out — besu's inlined hot-op `switch` (`runToHalt`).** besu hand-inlines the hottest opcodes as
a literal `switch` *beside* its `OperationRegistry` fallback (nethermind's `unsafe`/`fixed` dispatch is
the same shape). → **OBSOLETE (measured-fragile)** per `optimizations.md` L3: "two dispatch tables of
record" is a bug surface — a divergence between the inlined switch and the registry silently mis-executes
an opcode. fukuii keeps a **single dense `IArray[OpCode]`** table (§5); besu's own comment ("benchmark
before refactoring") is the standard for ever revisiting this.

## 5. Scala 3 idiom targets

- **Opcodes stay behavior-bearing, not a flat `enum`.** An opcode carries `execute` and a gas
  computation, so the idiom is a **sealed `OpCode` hierarchy with `case object`s** (the AS-IS shape),
  not a data-only `enum`. Keep the `ConstGas` / `AddrAccessGas` / `StorageAccessGas` mixins as
  `trait`s. (`enum` is reserved for pure-data closed sets like `ProposalId`, `TxType`, and
  `ForkActivation`.)
- **Gas schedule as a `given` strategy object per fork — the besu DEFAULT.** Model the fork's gas
  costs as a **`GasCalculator` typeclass instance** (`given etcOlympiaGas: GasCalculator` /
  `given ethOsakaGas: GasCalculator`) resolved once into the `EvmConfig` bundle and injected into
  every opcode/precompile via `using`. The decision this layer must make (§6): **unify the fee
  *values* and the gas *computation* into the one `GasCalculator` object** (besu) rather than the
  AS-IS split (values in the `FeeSchedule` chain, computation in `varGas`/`baseGas` on the opcode).
- **One `forBlock(header, schedule)` over an `enum ForkActivation`.** Replace the two overloads with a
  single method dispatching over `enum ForkActivation { case ByBlock(n); case ByTimestamp(t); case
  ByTotalDifficulty(ttd); case Never }` — a total `match`, the axes distinct as *cases*. The schedule
  (`ForkSchedule`, an ordered activation list) is a `given`/parameter; the resolver folds the active
  `Set[ProposalId]` from it. This is the R1 family-blind seam realized in Scala 3 (§2.1).
- **Keep the family-agnostic `ProposalId` fold — endorsed.** `enum ProposalId { case Eip(n); case
  Ecip(n); case Custom(...) }` keying additive `EvmProposal(opcodeDelta, feeDelta, configDelta)`
  records; `deriveEvmConfigAt` folds the active set in a pinned chronological order. This is fukuii's
  own notable pattern and the SR's DEFAULT(ETC path) — carry it forward, do not regress to a
  named-fork mega-table.
- **Intent-named getters via `extension` on the resolved config** — `extension (c: EvmConfig)
  def shiftOpcodesEnabled: Boolean` etc., so the interpreter reads intent, never a fork name (the
  two-layer model). Enforces the `scala3-style.md` `Etc*`/`Eth*` anti-conflation ratchet by
  construction, and retires the AS-IS `isEthereum`-branching `blockEvmActivations` (§6).
- **Fork-schedule / resolved config as an immutable, shareable bundle** — `EvmConfig` is the per-block
  resolved value object (fukuii's `Rules`/`IReleaseSpec`/`ProtocolSpec` analog), built once and cached;
  the opcode table is a field on it. **R2 (multi-instance):** the cache keying `header → EvmConfig` must
  hold **immutable, freely-shareable** values (a Scala 3 `IArray`-backed immutable table), *not*
  nethermind's mutable-spec memoization (`spec.EvmInstructions ??= GenerateOpCodes(spec)` mutates the
  spec) — a mutable cached spec shared across two `ChainInstance`s in one binary is an isolation break.
  No `object … { var … }` process-global EVM state anywhere in `evm`.
- **Dense `IArray[OpCode]` dispatch, not `Map[Byte, OpCode]`.** Use a Scala 3 immutable `IArray`
  indexed by the opcode byte for branch-free O(1) dispatch (closes the AS-IS hash-probe divergence —
  §6). Undefined slots hold a shared `InvalidOpCode` sentinel; no `Option` allocation on the miss
  path. **Build-time `validate`** over the assembled table (geth `validate(jt)`), and the
  fall-through/undefined-slot path **fails loud** at the site per `fail-loud-invariants.md` (a
  `sys.error`/`InvalidOpCode`-throwing miss, never a silent plausible default).
- **`@unchecked` only above a loud-throwing fall-through.** Per `fail-loud-invariants.md`: precompile
  input-shape is checked **at function entry** (rejected loud, not deferred downstream); any
  `@unchecked` in opcode/precompile dispatch is legitimate *only* above a `match` whose fall-through
  `sys.error`s naming the violated invariant. Prefer a sealed hierarchy + exhaustive match (tier 1) so
  the compiler proves totality — besu's typed-node/visitor shape.
- **Branch-free disabled tracer** — a single `given` `ExecutionTracer` with a `NoTracing` singleton
  whose methods the loop can elide, resolved from **one** slot (not the AS-IS two-slot
  `Option.foreach`).

## 6. Improvements over old fukuii (from the AS-IS)

Each row closes a gap named in `clients/fukuii/evm.md` "Gotchas / vs. observations".

| Old fukuii (AS-IS) | Rebuild L3 `evm` | Why it matters |
|---|---|---|

| **Two legacy `forBlock` overloads** as the prod entry (2-arg block, 3-arg block+timestamp) even though `ForkActivation`/`ForkSchedule` exist | **One `forBlock(header, schedule)`** over the axis-tagged `ForkActivation` enum (besu `getByBlockHeader` shape); the `ForkSchedule` a network gets is injected from L5 | The R1 family-blind seam realized at L3 *now* — one dispatch method, axes distinct as enum cases; the multi-network-safe form (§2.1) |
| **Gas split** — fee *values* in the `FeeSchedule` chain, gas *computation* in `varGas`/`baseGas` on each opcode | **Unified `GasCalculator` strategy object per fork** (besu DEFAULT) — values and computation in one injected object; a per-family gas rule is one overridden method | Adding an ETC-vs-ETH gas divergence touches one sibling calculator, not the fee chain *and* the opcode |
| **`Map[Byte, OpCode]` dispatch** — a hash probe returning `Option`, boxing on hit, allocating on the `None` miss path | **Dense `IArray[OpCode]`** indexed by opcode byte — branch-free O(1), shared `InvalidOpCode` sentinel, no per-step alloc | Every reference client uses a dense `[256]` table; the map probe is a per-opcode cost with no correctness upside |

| **`precompileRelocations` remap layer** — a source→target precompile-address remap threaded per context (`:121-135`), driven by the `@volatile _simulatePrecompileRelocations` flag on the L4 preparator | **Chesterton-review before carry (OPEN):** Wire-it / Delete-it / Defer per `dead-code-review.md` — its only live consumer is L4 simulation; if simulation moves to an immutable `SimulationOptions` (L4 §6) it may be dead. Do **not** carry it forward dormant. **If kept, it is an L4↔L3 API change (RX-L4-23):** L3 must **accept `SimulationOptions` as a parameter** threaded from L4's per-call value — the `@volatile _simulatePrecompileRelocations` global flag is removed, not relocated.   across Go/Java/C#** — **all six vendored clients (besu/geth/core-geth/erigon/nethermind/reth) mutate

  measured against), and besu documents its own hot loop as *"performance-critical code. Benchmark before
  refactoring."* By that standard the immutable loop is a **divergence and a measurable regression**,
  not a neutral stylistic choice. *In its favor:* immutable state trivially satisfies R2 (no shared
  mutable frame across instances) and gives "revert = keep the old value" **free**. **Resolution:** this
  is an **OPEN decided by a benchmark, not by inertia** — build an alloc/throughput bench (the erigon
  profile-driven discipline) comparing the immutable loop against a mutable-frame hot path at ETC/ETH
  mainnet workloads. **The bench must weigh like-for-like:** a mutable frame does **not** get revert
  free — every `call`/`create` re-entry must snapshot/restore via an **explicit revert journal/undo**
  (exactly what besu's `MessageFrame` / geth's snapshot do), so the comparison includes that journal
  cost, **not** per-step alloc alone. Keep immutability only if the bench shows the cost is acceptable,
  otherwise adopt the parity-correct mutable frame (single-threaded within one block execution, so no
  guard needed — `mutable-state-parity.md` Finding 1 standard). Either way it is a
  **correctness-neutral perf** call (the `@tailrec` loop is byte-identical to a mutable frame), so it
  does **not** gate the consensus DoD.

## 9. Risks & consensus-critical flags

**All of L3 is byte-exact / consensus-critical — dual-authority `forge` (PoW/ETC) + `beacon`
(PoS/ETH) gate.** Every opcode semantic, gas value, precompile output, and fork-activation height
routes through the Consensus-Critical Change Protocol (state-root litmus). Do not hand-edit `vm/`
reactively. Specific traps:

- **Fork-name-for-the-wrong-network.** `Etc*`/`Eth*` opcode/fee/gas objects must never cross-name —
  the old **unprefixed-`OlympiaOpCodes`-was-actually-Cancun** trap (fixed `b46e21ea1`). A
  fork-codename standing for the wrong network's byte set is a chain split. `scala3-style.md` ratchet
  makes it a compile error (an `Etc*` never `extends`/references an `Eth*` and vice versa).
- **Collapsing the two `forBlock` overloads must be byte-identical.** The single
  `forBlock(header, schedule)` (§2.1) is a *refactor of the resolution mechanism*, not a semantics
  change: the resolved `(opcode table, fee schedule, flags)` at every activation height on both fork
  clocks must be proven byte-identical to the two-overload AS-IS by the fold-identity suite (§8) before
  the second overload is deleted (Chesterton's Fence — the overloads coexist today because the
  unification was seeded but not wired). The axes stay **type-distinct as `ForkActivation` cases**;
  folding them into one geth-style flat `Rules` bool-struct is the thing to avoid — never a
  `forTimestamp`.
- **`etcOlympiaContracts` must exclude the `0x0a` KZG precompile.** ETC has no EIP-4844; routing ETC
  Olympia through ETH's precompile set would make any CALL to `0x0a` diverge from core-geth — a
  state-root split. Build the ETC set on the Istanbul/Phoenix base, not the Cancun base.
- **Consolidating EIP-2929 warm/cold gas + precompile gas into the fold is consensus-critical.** The
  AS-IS leaves these on the enum-fork read-path; moving them into the single mechanism (§6) must be
  proven byte-identical by the fold-identity suite before the enum path is deleted (Chesterton's
  Fence — the enum path exists because the fold did not yet cover these).
- **Precompile native-lib boundary (B-BLS-1 recurrence) — route through the L0 *checked* paths, never bypass.**
  The `0x08` / `0x0a` / `0x0b–0x11` wrappers call the **L0 `crypto` primitives**, which are pinned to the
  correct backend (jc-kzg 2.1.6, besu-native bls12-381 1.0.0) **and carry the subgroup/setup checks that
  closed L0's proven consensus traps** (RX-L0-14/20/21): `0x08` ECPAIRING must use the **subgroup-checked**
  BN128 G2 decode (`[r]·P = ∞`, F-BN-1 chain-split); `0x0a` KZG must use the **locked trusted setup**
  (B-KZG-1), not a re-loaded one; `0x0b–0x11` BLS must route the **9/9 subgroup-rejection KATs** (B-BLS-1),
  and the wrapper's **precompile-address mapping must match the shipped EIP-2537 revision**. Do not
  re-inline a native call at the precompile site (the AS-IS mislayering L0 already corrected); do not
  silently swap the backend. Precompile input-shape is **checked at entry
  and fails loud** (`fail-loud-invariants.md`) — never a wrong-but-plausible return. Gas math is JVM
  `BigInt` — the besu lens checks for Go `uint64`/`uint256` idioms that don't hold on the JVM. **Note
  besu itself does not use `BigInteger` for gas either — it uses `long` + clamped/saturating arithmetic
  (`Words.clampedAdd`, `OsakaGasCalculator.java:19-21`); fukuii's `BigInt` is a conscious
  correctness-over-throughput choice (like the immutable loop, §6), a perf candidate under that bench,
  not a besu mirror.**
- **Immutable-state allocation is an OPEN, not a settled "known outlier."** Per `mutable-state-parity.md`
  the immutable `ProgramState` loop is a *divergence + measurable regression* from every reference
  client (§6). It is **correctness-neutral** (byte-identical to a mutable frame), so it does not gate
  the consensus DoD — but it must be *decided by a benchmark*, and if kept, kept as a conscious,
  measured choice (R2-isolation benefit weighed against the alloc cost), not carried by inertia.
- **R2 — no process-global EVM state.** A JVM-wide mutable spec cache (nethermind's
  `spec.EvmInstructions ??=` memoization mutates the spec) shared across two `ChainInstance`s in one
  binary is an isolation break. The cached `header → EvmConfig` must be immutable and freely shareable.

## Layer boundaries (what lives elsewhere, and why)

_Durable placement — not build-status (see the README index)._

- **KZG / BLS / alt-bn128 cryptographic *primitives*** → **`crypto` (L0)**. L3 owns only the
  precompile *wrappers* (gas/decode/dispatch) that call down into them.
- **Block/tx orchestration, receipts, rewards, system calls** → **`execution` (L4)**. The VM executes

  now** (§2.1); L5 only supplies the per-network schedule instance.
- **Node-side mining protocol** (`getWork`/`submitWork`, internal Ethash miner) → **block-production
  (L5)** + **RPC (L9)**; the forge-owned submit-time seal-verify gap lands at L9 (§7).
- **Standalone embeddable EVM artifact / EVMC** → OPTIONAL(product), a later product-family decision.
