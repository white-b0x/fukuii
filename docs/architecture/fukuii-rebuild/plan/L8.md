# L8 — peripheral services: `txpool` · `keystore` · `observability`

_Prospective plan, SR-grounded, written before the layer is built. Retrospective as-built record
lands in `../08-*.md`; live build-status is the `../README.md` index, never here. Read
[`README.md`](README.md) (template, authority model, doc discipline) first. Enriched in Wave 2
against `REVIEW.md` §4, `requirements.md` (R2/R10/R11), `optimizations.md` §L8, and
`feature-ledger.md` (F2/F3/F6/F12)._

L8 is the first band of **peripheral services** — three modules that sit above the chain facade
(L7) and below RPC (L9), each depending only downward and **none depending on another L8 module**.
They are grouped because they share a disposition: **low-consensus-risk, high-enterprise-value
adopts** that the SR already sized as JVM-ecosystem wins (`observations/observability.md`
"comparatively low-consensus-risk, high-enterprise-value adopt"). The one consensus-adjacent seam
in the band — txpool **admission policy** — is **banksy**'s, not this layer's: L8 builds the pool
*structure* and the admission *seam*; banksy owns the tip/gas floors and selection ordering that
hang on it. Two cross-cutting requirements bite hardest here: **R2** (concurrent multi-instance —
the per-instance metric registry, the Bug-29 precondition for L10) and **R11** (security — keystore
hardening + the L0 constant-time primitive).

## 2. SR slots & verdicts

### `observations/txpool.md` (→ txpool)
- **DEFAULT (banksy admission shape):** "Express admission as a composable filter/validator chain
  over a consensus-invariant core… nethermind's `IIncomingTxFilter` pipeline, reth's
  `TransactionValidator` trait, and besu's `PluginTransactionPoolValidator` all separate
  *operator-tunable policy* from *consensus-mandatory validation*." → **ECIP-1122 `MIN_MINER_TIP` is
  a `TipTooLowFilter`, NOT an edit to the pool core.**
- **DEFAULT:** "Express ordering as a pluggable strategy, separate from the storage data structure"
  (reth `TransactionOrdering::priority(tx, base_fee)`).
- **DEFAULT (structural baseline):** `SubPool` aggregator seam routing by tx class (go-ethereum,
  byte-authority) — even ETC-with-no-blobs "needs only the legacy path, but the seam is the right
  decomposition."
- **DEFAULT:** keep the two-phase cheap→expensive gate (sender-independent rejects before ECDSA
  recovery) — "an admission-DoS mitigation every client converges on."
- **DEFAULT (replacement/eviction):** geth's 10% price-bump (must beat feeCap **and** tip) +
  global-worst-by-price eviction (nethermind `SortedPool` `_worstSortedValues` / reth `discard_worst`).
  The **10%** is the legacy/gasPrice bump (geth `legacypool` / besu `DEFAULT_PRICE_BUMP`) — ETC's
  path; the **blob** bump is **100%** (geth `blobpool` / besu `DEFAULT_BLOB_PRICE_BUMP`), the
  ETH-family path only, so an ETH-family instance must not reuse 10% for blobs.
- **OPTIONAL(adopt-or-defer): direct-push-for-small-txs to ~√peers** (go-ethereum eth/68) — fukuii
  today **announces hash-only for every tx** (`PendingTransactionsManager.scala:170-192`), a
  divergence from the DEFAULT; the rebuild either adopts geth's direct full-body push of small txs
  to ~√peers (announce-hash-only for large/blob) or **consciously defers with the seam in place**
  (`optimizations.md` §L8). Not skipped-silently: the gossip strategy is a named, tested choice.
- **OPTIONAL(enterprise/full):** layered promotion pipeline (besu Prioritized→Ready→Sparse) —
  "relevant to efficient tip-of-branch mining selection."
- **OPTIONAL(idea-level):** sub-pools derived from a state bitflag via a pure fn (reth
  `From<TxState> for SubPool`, erigon `SubPoolMarker`) — "if fukuii ever grows a first-class
  parked/pending split, this is the model."
- **OPTIONAL(product-family):** txpool-as-gRPC-service (erigon) — **does not land here**; forwards to
  L9 `grpc-seam` / DRPC-GATEWAY-01 (§7).
- **Note (honored):** "ETC has no blob / 1559-effective-tip parts" — the `blobpool`, `BaseFee`
  sub-pool split, and effective-tip reheap "degenerate on ETC to raw `gasPrice` ordering"; ETC path
  uses the flat-gas-price variant (besu `GasPricePrioritizedTransactions` analog).

### `observations/observability.md` (→ observability)
- **DEFAULT:** provider-agnostic `MetricsSystem`-style seam + no-op fallback (besu) — "no-op backend
  when disabled makes instrumentation always call-safe."
- **DEFAULT (authoring convention):** attributed/registered-once per-module `object XxxMetrics`
  (nethermind static `Metrics` adapted to Scala) fronted by one scraper — but under R2 "registered
  once" means **registered once per `ChainInstance`** into the injected registry, never a
  process-global static handle (nethermind's `static Metrics` is fine only because it runs one node
  per process; the naive Scala `object` port reintroduces Bug 29).
- **DEFAULT (Prometheus):** a pluggable exporter picked once at boot; **OPTIONAL(enterprise):** OTLP,
  InfluxDB.
- **DEFAULT:** first-class HealthChecks — `/health` readiness + an RPC method, **consensus-aware**
  (PoW block-production liveness vs PoS CL-alive), machine-readable errors, decoupled from the
  metrics port (nethermind + besu).
- **OPTIONAL(role): shipped Grafana dashboards** versioned in-repo alongside the metrics they read
  (erigon) — "dashboards evolve lockstep with the metrics they read; the cross-network QA dashboard
  doubles as a **perf-regression gate**." fukuii already ships 15 (F6); this is a DEFAULT-preserve
  for fukuii + an additive erigon cross-network QA-regression dashboard.
- **OPTIONAL(enterprise ops):** OTLP distributed tracing; erigon `diaglib` semantic diagnostics +
  support tunnel; ethstats push telemetry.
- **OBSOLETE (for a JVM successor):** vendoring/forking a self-contained metrics library
  (geth/core-geth `rcrowley` fork) — "the JVM gets the registry + pluggable-exporter pattern for
  free from Micrometer/Dropwizard."
- **OBSOLETE (from `node-lifecycle.md`, carried here):** "Global mutable singletons for log/metrics
  … a footgun when two nodes share a process. fukuii should scope observability to the node
  instance, not the process." — the Bug 29 fix (§6).

### `observations/accounts-signer.md` (→ keystore)
- **DEFAULT:** keep the geth-v3 keystore (fukuii already ships it — the cross-client interchange
  format) AND adopt a narrow **`ISigner`-style seam** so "key in memory vs keystore-unlocked vs
  external" is a DI choice with **zero block-production change**; split read (`ISigner`) from write
  (`ISignerStore`) so a remote signer implements "sign this" while "here is the private key" is a
  compile-visible unsupported operation.
- **DEFAULT (R11 hardening):** verify-after-write + **atomic-rename** (geth writes a temp file, fsyncs,
  renames) so a crash mid-write can never leave a torn keyfile; **key-zeroing / `ProtectedPrivateKey`
  heap-protection** (nethermind DPAPI shape, generalized) instead of bare `ByteString` living in the
  heap; **the keystore MAC uses the L0 `constantTimeEquals` primitive**, never `==` (`requirements.md`
  R11; `optimizations.md` §L0 constant-time row).
- **OPTIONAL(custody/enterprise):** external-signer / HSM delegation — besu `SecurityModule` registry
  (`--security-module=<name>`) and/or a clef-compatible client.
- **OPTIONAL(validator):** validator remote-signing (nethermind `ClefSigner` shape) — ties to
  CL-RESEARCH-EMBED-01.
- **Invariant (honored):** strict node-identity-key vs account-key separation (reth/erigon) — the P2P
  identity key must never be reachable as a signable account; account-signing RPCs fail closed
  (`NoAccount`) rather than silently degrade.
- **OBSOLETE:** permanent in-node account unlock (`--allow-insecure-unlock`) — "don't model fukuii on
  permanent in-node unlock."

## 4. besu structural mirror

- **txpool.** `TransactionPool` fronts a `PendingTransactions` SPI with two selectable impls
  (`layered/LayeredPendingTransactions`, legacy sorter) chosen at boot. The layered chain —
  `AbstractPrioritizedTransactions` → `ReadyTransactions` → `SparseTransactions` → `EndLayer` —
  confines full ordering to a small candidate layer and quarantines nonce-gap spam in a drop-first
  purgatory. For ETC, **`GasPricePrioritizedTransactions`** (not `BaseFeePrioritizedTransactions`) is
  the flat-gas-price ordering to mirror. The two policy veto points are
  `PluginTransactionPoolValidator` (admission) and `PluginTransactionSelector` (selection) —
  **exactly the two points banksy owns**; replacement is `TransactionPoolReplacementHandler` +
  `TransactionReplacementByGasPriceRule` (ETC) / `…ByFeeMarketRule` (ETH). Consensus-mandatory
  validation is baked into `TransactionValidator`; operator policy is the plugin seams (no-op by
  default). Global-worst eviction is besu's `TransactionsForSenderInfo` + layer eviction; nethermind's
  `SortedPool` global-worst set is the O(log n) index shape to adopt.
- **observability.** `MetricsSystemFactory` binds one concrete exporter at boot; every subsystem
  codes against the `ObservableMetricsSystem` interface; `noop/` is the disabled-backend fallback
  that keeps call sites null-guard-free; `MetricCategoryRegistryImpl` is the extensible taxonomy
  (`plugin-api/.../services/metrics/MetricCategory`). This is the direct JVM analog for fukuii's
  Micrometer stack — **the same shape, minus the process-global-registry trap** (§6, Bug 29). The
  factory is constructed **per node**, not process-global — the R2 precondition. **But besu is only a
  valid mirror for the factory/seam, not for the registry lifetime:** besu's per-instance-ness
  **stops at the `MetricsSystem` object** — `PrometheusMetricsSystem.java:66` binds
  `PrometheusRegistry.defaultRegistry` (JVM process-global), and `GlobalOpenTelemetry` is a JVM-global
  besu explicitly *disables* (`MetricsSystemFactory:36-44`). besu runs **one node per process**, so it
  never solved R2; copying it naively **reproduces Bug 29**. fukuii must construct a **fresh
  per-`ChainInstance` registry** (Micrometer `PrometheusMeterRegistry`, which is per-instance
  instantiable) and **never** bind `defaultRegistry` / `CollectorRegistry.defaultRegistry` /
  `GlobalOpenTelemetry`.
- **keystore.** besu's `SecurityModule` seam (`sign`/`getPublicKey`/ECDH) is the narrow capability
  interface an HSM/remote signer implements as a plugin jar while the core stays vendor-SDK-free —
  the structural target for fukuii's `Signer`/`SignerStore` split. besu writes keyfiles via a
  temp-then-rename path (the atomic-write mirror); nethermind's `ProtectedPrivateKey` is the
  heap-protection mirror.

## 5. Scala 3 idiom targets

- **txpool admission chain.** A `given`-composable list of small filters, each
  `Transaction => Either[RejectReason, Unit]`; `enum RejectReason` carries the machine-reason
  (nethermind/besu accept/reject-with-reason). banksy's `TipTooLowFilter(minTip)` and
  `PriorityFeeTooLowFilter` are just config-parameterized filters dropped into the chain — never
  edits to the pool core. Cheap in-memory filters (pending-nonce high-water) precede ECDSA recovery
  (the STFA child) which precedes the trie read.
- **Ordering as a strategy.** `given TransactionOrdering` with `priority(tx, baseFee): BigInt` (reth
  shape); ETC binds the flat-`gasPrice` instance. Ordering is separate from the storage structure.
- **Replacement + eviction.** A pure `isUnderpriced(incoming, incumbent, bumpPct): Boolean` predicate
  (reth `is_underpriced`, geth 10%-bump: beat feeCap **and** tip) — `bumpPct` = 10 on the
  legacy/gasPrice path (ETC), 100 on the blob path (ETH-family only, geth `blobpool` / besu
  `DEFAULT_BLOB_PRICE_BUMP`); a `SortedPool`-style global-worst
  index (nethermind O(log n)) so pool-full spam evicts the cheapest tx, never a high-fee one. The
  gossip strategy is a `given TxGossipPolicy` — `DirectPushSmallTx(√peers)` vs `AnnounceHashOnly` —
  the adopt-or-defer seam expressed as a swappable instance, not a hardcoded branch. The direct set
  is **not a random √peers draw**: geth chooses it by a **deterministic siphash score over
  `(nodeId, peerId, sender)`** (`eth/handler.go:690-712`), giving a stable per-sender propagation
  subset (anti-amplification); the seam should reproduce that deterministic selection.
- **Sub-pool derivation.** `enum SubPool { case Prioritized, Ready, Sparse }` **derived** from an
  opaque `TxState` bitflag by a pure fn (`From<TxState> for SubPool`), recomputed per block — so the
  partition is correct by construction, not set imperatively. This composes **two clients**: the enum
  *case set* is besu's layer taxonomy (Prioritized/Ready/Sparse), while the *derivation mechanism* is
  reth's `From<TxState>` total pure fn (reth's own case set is `Queued/BaseFee/Blob/Pending`) — so the
  DoD "total pure fn" test targets the besu case set. On ETC the base-fee/blob-equivalent cases are
  inert. ETC may activate only one active
  sub-pool, but the seam is built (planned-work-is-scope-floor).
- **Pool actor.** Pekko Typed `Behavior[PendingTxCommand]`, sealed Command ADT + explicit `replyTo`;
  the sender-recovery child (STFA analog) on a bounded mailbox, Cats-Effect `IO.parTraverseN` for
  large batches. No `Behavior[Any]`, no `sender()`.
- **keystore.** v3 JSON via `circe` `derives Codec` (scrypt N=2¹⁸/r=8/p=1, aes-128-ctr, keccak-MAC;
  pbkdf2/CBC read-compat); opaque `PrivateKey` that never escapes and is **zeroed** after use
  (`ProtectedPrivateKey` wrapper, `try/finally` clear of the mutable key array). Note the JVM caveat:
  immutable `String`-derived password material and GC-relocated copies **cannot be guaranteed-zeroed**
  — the wrapper *bounds* heap exposure, it does not eliminate it (contrast nethermind's DPAPI, which
  the plan generalizes rather than ports since the JVM has no DPAPI); the MAC compared with **L0
  `constantTimeEquals`**, not `==`; writes go through a **verify-after-write + atomic-rename** helper
  (temp file → fsync → `Files.move(ATOMIC_MOVE)`). `trait Signer` (read: `sign`) and
  `trait SignerStore` (write) are separate `given`-injected seams — an external signer supplies a
  `given Signer` while `SignerStore` is a compile-visible `unsupported`.
- **observability.** `trait MetricsSystem` provider-agnostic seam + a `given noop` fallback; per-module
  `object XxxMetrics` that registers its collectors **into the injected per-`ChainInstance` registry**
  (registered once *per instance*, not a process-global static handle — a Scala `object` that memoizes
  a global `Metrics.get()` is the Bug-29 reintroduction the §9 litmus catches); `enum MetricCategory`;
  **a registry constructed per `ChainInstance`, not a process-global static** (the Bug 29 fix — the
  differentiator dependency for L10). Micrometer/Prometheus binding chosen at boot; Kamon does not enter (dropped, §6). Health as
  composable Cats-Effect probes (`IO`-combinators, `parSequence`), branched on
  `enum ConsensusFamily { case PoW, PoS }` so the check set is family-correct.

## 6. Improvements over old fukuii (AS-IS gaps this layer closes)

From `.local/docs/research/clients/fukuii/{txpool,observability,accounts-signer}.md`:

- **txpool: replace the flat Guava cache with a structured pool + composable seam.** AS-IS is "a
  single Pekko Typed actor holding a flat, hash-keyed Guava `Cache`" (`PendingTransactionsManager.scala:139`)
  with a `validateAgainstState` method of "3 sequential `Set.filter` stages" (`:205`) — not a filter
  chain. This layer builds the composable admission chain (the DEFAULT shape) and a pluggable
  ordering strategy.
- **txpool: kill the duplicated inline tip floor.** AS-IS enforces ECIP-1122 at **two sites, inline**
  — PTM `:222-240` and `BlockGeneratorSkeleton.scala:139-149` — "the two copies must be kept in
  lockstep by hand." The rebuild expresses it as **one banksy `TipTooLowFilter` object** referenced
  by both admission and block-production; correct per the two-enforcement-point requirement, but
  single-sourced.
- **txpool: add price-bump replacement + fee-aware eviction.** AS-IS has "no price-bump replacement
  for gossip txs" (same-nonce txs coexist until eviction, `:199-207`) and "eviction is Guava size/TTL,
  not fee-aware" (`:208-212`) — "a high-fee tx can be evicted while a lower-fee one survives." The
  rebuild adopts the geth 10%-bump rule and a global-worst-by-price eviction index.
- **txpool: reorg-safe `pendingNonces`.** AS-IS never decrements the per-sender high-water except on
  full clear (`:162`, `:464`), so "after a reorg that lowers an account's effective nonce, admission
  can reject legitimate resubmits." The rebuild re-injects dropped txs and rolls back the high-water
  on reorg — deriving the pending-nonce from current state each reset (geth `legacypool` `reset` +
  `noncer.go`), never a monotonic max — by consuming the **L5** reorg-aware `ChainNotification`
  (defined in `consensus-api`, `optimizations.md` §L5 / R7), *carried via* L9's `grpc-seam`. The
  reorg dependency is on L5's event source, not an L9-defined type; L9 is only the transport.
- **txpool: decide the gossip push policy.** AS-IS "announces *every* tx hash-only and never does
  geth's direct full-body push to ~√peers for small txs" (`:276-280` vs go-ethereum eth/68 authority).
  The rebuild binds a `given TxGossipPolicy` — adopt direct-push-for-small-tx (the DEFAULT) or
  consciously defer with the seam wired (`optimizations.md` §L8 "adopt-or-defer").
- **keystore: add the `Signer`/`SignerStore` seam.** AS-IS has "`trait KeyStore` + `Wallet` only; no
  narrow `ISigner`-style read/write DI seam" and "no clef/Web3Signer/`Backend` seam." The rebuild
  adds the split and the external-signer landing point (§7).
- **keystore: harden write + heap + MAC (R11).** AS-IS writes the keyfile with a direct `Files.write`
  (a **torn-key risk** on a crash), holds decrypted private keys as **bare `ByteString` in the heap**
  (no zeroing), and **compares the keystore MAC with `==`** rather than a constant-time equal. The
  rebuild uses verify-after-write + atomic-rename, an opaque zeroing `ProtectedPrivateKey`, and the
  L0 `constantTimeEquals` primitive on the MAC (`requirements.md` R11; `optimizations.md` §L0/§L8).
  The `constantTimeEquals`-on-MAC is **defense-in-depth / consistency**, not an exploitable timing
  fix: go-ethereum itself uses non-constant-time `bytes.Equal` on the keystore MAC
  (`passphrase.go:268`) because the attacker mounting the timing attack already **holds both
  operands** (the stored `mac` is in the keyfile they possess; `calculatedMAC` derives from their own
  password guess), so the oracle leaks nothing new. Adopt it anyway — it's free, and the primitive
  must exist for the genuinely exploitable sites regardless.
- **observability: fix Bug 29 — the multi-instance registry collapse.** AS-IS: "every per-module
  holder across every running chain instance writes to the SAME registry… multiple `/metrics`
  endpoints return byte-identical content regardless of instance" (`Metrics.scala:93-106`,
  `MetricsContainer.scala:5-11`) — the fix is "explicitly out of scope in the source." **This is THE
  Kamon-dropped rework the target names** (`target-architecture.md` MOD row): per-instance registry
  is the hard precondition for L10's multi-ChainInstance runtime (R2).
- **observability: per-instance logback config (RX-L10-10, R2).** Beyond the metrics registry, the AS-IS
  `System.setProperty` logback-file sysprop is a **process-global** — two `ChainInstance`s cannot each
  pick a logback file via a JVM-wide sysprop. `observability` owns per-instance logback configuration —
  the L10 G-NL1 retirement home for the logback sysprop (the metrics `defaultRegistry`/`GlobalOpenTelemetry`
  process-globals, RX-L8-22, are the same class and covered by the §9 isolation grep).
- **observability: drop Kamon, consolidate to one façade.** AS-IS carries "three metrics libraries
  … Micrometer (1.16.6), the Prometheus Java client (1.3.10), and Kamon (2.8.1 + kanela agent)"
  (`observability.md` gotchas). Kamon is dropped (target MOD row — also clears the sbt-2 blocker);
  Micrometer + Prometheus stay, fronted by the provider-agnostic seam. **The dep change is
  sentinel-gated** (§Agentic alignment).
- **observability: consensus-family-branched health + low-disk + machine errors.** AS-IS: "Health
  rules are not consensus-family-branched" (one shared check set for PoW and PoS), "no
  low-disk-space probe," no machine-readable `Errors`, and a stable-name typo `HealhcheckErrorCounter`
  (`JsonRpcHealthChecker.scala:17`). The rebuild branches PoW block-production-liveness vs PoS
  CL-alive (nethermind), adds a disk check, machine-readable errors, and corrects the metric name
  (flagged as a dashboard-breaking rename — coordinate with the shipped `ops/grafana/` dashboards).
- **observability: version the 15 shipped dashboards to metric names (F6/R10).** AS-IS: "Dashboards
  ship but are not version-gated to the metric names" — 15 Grafana JSON under `ops/grafana/`,
  "maintained separately from the `object XxxMetrics` holders, so metric renames can silently drift"
  (`observability.md` gotchas). The rebuild binds them with an in-repo drift test (the metric names a
  panel reads must exist), and adds erigon's **cross-network QA-regression dashboard as a perf gate**
  (`optimizations.md` §L8). fukuii is one of only two clients (with erigon) that ship dashboards —
  preserve that lead, close the drift gap.

## 7. Deferrals landing here (a floor, not "optional"), with tests

- **Per-`ChainInstance` isolation for `txpool` and `keystore` (R2) — a floor, not just the metrics
  registry.** The per-instance treatment L8 already gives the observability registry (the Bug-29
  Kamon-dropped rework) extends to **both** other L8-owned modules: the mempool / pending-tx set
  (`txpool`) and the credential / signer store (`keystore`) are **constructor-injected per
  `ChainInstance`, never process-global statics** — two networks in one binary must not share a
  pending-tx set or a signer (L9 assumes exactly this, `L9.md §9`: "must not share a metrics registry,
  a credential store, or an RPC route table"). *Tests:* two `ChainInstance`s each get an isolated pool +
  keystore (no cross-instance tx or key visibility); the **R2 isolation-regression grep** (`object … {
  var … }` + direct `Config.`-read) covers `txpool`/`keystore`, matching L2/L9/L10 and the repo-wide
  setup CI ratchet (`setup.md §8`).
- **External-signer custody seam — OPTIONAL(custody), lands at `keystore` (L8).** The

## 8. Exit DoD (GREEN bar)

## 9. Risks & consensus-critical flags

- **NOT consensus — but admission policy is banksy's.** The state-root litmus
  (`consensus-change-protocol.md`) decides ownership: tip/gas floors and selection ordering are
  **state-root-invariant, operator-tunable → banksy**; ECIP-1017 emission and ECIP-1111
  base-fee-floor economics that banksy sizes *against* remain **forge**-owned. Route accordingly; do
  not design consensus into txpool.
- **The no-execution-state invariant.** `txpool` must hold no execution state (erigon precondition)
  — this is what makes the L9 gRPC-service txpool seam possible and keeps the pool a pure admission
  buffer. Bake it in at L8; a violation here is discovered expensively at L9.
- **The per-instance metrics isolation invariant (R2).** L10's concurrent multi-ChainInstance runtime —
  fukuii's differentiator — depends on the Bug 29 fix. A process-global registry (the AS-IS state)
  silently corrupts multi-network telemetry; the per-instance registry is a hard L8 requirement, not
  a nicety. **Litmus grep:** no `object … { … Metrics.get() }` static default reaches per-instance
  code — **and** the banned-static set must also catch `PrometheusRegistry.defaultRegistry` /
  `CollectorRegistry.defaultRegistry` / `GlobalOpenTelemetry` (the exact process-global handles the
  byte-authority besu itself binds — §4), not only the `object`-memoized-`Metrics.get()` shape.
- **Keystore hardening is R11-structural, not cosmetic.** The AS-IS `==`-MAC is hardened to
  `constantTimeEquals` for **consistency/defense-in-depth** (go-ethereum itself ships non-constant-time
  `bytes.Equal` on the keystore MAC, `passphrase.go:268`, because the attacker holds both operands);
  the **exploitable** constant-time sites are the ECIES handshake auth-tag (L6, besu
  `ECIESEncryptionEngine:276`) and the Engine-API JWT / MCP-OAuth HMAC (L9, R11), where a *server-held
  secret* expected value makes the timing oracle real. The torn-write is a custody-grade corruption
  risk. These land as the default path with tests, not a later enterprise cut. The L0
  `constantTimeEquals` primitive must exist first (a downward dependency feeding L6/L9, not only L8).
- **Built-but-unshipped.** Do not scaffold the external-signer, sub-pool, gossip-policy, OTLP/diaglib,
  or QA-dashboard seams without a wired default impl — that is the dominant old-fukuii failure mode
  (`README.md` risk register). Every seam ships with a live default.

## Layer boundaries

- **L8 owns:** the mempool structure + admission seam + gossip policy (`txpool`), the keystore +
  signer seam + R11 hardening (`keystore`), the metrics/health instrumentation seam + per-instance
  registry + shipped dashboards (`observability`).
- **L8 does NOT own:** admission *policy* (banksy — tip/gas floors, selection ordering); the
  txpool-as-gRPC-service boundary (L9 `grpc-seam`); the composition that wires per-instance
  registries into concurrent runtimes (L10 `node`); the `Principal`/`Capability` auth gate at the
  serving boundary (L9, R11); consensus emission/base-fee economics (forge/beacon); the L0
  `constantTimeEquals` primitive it consumes.
- **Down-only edges:** `txpool → {domain, execution, network}`, `keystore → {crypto, domain}`,
  `observability → common`. No L8 module depends on another L8 module; nothing above L8 is imported
  (an upward edge is a compile error).
- **Reads, never writes, consensus state:** `txpool` reads chain state through a narrow interface and
  holds none of it; `observability`/`keystore` touch no consensus path.
