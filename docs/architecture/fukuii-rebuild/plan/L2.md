# L2 plan — `storage` + `trie`

_Forward-looking layer plan, written before the build (per [`README.md`](README.md)). Grounds every
decision in the Systemic Review (`observations/{state-trie,storage-persistence,historical-distribution}.md`
+ the fukuii AS-IS `clients/fukuii/{…}.md`), honors the recorded DEFAULT / OPTIONAL(role) / OBSOLETE
verdicts, mines all six clients per-concern (`optimizations.md` L2 rows), carries the R1/R2/R5/R7/R8
downward constraints from `requirements.md`, and names the per-concern authorities. Durable design +
Layer boundaries only — build-status lives in the `../README.md` index, never here._

L2 is where **the state root gets its bytes and the datadir gets its schema.** It is consensus-load-bearing
(state root) and the storage seam every layer above (execution, sync, rpc) is written against. It is also
where the old codebase's most-cited structural defect lived — the `db ↔ mpt` 2-cycle — so a large part of
this plan is *how the seam is factored*, not just what it computes. And it is the layer where the rebuild's
**feature-completeness doctrine is most load-bearing**: storage is the one concern where the SR found a
full *menu of coexisting approaches* in production (besu ships Forest **and** Bonsai behind one interface),
so L2 must be a **multi-approach architecture from line one**, never a single hardcoded store (`R8`).

---

## The storage-approach doctrine (read before §1 — it shapes every module boundary)

**fukuii supports multiple storage *approaches / backends*, each optimized for a network-type × user-role,
selectable — the *default + multiple-additive* doctrine (`REVIEW.md` feature-completeness) applied to
storage.** This is not a "later mode flag"; it is the shape of the seam. `requirements.md` R8 states it and
`feature-ledger.md` §"Storage-approach completeness" sharpens it: **do not pigeonhole on one backend.** The
proof is in the reference repos — besu alone runs Forest (hash-keyed full node store) **and** Bonsai (flat
values + thin proof trie + trie-log) behind one `DataStorageFormat` interface, with separate
`WorldStateKeyValueStorage` hierarchies. The full menu the SR catalogued (all six clients):

| Client | Approaches available behind one storage interface |
|---|---|
| **besu** | Forest · Bonsai · X_BONSAI_ARCHIVE — the JVM proof that ≥2 approaches coexist |
| **go-ethereum** | hashdb · pathdb · snapshot(flat) · freezer(cold) |
| **nethermind** | Hash · HalfPath(default) · online-full-pruning · `INodeStorage` scheme-indirection |
| **erigon** | flat-state · Domains · MDBX (OBSOLETE for JVM — no mature binding) |
| **reth** | pathdb/nibble-path · static-files · parallel+streaming state-root |
| **core-geth** | hashdb + freezer (ETC-frozen; retains TD) — the ETC byte anchor |

**The SR-flagged gap fukuii must close:** fukuii inherited **core-geth's HASH-keyed** node store, but the
reference-client *standard* has moved to **PATH-keyed** (geth pathdb, nethermind HalfPath-default, reth
nibble-path — "the direction all three independently converged on," `state-trie.md` Approach catalog).
**Support both** — archival = hash-keyed (subtree dedup, full history); pruned/tip = path-keyed (locality,
bounded disk, cheap online pruning) — via nethermind's `INodeStorage` scheme-indirection seam (a mutable
`Scheme` + dual-read fallback = a per-datadir role choice **and** an online Hash→HalfPath migration).
fukuii's `PathNodeStorage` is a **one-way-locked SNAP island** today (`state-trie.md` §Gotchas); the seam
must sit at the `MptStorage` boundary from line one — **retrofitting a second backend behind a hash-only
design is a rewrite**, not an addition.

**Realization: a `StorageProfile` role×network selector** (besu `DataStorageFormat` shape) composing six
orthogonal axes (**five live + a reserved single-inhabitant `backend`**, §5 gap #1) — **{node-keying ×
pruning-strategy × flat-accelerator × freezer × history-expiry × backend-format}** — resolved once per
`ChainInstance` at open, recorded in the schema marker, and threaded (never re-asked) downward. The role × network matrix it selects on: `archival-deep-data-for-dApps` ·
`tip-of-branch server` · `pruned RPC-relay` · `resource-light` · `validator` · `mining-pool`, across L1 /
sidechain / L2-rollup / diverse consensus (PoW/PoS/PoA). A profile optimized for an L2 rollup ≠ one for an
L1 ≠ one for archival — support the ones that make sense, each **built to a seam now** even where the mode
itself is role-gated (`planned-work-is-scope-floor`).

The resolved profile also **gates the opened CF set**, not merely per-CF tuning: besu's
`KeyValueSegmentIdentifier.includeInDatabaseFormat` opens a *format-dependent* subset (Forest opens
`WORLD_STATE`; Bonsai opens `ACCOUNT_INFO_STATE`/`TRIE_LOG` instead), so the open path opens a
profile-dependent CF subset and the `SchemaMarker` (§5 gap #7) must reject a datadir whose CF set doesn't
match the profile — not only a `(format,version,keying)` scalar mismatch.

Two sbt modules, both `com.chipprbots.fukuii.*`, both down-only in the DAG:

| **trie** | `fukuii-trie` | `com.chipprbots.fukuii.trie` | `domain`, `crypto`, `storage` | the pure MPT (`enum MptNode`, RLP node encoding, HP nibble compaction, `<32` inlining, keccak-key "secure trie"), state-root computation, the `MptStorage`/`NodeLoader`/`NodeUpdater` load/store seam, `getProof` (EIP-1186), the mutable **`StackTrie` streaming builder + `HashBuilder`-shaped state-root substrate**, `ShardEnumerator` (16-partition, go-ethereum-`GenerateTrie`-aligned), node-aware refcount + child-hash extraction |

**The dependency edge is the point.** `storage → domain, common` and `trie → domain, crypto, storage`
(build.sbt L2 block; README layering line `storage → domain,common · trie → domain,crypto,storage`). Nothing
in `storage` may import `trie`; that single directional edge is the structural resolution of the old cycle
(see §6, "db↔mpt"). An upward edge is a compile error, not a lint finding.

`node` (L10) is the only composition root; L2 depends on nothing above it and wires no actors — it is pure
value-plus-persistence machinery consumed upward by `execution` (L4), `sync` (L7), and `rpc` (L9). **Every
handle is per-`ChainInstance`** (R2): the `DataSource`, the RocksDB handle, the block cache, and the
`StorageProfile` are constructor-injected per instance — no process-global DB state, no `object … { var … }`
static (§9 isolation grep).

## 2. SR slots & verdicts (quoted + cited)

Three observation slots govern L2 (`../README.md` Rule-0 table: `state-trie`, `storage-persistence`,
`historical-distribution` → "L2 storage + trie"). The verdicts to honor:

### `observations/state-trie.md`
- **DEFAULT — decouple the trie from persistence behind a WorldState-style interface.** *"This is the single
  highest-value structural move and every non-erigon client already does it … besu is fukuii's closest JVM
  structural target. This seam is the precondition for every optional mode below."* (`state-trie.md` §Best-practice,
  DEFAULT.) fukuii already has the shape (`MptStorage` + `collapseTrie` emitting a collapsed `(hash,rlp)` set)
  but *"less fully factored than besu's `MerkleTrie`/`WorldUpdater` stack (the seam is split across two
  mutually-cyclic packages)"* (`clients/fukuii/state-trie.md` §Notable patterns).
- **DEFAULT (not-negotiable) — the state-root algorithm is consensus.** *"The state-root algorithm itself
  (node encoding, `<32`-byte inlining, keccak key hashing, RLP) is consensus-load-bearing and must stay
  geth/core-geth byte-identical — those are DEFAULT-not-negotiable, not menu items."* (`state-trie.md`
  §Best-practice.) *"core-geth confirms ETC introduces zero state-structure divergence … network-specific
  behavior (ECIP-1017 rewards, fork-selected VM rules) is applied upstream as `StateDB`/state mutations, never
  in the trie."* (§fukuii implications.)
- **DEFAULT (adopt-as-default-on) — flat-state accelerator under a trie fallback.** *"O(1) warm reads via
  `hash(key)→value` mirror; trie stays authoritative + fallback, so correctness never depends on the accelerator
  being complete. Low-risk: additive, degrades gracefully."* fukuii's `FlatAccountStorage`/`FlatSlotStorage` are
  *"a partial start on this"* — and the AS-IS gap is explicit: `FlatAccountStorage` is *"not on the live account
  read path"* (`clients/fukuii/state-trie.md` §Gotchas).
- **DEFAULT-candidate — path/nibble-keyed node store.** *"One path = one write (no hash-recompute cascade),
  better block-cache locality, bounded disk + cheap online pruning. The direction all three independently
  converged on."* (`state-trie.md` Approach catalog.) The complement to the hash-keyed archival default — the
  block-processing-hot-path default, offered as a `StorageProfile` axis, not a rewrite.
- **OPTIONAL(archival/perf)** — flat state + commitment-on-demand (erigon Domains / reth streaming `HashBuilder`);
  *"NOT the default hot-path choice for a hash-keyed client."*
- **OPTIONAL(light/custody)** — Bonsai thin-trie + TrieLog reorg-rollback, and sparse-trie / witnesses (reth).
- **OPTIONAL(validator/perf)** — parallel / concurrent state-root (reth), *"once a streaming/flat substrate exists."*

### `observations/storage-persistence.md`
- **DEFAULT — RocksDB + column families.** *"Per-dataset independent tuning (cache, compression, BlobDB, GC)
  impossible in a single keyspace; the dominant JVM/CLR pattern and fukuii's existing shape."* Single-keyspace
  byte-prefix (geth) is **OBSOLETE** as fukuii's primary model.
- **DEFAULT — explicit, persisted, checked schema-version.** *"Makes 'what schema is this datadir' a checked
  precondition, not an assumption. fukuii has NONE (confirmed gap) … the single most exportable pattern and
  fukuii's clearest gap … Highest-value single item."* Authority: besu `DATABASE_METADATA.json` + a
  `(format, version)` enum with per-bump rationale — extended here to record the **active `StorageProfile`**
  (reth's 3-marker / nethermind auto-detect informing what else the marker must carry).
- **DEFAULT — keep the L1 batched `unboundedScan`.** *"It already sits at the strong (erigon/reth
  transaction-owned) end of the spectrum, structurally more defensive than besu's own `Stream.onClose`.
  Optionally add a live-iterator/leak metric (geth's `liveIterGauge`)."* Explicit **do-not** *"align to besu"*
  (its convention is weaker).
- **DEFAULT-adjacent / OPTIONAL** — BlobDB per static CF (besu) for freezer-like write-amp reduction inside the
  existing RocksDB engine; per-CF/per-table-shape tuning.
- **OPTIONAL(sync-phase)** — live-tunable compaction profiles (nethermind `ITunableDb` `HeavyWrite`/`DisableCompaction`);
  *"measured write-amp wins"* — the cited fix for fukuii's SNAP memtable-starvation incident.
- **OPTIONAL(custody/end-user)** — online full-pruning (nethermind copy-live-and-swap); *"the biggest missing
  operator capability."*
- **OPTIONAL(migration)** — dual key-scheme + live fallback-read migration (nethermind Hash↔HalfPath).
- **OPTIONAL(light/end-user)** — Bonsai-style flat + thin proof trie + trie-log.
- **OBSOLETE / not-for-fukuii-yet** — MDBX + flat Domains (erigon) and reth's secondary-engine split; *"no
  mature JVM MDBX binding … a genuine re-architecture, not a swap."*
- **Invariant** — *"network identity belongs in the config/type layer, not storage keys — the same datadir
  schema serves every family … keep fukuii's CF layout network-neutral."*

### `observations/historical-distribution.md`
- **DEFAULT (state-pivot bootstrap)** — checkpoint-anchor. *"Near-exact match to fukuii's checkpoint-service …
  the most transferable single idea."* fukuii already occupies besu's niche but ships the state itself, not a
  pointer, with only a CRC32 trailer (`clients/fukuii/historical-distribution.md` §Gotchas — weaker than era1's
  accumulator).
- **DEFAULT (storage-lifecycle adopt)** — hot/cold freezer split. *"Migrate ETC blocks past reorg depth out of
  the mutable RocksDB working set into an append-only, number-addressed flat cold store."* core-geth pins the
  ETC shape: *"the cold store must retain total difficulty (the `diffs` table) — the post-merge ETH freezer
  table set is the wrong template for a PoW successor."* fukuii today has **no hot/cold split** (confirmed by
  grep).
- **Cross-cutting** — *"fixed-block-range file shards make transport AND expiry fall out of one design … the
  same whole-file granularity that lets you seed/copy one file also lets you `rm` it for expiry."* → one
  sharded cold format unifies freezer + era1 + EIP-4444 expiry.
- **OPTIONAL(fast-bootstrap / archival)** — era1 verifiable HTTP history bootstrap; *"composes with checkpoint-
  sync"* (checkpoint = state pivot, era1 = backfilled history). For ETC only the *original* pre-merge era1 is
  needed; EraE / EIP-4444 machinery is *"PoS-specific and unneeded."*
- **OPTIONAL(light/custody)** — EIP-4444 history-expiry. fukuii has **none** (matches core-geth's no-expiry row).

## 4. besu structural mirror

besu is the apples-to-apples JVM target: same language family, same RocksDB Java binding, same CF-per-purpose
model, same big-int/`Bytes` constraints (no native `uint256`), and — decisively for R8 — the JVM proof that
**two full storage approaches coexist behind one interface**. Read its Java alongside geth's Go from line one.

### 4a. Trie reader/writer seam — the decoupling
besu factors the trie as a pure structure over a **load/store function pair** — the DEFAULT seam fukuii must
land cleanly (it has the shape today but split across the cyclic packages):

- `NodeLoader` — `Optional<Bytes> getNode(Bytes location, Bytes32 hash)` — the read half.
- `NodeUpdater` — `void store(Bytes location, Bytes32 hash, Bytes value)` — the write half.
- `MerkleTrie<K,V>` — the trie interface: `get`/`put`/`remove`/`getRootHash`/`commit(NodeUpdater)`/
  `getValueWithProof`/`entriesFrom`/`visitAll`/`visitLeafs`. `StoredMerklePatriciaTrie` is the persistent impl,
  `SimpleMerklePatriciaTrie` the in-memory one — *one interface, storage policy is a constructor argument.*
- `StoredNodeFactory` / `DefaultNodeFactory` — node construction + RLP decode; visitor pattern
  (`GetVisitor`/`PutVisitor`/`RemoveVisitor`/`CommitVisitor`/`ProofVisitor`) for every traversal.

**Note the `location` parameter.** besu's `NodeLoader`/`NodeUpdater` take **both** a `location` (nibble path)
and a `hash` — that is precisely the abstraction that lets besu key nodes by *either* hash (Forest) *or* path
(Bonsai) behind the same function pair. fukuii's `INodeStorage` scheme-indirection seam (§5, gap #4) is this
`(location, hash)` shape realized as the storage boundary. **The `location` is account-scoped.** As-built
(`storage/INodeStorage.scala`) it is `NodeLocation(owner: Option[accountKey], path)` — realizing account
scoping via nethermind's explicit `(owner, path)` key (`NodeStorage.cs:32-35`) rather than besu's bare
single nibble path: `owner = None` addresses a node in the state trie, `owner = Some(accountKey)` a node in
that account's storage sub-trie. The path-keyed physical key is `owner ++ path ++ nodeHash` (the D4 hash-tail
folded into the key, not discarded); a bare per-subtrie nibble path would collide across accounts sharing one
node store.

**fukuii's Scala 3 realization:** keep the immutable functional `MerklePatriciaTrie[K,V]` (Mantis lineage — it
already gives the geth-`NodeSet` decoupling: `(root, mutations) → (newRoot, dirtyNodes)`), but express the
load/store pair as the module boundary: **`storage` provides only bytes keyed by `(location, hash)`; `trie`
provides the typed `MptStorage`/`NodeLoader`/`NodeUpdater` on top.** The trie never imports RocksDB; `storage`
never imports node types. That is besu's `NodeLoader`/`NodeUpdater` seam realized as the L2 module edge.

### 4b. DataStorageFormat — the multi-approach selector besu proves
besu's `plugin-api/…/storage/DataStorageFormat.java` (`FOREST` / `BONSAI` / `X_BONSAI_ARCHIVE`) is the shape
of fukuii's `StorageProfile` (§5, gap #1): a **single enum that selects an entire coexisting storage
philosophy**, with `WorldStateKeyValueStorage` hierarchies per format. besu's Bonsai flat strategy
(`.../bonsai/storage/flat/BonsaiFullFlatDbStrategy.java`, `BonsaiFlatDbStrategy.java`, `BonsaiPartialFlatDbStrategy.java`)
is the direct mirror for fukuii's flat overlay (fukuii's `FlatAccountStorage` already cites
`BonsaiFullFlatDbStrategy.getFlatAccount` by name). fukuii composes *more axes* than besu's single enum
(node-keying, freezer, expiry, backend on top of pruning+flat) — but `DataStorageFormat` is the structural
proof that the selector belongs at the interface, not bolted on.

### 4c. DataSource / KV backend + self-describing CF config
besu `RocksDBColumnarKeyValueStorage` (a `TransactionDB`/`OptimisticTransactionDB` with MVCC snapshots) is the
tuning reference for fukuii's `RocksDbDataSource`. fukuii's backend is a plain `RocksDB.open` (no MVCC) — keep
that (fukuii's atomicity comes from `WriteBatch` + the batched-iterator discipline, not MVCC snapshots), but
cross-check per-CF options, compression, and the `setStatsDumpPeriodSec(0)` JNI-SIGSEGV guard against besu.
Keep the fukuii-authored hardening the AS-IS doc catalogs (the `#1355` batched-iterator fix, the
`deleteRange`-not-loop rule, the global `dbWriteBufferSize`/`maxTotalWalSize` memtable ceiling) — those are
strictly stronger than besu's shape and are driven by cited ETC-mainnet incidents.

This is the concrete improvement over fukuii's *one shared `ColumnFamilyOptions` for all 20 CFs*. besu's
`SegmentIdentifier` (`plugin-api/…/storage/SegmentIdentifier.java`) is a **self-describing config carrier** —
each segment declares its own tuning, not a global default:

```
String getName();  byte[] getId();
boolean includeInDatabaseFormat(DataStorageFormat);   // format-gated CFs (Forest vs Bonsai)
boolean containsStaticData();                          // append-only ⇒ BlobDB-eligible
boolean isEligibleToHighSpecFlag();                    // opt-in 1 GiB cache
boolean isStaticDataGarbageCollectionEnabled();
boolean isCacheIndexAndFilterBlocks();
```

`KeyValueSegmentIdentifier` (in `ethereum/core/…/keyvalue/`) is the concrete enum:
`BLOCKCHAIN(id=1, staticData=true)`, `WORLD_STATE(id=2, FOREST)`, `ACCOUNT_INFO_STATE(id=6, BONSAI)`,
`ACCOUNT_STORAGE_STORAGE(id=8)`, `TRIE_BRANCH_STORAGE(id=9)`, `TRIE_LOG_STORAGE(id=10, staticData=true)`, …
Each carries the flags that pick cache size, BlobDB eligibility, and format-gating. fukuii's `Namespaces` (19
single-byte constants, `nsSeq`, already citing besu's `ACCOUNT_STORAGE_STORAGE`/`ACCOUNT_INFO_STATE`) becomes a
**Scala 3 `enum Namespace` whose cases carry the same self-describing config** (30 cases as-built —
`storage/Namespace.scala`: 14 core/ported CFs incl. `ChainWeight` + 3 SNAP journal + 2 path-scheme +
`SchemaMeta` + 4 refcount/prune + 5 `Cold*` + `TrieLog`) — the static CFs (receipts,
headers, **chain-weight / total-difficulty**, canonical-mapping, trie-logs, checkpoint, **the SNAP
frontier-journal CFs**) get BlobDB / GC flags a hot CF (`Node`) does not. **reth's per-table
tune-against-defaults** (disable compression + bloom for incompressible-always-hit hash tables, e.g.
`tx_hash_numbers`) is the same carrier's OPTIONAL(perf) knob — an axis on the `Namespace` case, "under-explored"
per the SR.

**`chain-weight` (per-block total-difficulty) is a first-class, PoW-load-bearing CF — not optional, and
explicitly enumerated so the rebuild cannot drop it** (the same omission class as the SNAP-progress CFs,
`coherence-pass-03` L2-F1). It is the **hot-path backing store the L6 §5 TD-sourcing invariant reads** for
fork-choice + MESS/ECBP-1100 heaviest-chain comparison — TD is *never* trusted from the wire (eth/69+
removed it, and it was never the security boundary); a peer's weight is computed from PoW-validated
headers and compared against **the locally-stored canonical chain-weight**, so that store must be O(1)-keyed
by canonical block and preserved from the AS-IS `Namespaces` (`ChainWeightStorage` is one of the 19). It is
**written atomically with its block** (the block-append + chain-weight commit share one `WriteBatch` —
BUG-W7, below) so a crash can never leave a block without its weight (which would corrupt PoW fork choice
on restart). The cold store retains it too (core-geth ETC invariant, §4e — the ETH freezer that *drops* TD
is the wrong PoW template). This is fukuii-specific first-class treatment: post-merge ETH clients demote TD
(the CL owns fork choice), but for a PoW successor TD is load-bearing at both the hot and cold tiers.

**SNAP frontier-journal CFs + WAL-durability write contract (`coherence-pass-03` L2-F1/F2, reciprocating
L7 §6.8.1).** L7's SNAP heal keeps a **transactional per-dequeue frontier journal in dedicated column
families** (besu `SNAPSYNC_MISSING_ACCOUNT_RANGE` / `SNAPSYNC_ACCOUNT_TO_FIX` model; L7 §6.8.1 +
[`snap-porting-reference.md`](../../../research/clients/topics/snap-porting-reference.md) §5) — L2 **owns
the CF registry, so it must declare those SNAP-progress/frontier CFs** in `enum Namespace` and assign them
to the sync-capable profiles' CF-set (the `SchemaMarker` profile→CF-set gating requires every CF declared;
L7 writes them). And the **DataSource/`Tune` write contract MUST guarantee WAL durability at
frontier-checkpoint boundaries — no unqualified WAL-off bulk-write knob**: nethermind's
`WriteFlags.DisableWAL` on range commits is safe *only because* it re-runs the whole phase, but with L7's
persisted frontier a lost memtable would mark missing nodes "done" → **silent state corruption**. The
`Tune` seam's throughput knobs must not expose a WAL-off path that outlives a frontier checkpoint.

### 4d. TrieLog — the clean R7 reorg-event source
besu's `plugin-api/…/trielogs/TrieLog.java` is a per-block `{prior, updated}` **leaf-diff** journal with a
`rollForward`/`rollBack` engine walking to a shared ancestor. This is a **clean, serializable reorg-event
source** — exactly what R7's gRPC/ExEx seam wants to carry (`optimizations.md` L2 row "BonsaiTrieLog
`{prior,updated}` leaf-diff → OPTIONAL(light) + R7 enabler"). fukuii's reorg substrate today is
`ReferenceCountNodeStorage`'s **node-level** death-row snapshots — coupled to the hash-keyed store and *not* a
leaf diff, so it can't be handed to an out-of-process consumer as a state-change stream. Build the flat/pruned
(`StorageProfile`) path with a besu-TrieLog-shaped `{prior,updated}` journal so the reorg-event source is
available where R7 needs it; keep the node-refcount snapshots for the hash-keyed archival profile.

### 4e. Freezer / era1 / checkpoint
besu `util/era1` (reader/writer, `blocks import/export --format=ERA1`) is the JVM reference for the **ERA1
standard** fukuii's bespoke `CheckpointArchive` should converge toward for interoperable history; besu's
checkpoint-anchor is the concept fukuii already occupies (but ships the state, not a pointer). For the freezer
itself besu uses **BlobDB-per-static-segment** rather than a separate engine — the in-engine analogue fukuii
can reach without a second store; go-ethereum `core/rawdb` freezer + core-geth's TD-retaining table set are the
byte references for what an ETC cold store holds.

## 5. Scala 3 idiom targets

The idiom is native to us; no reference client writes it (geth is Go, besu is Java). Concrete shapes:

- **`enum MptNode`** replacing the `sealed abstract class MptNode` + subclass hierarchy
  (`Node.scala:15-117`): cases `Leaf(key, value)`, `Extension(sharedKey, next)`, `Branch(children, terminator)`,
  `Hash(ref)`, `Null`. This directly **retires the AS-IS `@unchecked` exhaustivity suppressions** in the insert
  paths (`MerklePatriciaTrie.scala:336-397`) — a total `match` over the enum is compiler-checked, so a future
  node-shape change *is* caught. `encode`/`hash` as lazy vals memoised via the L0 `rlp`/`crypto` givens.
- **Keccak-key "secure trie" is L1 serializer composition, not a `trie`-layer wrapper.** The hashed-key mapping
  lives at the **L1 `domain` key-encoder** (`Address.hashedAddressEncoder` / `HashByteArraySerializable`),
  folded into the key serializer — **not** a `trie`-layer `SecureTrie`/`StateTrie` wrapper class (geth wraps it
  in `secure_trie.go`/`StateTrie`; fukuii folds it, byte-identical hashed-key bytes). Consequence: the DoD
  "secure-trie known roots" vector (§8) exercises the **L1 encoder**, not a `trie` type — don't search `trie`
  for a secure-trie wrapper.
- **`enum StorageProfile`** (gap #1) — the besu `DataStorageFormat` analogue, but composing the six axes as a
  product, resolved once per `ChainInstance`:
  ```scala
  final case class StorageProfile(
      keying:    NodeKeying,        // Hash | Path | Both  — the trie-node key scheme (Both = the CF-opening footprint, not a dispatch scheme — StorageProfile.default)
      pruning:   PruningMode,       // Archive | Basic(history) | InMemory(history)
      flat:      FlatAccelerator,   // Off | On
      freezer:   ColdStore.Mode,    // None | Freezer(reorgDepth) | Era1
      expiry:    HistoryExpiry,     // None | After(blocks)
      engine:    KvEngine           // RocksDb  (MDBX = OBSOLETE, not offered) — the KV backend, NOT a 2nd keying axis
  )
  object StorageProfile:
    val ArchivalDApp, TipServer, PrunedRelay, ResourceLight, Validator, MiningPool: StorageProfile = ???
  ```
  The named role presets are sugar; the record is the seam. The profile is **data, selected per network×role**,
  never an `isEtc()` branch (R1/R3). **`keying` and `engine` are orthogonal and must not both encode
  hash-vs-path** (R8-7): `keying` (`Hash | Path`) is the *sole* trie-node key-scheme axis; `engine` is the
  KV *backend* (RocksDB today; MDBX OBSOLETE) — it does **not** re-state the keying choice, so there is no
  invalid `keying=Path, engine=…HashKeyed` combination to guard. The path/hash store distinction is realized
  under one `engine` by the `INodeStorage` scheme-indirection seam (below), keyed off `keying` alone. The
  `engine` axis is a **reserved single-inhabitant seam** — RocksDB is its only live inhabitant (MDBX OBSOLETE,
  §7 foot) — so `StorageProfile` is **five live axes + one reserved**, not a live six-way selector; building
  `engine` as a live axis would imply a backend variability that does not exist.
- **`INodeStorage` scheme-indirection seam** (gap #4, R8) — a mutable `Scheme` (`Hash | Path`) at the
  `MptStorage` boundary with a **directional dual-read**, so archival = hash / pruned = path is a role choice
  **and** an online Hash→Path migration (nethermind `Nethermind.Trie/INodeStorage.cs` shape). **The path-keyed
  key must be account-scoped** — fukuii's single node store is shared by the state trie and every per-contract
  storage trie, so a bare nibble path would collide storage-subtrie nodes at the same path across different
  accounts. Built as nethermind's explicit `(owner, path)` key — `NodeLocation(owner: Option[accountKey], path)`,
  physical key `owner ++ path ++ nodeHash` (`storage/INodeStorage.scala`); `owner = None` → the state trie,
  `Some` → a storage sub-trie — **not** besu's single global nibble-path-from-account-root. The **dual-read is
  directional and migration-gated** (`current-scheme-key ?? other-scheme-key`): a read probes the *other* scheme
  **only when a migration is in flight** (`migrationInProgress`), steady-state a single probe (geth-aligned
  `ReadTrieNode`, not nethermind's unconditional dual-read); writes and deletes use the active scheme alone (D3
  delete-asymmetry — a path-scheme delete leaves any hash-keyed archival copy intact). `RequirePath` (nethermind
  `NodeStorage.cs:19,25`) is the perf carve-out:
  under a pure-hash profile the path computation is skipped. This retires the one-way-locked `PathNodeStorage`
  SNAP island — path-keying becomes a first-class general backend, not a SNAP-only store guarded off from the
  live trie.
- **Composable pruning under the `enum PruningMode` selector** (gap #6 — the §5/§6 vs §7 reconciliation).
  `PruningMode` stays the *user-facing named selector* (Archive / Basic / InMemory), but each mode is
  **implemented by composing** an `EvictionStrategy` ("when to evict RAM") × `PersistenceStrategy` ("where/when
  to flush disk") — nethermind's `IPruningStrategy`/`IPersistenceStrategy` split. The enum is the preset; the
  two strategies are its composed internals. The `EvictionStrategy` (nethermind's `IPruningStrategy`) is itself
  a **two-method split** — `ShouldPruneDirtyNode` vs `ShouldPrunePersistedNode` (`IPruningStrategy.cs:10-11`):
  evicting a dirty in-RAM node and pruning a persisted disk node are distinct decisions, so the composed
  strategy must express both, not a single "evict?" predicate. This kills the AS-IS *two independently-maintained refcount impls*
  (`ReferenceCountNodeStorage` disk vs `CachedReferenceCountedStorage` in-memory) — one composed policy, not two
  class hierarchies re-implementing one idea.
- **Safe-height-gated `prune()` barrier** (gap #2, R7) — `prune()` takes an external safe-height, never prunes
  purely on local reorg depth:
  ```scala
  def prune(safeHeight: BlockNumber): IO[PruneReport]   // safeHeight = min(local reorg horizon, min(consumer FinishedHeights))
  ```
  The consumer registry (reth ExEx `FinishedHeight`) lives at L9's gRPC seam; the *hook* is designed into L2's
  pruning seam now (**one-way to retrofit**). Absent a consumer, `safeHeight` = the local reorg horizon (today's
  behavior) — additive, no regression.
- **`SchemaMarker` recording the active `StorageProfile`** (gap #7) — `enum StorageFormat` + a
  `SchemaMarker(format, version, profile)` value, hand-rolled binary (format ordinal + 4 version bytes + six
  profile-ordinal bytes — `storage` has no `rlp`/`circe` dependency, `SchemaMarker.encode`/`decode`), written
  to a dedicated CF and **checked at open**: a datadir built under one profile (keying/pruning/freezer) that is reopened under a mismatched profile
  fails loud with a typed error, not RocksDB undefined behavior. The besu `BaseVersionedStorageFormat` analogue,
  extended to carry the profile (reth's 3-marker / nethermind auto-detect informing what the marker must hold).
  Because the resolved profile also **gates which CFs exist** (besu `KeyValueSegmentIdentifier.includeInDatabaseFormat`
  format-gating — Forest opens `WORLD_STATE`, Bonsai opens `ACCOUNT_INFO_STATE`/`TRIE_LOG` instead), the marker
  check reconciles the **on-disk CF set with the recorded profile**, not only scalar `(format,version,keying)`
  equality — a profile whose CF set doesn't match the datadir's actual CFs fails at the marker, before RocksDB
  hits a missing/extra column family.
- **`HashBuilder`-shaped streaming state-root substrate** (gap #5) — keep the mutable `StackTrie` (geth port)
  and wire it to a reth-`HashBuilder`-style streaming cursor (`TrieCursor`/`HashedCursor` + prefix-set) so the
  root can be computed over sorted hashed leaves for the flat/parallel profiles. `ShardEnumerator` (16 shards,
  first-nibble) already aligns with go-ethereum `triedb/generate.go` `GenerateTrie`'s 16-partition parallel rebuild —
  **connect them**: `ShardEnumerator` + `StackTrie` is the enumeration backbone for a parallel `GenerateTrie`
  equivalent (the OPTIONAL(validator/perf) parallel state-root, and the snap/2 completion path — see §7 SNAP).
- **Opaque types** (born at L1 `domain`, consumed here): `NodeHash` (opaque over the 32-byte `crypto` hash),
  `NodeEncoded` (opaque over RLP bytes), `StateRoot`/`StorageRoot`, `Scheme`, `SafeHeight`. A node's location is
  the account-scoped `NodeLocation(owner: Option[accountKey], path)` pair (`owner = None` → state trie, `Some`
  → that account's storage sub-trie), not a bare nibble path (`storage/INodeStorage.scala`). `Namespace` is
  **not** an opaque-over-`Byte` — it is an `enum Namespace` (`storage/Namespace.scala`) whose cases carry
  besu-`SegmentIdentifier` flags + `profiles` + `includeInDatabaseFormat`. No raw `Array[Byte]` addresses
  crossing the seam.
- **RLP codecs split by module.** Only the **`trie`-side** `TrieLog`/`LeafChange` `{prior,updated}` diff uses
  L0 `rlp` `derives RLPCodec` (`trie/TrieLog.scala`). `storage` itself has **no `rlp`/`circe` dependency**
  (`storage → domain, common` only): its records — `SchemaMarker` (six ordinal bytes + version), the pruning
  bookkeeping (`PruningCodec`), `Era1Shard.Codec`, and `CheckpointArchive` — are hand-rolled length-prefixed
  binary codecs, not `derives`.
- **`NodeLoader`/`NodeUpdater` as SAM function types** (`(Location, NodeHash) => Option[NodeEncoded]` /
  `(Location, NodeHash, NodeEncoded) => Unit`) passed as `given`/constructor args — besu's function-pair seam.
- **`extension` methods** for node ops (`node.childHashes`, `hash.namespaced(ns)`) instead of `implicit class`.
- **`ColdStore` seam** (gap #11) — a sealed `ColdStore` with a hot→cold `freeze(reorgSafeRange)` and a
  number-addressed read path; one **fixed-block-range sharded format** underneath so freezer + era1 export +
  EIP-4444 expiry all fall out of the same sharding (`historical-distribution.md` cross-cutting note). **The
  shard is a byte-canonical, immutable era1 (E2Store) *file*, not merely an in-engine RocksDB key-range** —
  because cold-store/era1 *distribution* is a **committed** L7 deliverable (HTTP-range **and BitTorrent** **and**
  the ERA1 downloader — §"Layer boundaries"), every node MUST produce byte-identical shard-file bytes for the
  same block range (so torrent infohashes match across the swarm) and each shard MUST carry its **own
  accumulator commitment** so a shard fetched from an untrusted peer self-verifies against a known root before
  trust. The local RocksDB freezer may back the hot→cold migration + `rm`-expiry, but the **distributable
  representation is the canonical era1 file + a shard `manifest`** (block-range → shard-id → accumulator-root)
  that L7 turns into torrent metainfo / WebSeed URLs. Shard boundaries align to the ERA1 epoch (8192 blocks)
  for interop. **TD is retained** in the cold shard (core-geth ETC invariant — verified against the living ETC freezer: core-geth
  `ancient_scheme.go:35-36` `ChainFreezerDifficultyTable = "diffs"`, retained `:46`, appended
  `chain_freezer.go:293`; the post-merge ETH freezer *drops* TD, the wrong template for a PoW successor);
  freeze at the **write-time boundary** (reth) rather than a separate freeze pass (avoids the geth freeze-pass bug).
- **cats-effect `IO` + `fs2.Stream`** for `iterate`/`scanRange` (already the AS-IS `DataSource` return shape) —
  keep, no `Future`/blocking/`unsafeRunSync` in the contract (R5, TL1/TL2).

## 8. Exit DoD (GREEN bar)

L2 is done only when every module is GREEN across the gate lenses (`../README.md` gate: correctness/byte-
alignment · besu JVM-impl lens · Scala 3 idiom (mithril) · test quality (eye) · requirements+ledger check).
State-root paths additionally **forge-gated** (§9).

**Byte-exact reference vectors that must pass:**
- **State-root vectors** — the `ethereum/tests` state-trie fixtures and go-ethereum `trie` test vectors:
  empty-root hash (`EmptyRootHash`), secure-trie known roots, node RLP encoding, the `<32`-byte inlining
  threshold, HP nibble compaction round-trips. Byte-identical to geth/core-geth (consensus). (The secure-trie
  known-roots vector exercises the **L1 `domain` key-encoder** — `hashedAddressEncoder` — not a `trie`-layer
  wrapper; §5.)
- **Cross-backend state-root parity** — the same state committed under the hash-keyed **and** path-keyed
  `StorageProfile` produces the byte-identical state root; the streaming/`HashBuilder` substrate produces the
  same root as the resident MPT.
- **Trie proof vectors** — EIP-1186 `getProof` inclusion **and** non-inclusion (walked-path terminal proves
  absence, root always included); SNAP range-proof verify (`StackTrie`/range-proof inserter).
- **DataSource contract-parity tests** — `EphemDataSource` ≡ `RocksDbDataSource` behavioral parity across
  `get`/`getOptimized`/`multiGetOptimized`/`scanRange`/`deleteRange`/`update`/`updateSync`/`iterate`; atomic
  multi-key `WriteBatch`; native range-tombstone delete; **key-ordering and empty-read edge cases** where the
  two are known to diverge (`storage-rocksdb.md` EphemDataSource note).
- **Block + chain-weight atomicity (BUG-W7, required — not optional)** — a block append and its
  total-difficulty write commit in **one atomic `WriteBatch`**; a simulated crash between them leaves the
  store consistent (either both present or neither), never a block without its weight — the guarantee PoW
  fork choice depends on for a correct heaviest-chain decision on restart (backs the L6 §5 TD-sourcing
  invariant + `coherence-pass-03` L2-F4, hereby elevated from an optional pointer to a required contract).
  The `chain-weight` CF round-trips (`getTotalDifficulty(hash)` after `putBlock`) and is retained through a
  cold-store freeze.
- **SNAP frontier-journal CFs declared + WAL durability (L2-F1/F2, reciprocating L7 §6.8.1)** — the SNAP
  progress/frontier CFs are present in `enum Namespace` and in the sync-capable profiles' CF-set (schema
  marker opens them); the write contract commits WAL-durably at frontier-checkpoint boundaries — a
  simulated crash after a checkpoint never reports a node "done" that a memtable loss dropped (no
  unqualified WAL-off bulk path outlives a checkpoint).
- **Iterator-safety regression** — grep clean (`newIterator` only inside `withResources`); a cancellation/
  concurrent-`close()` test reproducing the `#1355` shape and proving no native iterator outlives a batch.
- **Schema-version + profile** — matching `(format,version,profile)` opens; a mismatched keying/pruning/absent
  marker is rejected at startup with a typed error; the marker check reconciles the **opened CF set with the
  recorded profile** (format-gated CFs, besu `includeInDatabaseFormat`), not only scalar `(format,version,keying)`.
- **Pruning + rollback + safe-height** — the §7 pruning-mode tests, each asserting the post-rollback state
  root; `prune(safeHeight)` never removes a node above the barrier.
- **Flat accelerator** — flat-first account/slot read == MPT read; fallback correctness when flat is empty.
- **Cold-store** — migrating a reorg-safe range preserves reads and **retains TD**; a `ColdStore` shard
  round-trips through ERA1 export/import (accumulator-verified).
- **Per-instance isolation** — two `ChainInstance`s in one process open distinct datadirs with distinct
  handles/caches and no shared mutable static (the R2 isolation grep is a DoD gate — §9).

**Test tiers:** `storage/test` + `trie/test` (unit, `EphemDataSource`), then `IntegrationTest` for
`RocksDbDataSource` (real DB open/close/reopen, CF lifecycle, `deleteRange` at scale, freezer migration).
`eye` runs the suites and the `ethereum/tests` state fixtures; a hive `consume`/state check is the
cross-client confirmation.

## 9. Risks & consensus-critical flags

**Consensus-critical (state root is byte-exact — one-way door → forge gate).**
The trie's node RLP encoding, `<32`-byte inlining (`NodeCapper`), HP nibble compaction (`HexPrefix`), keccak
key hashing (the "secure trie", folded into the key serializer), and bottom-up state-root computation are
**consensus-load-bearing**. State-root litmus (`consensus-change-protocol.md`): a change that alters the state
root is forge's. Any change to the `NodeStorage`/`MptStorage` read/write path, namespace IDs, CF configuration,
or the `StorageProfile` keying axis requires **forge review** (`storage-rocksdb.md` §Consensus state — FORGE
routing). Validate every value against the *verified reference map built from go-ethereum + besu first*, then
diff — never against the old code. **The multi-backend seam does not change this**: the path-keyed profile must
produce the *same* state root as the hash-keyed one (only the storage layout differs, not the commitment), and
that cross-backend parity is a forge-gated DoD vector (§8).

**Network-neutrality invariant (R1/R3 — the L2 analogue of the `Eth*`/`Etc*` opcode trap).** The fork-named-
opcode trap doesn't reach the trie (no fork-named types here), but the equivalent applies: **the CF layout,
node schema, and `StorageProfile` axes must stay network-neutral** (core-geth: "fork the config system, not the
storage schema"). No `isEtc()` / `is_optimism()` in a storage reader; network identity lives in the config/type
layer, so one datadir schema serves every family (the erigon `FrozenBorBlocks`-in-`ChainHeaderReader` leak is
the cautionary counter-example). The `StorageProfile` is selected *by role × network as data*, never a branch.

**Multi-instance isolation (R2 — DoD grep).** No process-global DB state: no `object … { var db … }`, no static
block cache, no JVM-wide `StorageProfile`. The `DataSource`, RocksDB handle, block cache, metric sink, and
profile are per-`ChainInstance`, constructor-injected. The isolation grep (`object … { var … }` / shared
statics under `storage`) is a DoD gate — each hit is an isolation break to justify or remove.

**Storage traps carried from `storage-rocksdb.md` (not consensus, but corruption/crash risk):**
- **Iterator leak / use-after-free.** Every `newIterator` inside `withResources`; the batched `unboundedScan`
  keeps no native iterator alive across an fs2 suspension or a concurrent `close()` (the `#1355` SIGSEGV race).
  Grep-clean is a DoD gate, and any leak fix is a whole-`storage/` sweep, not a one-file patch.
- **Bulk delete.** `deleteRange` (native range tombstone), never point-delete-in-a-loop — the cited ~140M-key,
  ~30-minute, near-OOM incident.
- **`updateSync` only for durability boundaries** (pivot/checkpoint commit), never a hot loop (10–100× slower).
- **Global memtable ceiling.** `dbWriteBufferSize`/`maxTotalWalSize` cap the *sum* of all CF memtables — without
  it, SNAP's write-heavy phase starved the box (~1.9 GiB off-heap on ETC mainnet). Carry the ceiling forward;
  the `ITunableDb` sync-phase profile (§7) is the additive, not a replacement, for it.
- **`setStatsDumpPeriodSec(0)`** — besu's documented JNI-SIGSEGV workaround; apply when statistics are enabled.
- **Namespace-ID immutability.** Changing a namespace ID silently corrupts (reads return empty, old data
  stranded). The new `SchemaMarker` is the guard that makes this a *checked* precondition — and it now also
  catches a `StorageProfile`/keying mismatch, not just a `(format,version)` mismatch.
- **`EphemDataSource` divergence.** Not thread-safe, no WAL/bloom/CFs, O(n) scans, key-ordering/empty-read
  edge-case divergence from RocksDB — contract-parity tests must cover the edges; production use is confined to
  throwaway stateless computes (`eth_simulate`, Engine-API dry runs), never restart-surviving data.

**Structural risk — the cycle.** The db↔mpt resolution (§6) rests on `storage` staying byte-pure. If
node-aware code (refcount child-hash propagation, the TrieLog `{prior,updated}` diff builder) leaks into
`storage`, the cycle re-forms. The DoD grep is: `storage` imports no `com.chipprbots.fukuii.trie.*`. Enforced by
the module boundary (compile error), confirmed by review. Child-hash extraction and the TrieLog diff live in
`trie`, which hands `storage` explicit child-hash lists / serialized diffs, never parsed nodes.

**Retrofit risk — the two one-way seams.** R7's `prune(safeHeight)` barrier and R8's `INodeStorage`
scheme-indirection are **structural**: absent from the seam, they are a rewrite to add later
(`optimizations.md` STRUCTURAL disposition; `feature-ledger.md` "retrofitting a second backend behind a
hash-only design is a rewrite"). Both are designed into the seam now even though their *occupancy* (a live
gRPC consumer; a shipped path-keyed profile) may be role-gated and land later. The `safeHeight` barrier binds
**both** the incremental refcount pruner **and** the online full-pruning pass (§7 online full-pruning): a
copy-swap full-prune must not drop nodes above `safeHeight` either, not only the incremental pruner.

## Layer boundaries (what lives elsewhere, and why)

_Durable placement decisions — not build-status (see the README index for what's committed)._

- **WorldState / EVM-facing account model** (`WorldStateProxy`, `InMemoryWorldStateProxy`) → **`execution`
  (L4)**. L2 provides the trie and the persistence seam; the copy-on-write world-state the EVM runs against,
  the touched-account journal, and the bottom-up `persistState` orchestration are execution's. (The state-root
  *algorithm* — node hashing — is L2; the *world-state mutation* that feeds it is L4.) The **flat-first account
  read wiring** (`getAccount` flat-first, MPT-fallback — §6 row 13) is likewise L4: L2 owns the
  `FlatAccountStorage` CF + flat-first seam, L4 flips the account read to consult it.
- **ECIP-1017 rewards, fork-selected VM rules, any network-specific state mutation** → **`execution` (L4) /
  `consensus` (L5)**, applied *upstream as account mutations*, never inside the trie (`state-trie.md`: the trie
  does not diverge ETC vs ETH).
- **SNAP-sync engagement + SNAP serving (F9)** (path-keyed store *consumption*, healing frontier walk,
  range-proof serving/ingestion, DoS budgeting, snap/1↔snap/2 `Syncer` selection) → **`sync` (L7)**. L2 owns
  the path-keyed store + the `FlatAccountStorage.seekFrom` range-serve *primitive* as storage; L7 drives it.
  This reverses the AS-IS `db → blockchain.sync` back-edge (SNAP storage components lived under `db/`): the
  primitive stays in `storage`, consumed *downward* by `sync`.
- **Checkpoint-archive *sync-time engagement*** (import-only-on-fresh-DB, config keys, resumable HTTP download
  driver) → **`sync` (L7)**. L2 owns the archive *format* (accumulator-committed) + export/import through
  `StateStorage`.
- **Cold-store / era1 *distribution transport*** — HTTP-range, **BitTorrent** (erigon's `.seg` / anacrolix-torrent
  + WebSeed-HTTP-fallback model), provenance, and the ERA1 downloader are **committed L7 deliverables (not
  optional — operator decision 2026-07-15)** → **`sync` (L7) / product seam**. **L2 owns the byte-canonical era1
  (E2Store) *file* format + the per-shard accumulator commitment + the shard `manifest`** (the seed-able,
  self-verifying unit) + the hot→cold migration seam + the expiry `rm`; **L7 owns** the torrent client, the
  WebSeed/HTTP server, the manifest distribution, and the resumable download driver. The L2 format must be
  file-canonical *now* so L7's transports are a clean addition, never a cold-store rewrite.
- **The R7 prune-barrier *consumer registry*** (reth ExEx `FinishedHeight` producers, the gRPC/dRPC data seam
  that carries the TrieLog reorg-event stream) → **`rpc`/`grpc-seam` (L9)** + **`execution`/`consensus`
  (L4/L5)** as the reorg-event source. L2 owns the `prune(safeHeight)` *hook* and the TrieLog *format*; L9
  supplies the `min(consumer heights)`.
- **Metrics registry** (`RocksDbCacheMetrics`, the `liveIterGauge` sink) → **`observability` (L8)**. L2 emits
  the counters **per-instance** (R2); the per-instance registry lives at L8.
- **Keystore / V3 KDFs** → **`keystore` (L8)** — not a storage or trie concern.
