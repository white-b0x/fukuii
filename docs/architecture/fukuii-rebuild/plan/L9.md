_Prospective plan, SR-grounded, written before the layer is built. Retrospective as-built record
lands in `../09-*.md`; live build-status is the `../README.md` index, never here. Read
[`README.md`](README.md) (template, authority model, doc discipline) first._

L9 is the node's **serving surface**, its **agentic front door**, and its **product-family seed** —
three concerns over one service layer:

- **`rpc`** — the JSON-RPC / WS / IPC / GraphQL surface plus the Engine-API JWT transport contract for
  the PoS family.
- **`agentic-interface`** — native **MCP / A2A / ACP** as a first-class transport **peer to GraphQL**
  (not a `mcp_`-namespace afterthought over the JSON-RPC port), an additive-L9 transport over the same
  `ServiceResponse[T]` service layer. Lives inside the `fukuii-rpc` module (a concern, not a third
  sbt module).
- **`grpc-seam`** — the first-class exec-extension data plane: reth-ExEx reorg-aware notifications
  realized cross-process as an erigon-`StateChanges`-style gRPC service — the DRPC-Provider bridge
  (`cross-cutting-themes.md` Theme 2 / DRPC-GATEWAY-01).

**The one structural (not additive) piece is the R11 auth/identity/capability gate** — a per-request
`Principal` + `Capability` + audit log threaded through the dispatch registry, **per-instance (R2)**,
designed **now**, not per-transport: MCP-2026 (OAuth 2.1 + write-ops), Engine-API JWT, and the
external-signer custody boundary **all converge on this one seam**. The 2026 MCP stateless-core RC
*reduces* the structural burden (it aligns with R2 per-instance isolation and R8 stateless serving),
it does not raise it.

Two library decisions are **already made and must not be re-opened**: JSON codec = **circe** (MOD-06,
not json4s), GraphQL = **Caliban 3.1.2 + caliban-pekko-http** with `caliban-cats` interop (MOD-14, not
Sangria) — both born-modern on the successor **from line one** (the old library never enters), both
dep-adds **sentinel-gated**.

gain. `grpc-seam` stays a separate module because it carries a distinct (protobuf/streaming)

## 2. SR slots & verdicts

### `observations/rpc-api.md` (→ rpc)
- **DEFAULT:** "a namespace-gated registration returning a name-keyed dispatch map" (besu
  `ApiGroupJsonRpcMethods`) — "enabling is a property of the registry, not the transport"; preserve
  **METHOD_NOT_ENABLED (known, namespace off) vs METHOD_NOT_FOUND (unknown)**. "conduit's
  controller-per-namespace is the coarser variant of exactly this idea… the gap is
  namespace-gating-as-registry-property + versioned/fork-gated registration, not a rewrite."
- **DEFAULT:** Engine API as a **separate JWT-gated service** — geth's authenticated-flag-on-
  registration is "the cleanest statement: auth is a routing/deployment concern, not dispatcher
  logic"; physically separate (besu/erigon); off the public port; **inert/omittable on PoW ETC**.
- **Avoid:** the geth reflection collision gotcha — "multiple services merged into one namespace
  silently lose colliding method names" (conduit's controller-per-namespace already sidesteps it).
- **OPTIONAL(archival/RPC role):** RPCDaemon separable-process over a **remote-KV read seam**
  (erigon) → "the dRPC-Provider seam (DRPC-GATEWAY-01)… a DB-read-seam definition, not an immediate
  split."
- **OPTIONAL(enterprise):** plugin-contributed namespaces (besu `RpcEndpointService`, nethermind DI).
- **OPTIONAL:** per-module concurrency isolation (nethermind bounded pools) if `debug_*`/`trace_*`
  must not starve `eth_*`.
- **Open finding:** **FEEHISTORY-PERCENTILE-VALIDATION-01** (validate `eth_feeHistory` reward
  percentiles).

### `observations/exec-extensions.md` (→ grpc-seam)
- **DEFAULT:** "fukuii's exec-extension / data-product seam = **reth ExEx**, realized cross-process as
  a **gRPC service (erigon `StateChanges`)**." The three properties a naive callback lacks:
  1. **Reorg-aware notifications** — `ChainCommitted` / `ChainReorged{old,new}` / `ChainReverted`.
  2. **`FinishedHeight` distributed prune barrier** — node gates irreversible cleanup on
     `min(consumer heights)`; real backpressure.
  3. **WAL for restart reorg-safety** — every notification committed to disk before delivery;
     `into_inverted()` undo; resume-via-`ExExHead` backfill.
- **DEFAULT (THE gRPC-seam thesis, DRPC-GATEWAY-01):** realize ExEx cross-process as a gRPC service —
  `StateChanges` **push** co-located on the *same* service that exposes remote-KV **pull**
  (`Tx`/`Range`/`HistorySeek`).
- **Write-side shape:** carry geth's typed-reason hooks (tag each mutation by *why* — reward vs
  fee-burn vs transfer) into the notification payload.
- **OPTIONAL(by node role):** in-process typed-reason hooks (geth, archival); materialized trace-store
  (nethermind, archival `trace_*` on a pruned node); plugin event bus (besu, single-node); OpenEthereum
  `trace_*` facade (core-geth, ETC-family explorer compat).
- **OBSOLETE (as a model):** nethermind's legacy JSON-string `Grpc` fan-out — "not the model."

### F1 / R9 / R11 (→ agentic-interface) — native MCP/A2A/ACP

Grounded in `feature-ledger.md` F1, the L8-9-10 MCP dossier, and `docs/api/MCP_ANALYSIS_SUMMARY.md`
(the current-state audit) — not a per-client SR slot, since no reference client but erigon ships a
node-level MCP server.

- **DEFAULT (adopt + build), authority = erigon.** erigon is the node-level MCP authority:
  **embedded-SSE** (inside the node binary, localhost-bound, default-on, `--mcp.*`) **+ standalone
  stdio/SSE** (a separate `mcp` binary); **three connection modes tried in priority order** —

  fukuii adopts the *shape*: schema'd tools bound to **real actor-state** (not placeholder JSON),

  the R11 auth gate for any write-ops it later enables.
- **STRUCTURAL (R11) — the auth/identity/capability gate.** MCP-2026 (OAuth 2.1 + write-ops),
  Engine-API JWT, and the external-signer custody boundary **converge on one per-request `Principal`
  + `Capability` + audit-log seam** in the dispatch registry, per-instance (R2) — designed now, not
  per-transport. The 2026 stateless-core RC reduces the structural burden (aligns R2/R8), it does not
  raise it.
- **Current-state gap (the improvement target):** fukuii's MCP is **7.2% coverage (7 of 97
  endpoints), empty `{}` tool schemas, placeholder (not real) node state, and HTTP-bound to the
  JSON-RPC port** (`.github/copilot/mcp.json` + `McpService`). The rebuild makes it first-class,
  schema'd, real-state — but strictly under the **built-but-unshipped guard** (§9): every tool is
  wired to a live consumer and tested, or it does not ship.

## 4. besu structural mirror

- **rpc.** `ApiGroupJsonRpcMethods` is a namespace factory that contributes its methods **only if the
  namespace is operator-enabled**, folded into one flat name-keyed `Map<name, method>` for O(1)
  dispatch; a disabled namespace contributes zero methods and the executor preserves
  METHOD_NOT_ENABLED vs METHOD_NOT_FOUND. fukuii's controller-per-namespace is the coarser variant —
  **adopt besu's namespace-gating-as-registry-property + versioned/fork-gated registration without
  abandoning the controller grain** (`observations/rpc-api.md`). Engine API mirrors besu's
  physically-separate `EngineJsonRpcService` (own port, own JWT, own QoS timer) — fukuii already goes
  one level deeper (a whole second `ActorSystem` + `IORuntime`), which is retained as a design
  improvement, not regressed.
- **grpc-seam.** besu is **not** the authority here — its `BesuEvents`/`TrieLogService` are
  synchronous listeners with "no backpressure or prune gate," the very properties this seam exists to
  add. The structural mirror is **reth ExEx** (the notification framework) + **erigon `KV`/`StateChanges`
  protobuf** (the cross-process transport). besu contributes only the negative lesson: don't ship a
  callback bus without flow-control.

  **The mechanism, specified (not just named)** — the load-bearing details a naive re-implementation
  drops:
  - **WAL scope = tree, never pipeline.** Only reorg-able (blockchain-tree) notifications are
    committed to the WAL before delivery; final (staged/pipeline) notifications skip it (reth
    `ExExNotificationSource` — WAL-logging already-finalized blocks is wasted disk; mislabeling a live
    notification as pipeline breaks reorg recovery for that block).
  - **Reorg delivery is unconditional below the finished height.** The skip-if-already-processed
    optimization applies **only** to `ChainCommitted`; `ChainReorged`/`ChainReverted` are **always**
    delivered even below a consumer's finished height (on a reorg a consumer's finished height can
    legitimately move *down* — reth `manager.rs:135-160`).
  - **Per-consumer sender capacity 1 + a manager-owned reorderable buffer.** Each consumer handle has
    a capacity-1 sender; the manager holds the real monotonic-ID buffer and retains a notification
    only until **all** consumers have seen it (`retain(id >= min_id)`), so a fast consumer isn't
    blocked by a slow one. The manager must `wake_by_ref()` after the buffer drains from full — **the
    deadlock guard** (a full buffer that later clears must re-wake the manager or a pending item
    stalls; reth pins this with a dedicated regression test).
  - **`FinishedHeight` = the distributed prune barrier.** Each consumer publishes its finished
    height; the node gates irreversible cleanup (state/WAL prune) on `min(consumer heights)` — real
    backpressure, not advisory. Finalize the WAL only when every consumer's finished-height hash is
    still canonical. **One node-scoped aggregator (RX-XC-04):** exactly **one** `min(consumer heights)`
    aggregator per `ChainInstance`, the single registration point for **every** prune-blocking consumer —
    in-proc (`direct.*` shim) or remote (gRPC) alike; L2's `prune(safeHeight)` is driven only by it.
    Because it is a `min`, a **missing** consumer is worse than a slow one (slow → holds the barrier back,
    safe; missing → lets it advance past data still needed, **unsafe**): a consumer that fails to register
    must **HOLD** the barrier (fail-safe), never be silently omitted from the `min` (reth: one node-scoped
    `ExExManager` over the full `handles` vec, `manager.rs:280-306`/`:544`).
  - **`ExExHead` durable resume cursor.** On restart, revert any now-orphaned head, backfill to the
    node tip (buffering live notifications so none drop), then resume live — deterministic
    restart-and-reorg.
  - **erigon transport specifics:** `StateChanges` **push** (`Direction FORWARD|UNWIND`,
    `AccountChange{action ∈ STORAGE|UPSERT|CODE|UPSERT_CODE|REMOVE}`) co-located on the **same** `KV`
    service that serves remote-KV **pull** (`Tx`/`Range`/`HistorySeek`). Delivery is best-effort
    (cap-8 `PrioritizedSend`), so **the pull path is the reconcile path** — an indexer that must not
    miss a batch resyncs via range/history reads, it never relies on the stream alone.
  - **The `SubscriptionReadyNotifier` ack closes the register-then-produce race** — the timing hole
    between the server goroutine starting and the subscription being live; any reimplementation needs
    an explicit "subscription ready" ack or a subscriber misses the first batch.
  - **Write-side hot-path guard = geth's nil-hook / not-installed-wrapper short-circuit.** Reason-tagging
    each mutation (`MutationReason`: reward vs fee-burn vs transfer) must be ~free when no consumer is
    attached. geth has **no `HasHook()` symbol** (grep-confirmed absent); the true zero-cost mechanism is
    two-fold — the hooked state wrapper is **not installed at all** when no tracer/consumer is attached
    (`core/state_processor.go:77`), and each hook site is a per-hook nil-guard (`s.hooks.OnBalanceChange
    != nil` / `evm.Config.Tracer != nil`, `core/state/statedb_hooked.go:44,168`). Build it the
    not-installed-wrapper way, not a per-mutation branch before building the payload.
  - **`AccountChange.incarnation` is OPEN — owner: vault + forge.** erigon's incarnation is an MDBX
    account-versioning concept (self-destruct/recreate); fukuii's RocksDB account model differs.
    Whether the wire record carries an incarnation-equivalent is a **structural, expensive-to-change
    post-ship decision** (out-of-process readers) that vault (storage model) and forge (ETC account
    semantics) own jointly. Until decided, the state-diff record stays **version-less-additive**
    (nethermind positional-RLP "absent = zero").

## 5. Scala 3 idiom targets

- **rpc codec — circe from line one.** Every request/response DTO `derives Codec.AsObject`; the
  json4s `JsonMethodDecoder`/`JsonEncoder` typeclass pair is **not** ported — a single circe codec
  serves JSON-RPC/WS/IPC (retiring the `july-fourth` "two JSON libraries coexist by transport" and the
  `RpcClient` json4s-error-`data` special-case).
- **rpc dispatch.** Namespace registry as a gated `Map[String, PartialFunction[JsonRpcRequest,
  IO[JsonRpcResponse]]]`, but resolve to `enum DispatchMiss { case NamespaceDisabled, MethodUnknown }`
  so the METHOD_NOT_ENABLED vs METHOD_NOT_FOUND distinction is preserved (the SR-03 gap). The
  distinction has a **load-bearing precondition**: an **all-known-methods catalog** independent of the
  per-instance enabled map (besu `RpcMethod` enum shape, `JsonRpcExecutor.java:166-186` — every method
  fukuii *could* serve). `DispatchMiss.NamespaceDisabled` resolves as "name ∈ catalog ∧ name ∉ enabled"
  (→ METHOD_NOT_ENABLED); `DispatchMiss.MethodUnknown` as "name ∉ catalog" (→ METHOD_NOT_FOUND).
  Without the catalog a disabled-namespace method is indistinguishable from an unknown one, so the
  `enum DispatchMiss` alone does not supply the distinction — the catalog is what separates the two.
  Keep `ServiceResponse[T] = IO[Either[JsonRpcError, T]]` as the universal seam.
- **GraphQL — Caliban from line one.** `Schema.derived` for the EIP-1767 types; `caliban-cats`
  interop keeps resolver effects in cats-effect `IO` (cleaner than the old `Future↔ZIO` shim, since
  the codebase is already on `IO`); resolvers call the **same** `rpc` service instances (the
  anti-besu-parallel-stack pattern the `july-fourth` already gets right — preserve it). Sangria never enters.
  **The GraphQL/Caliban service boundary receives an injected per-`ChainInstance` `InstanceConfig`,
  retiring the `july-fourth` `GraphQLServiceBuilder` process-global `Config.config` read** — this is L9's carried
  commitment for the G-NL1 leak-set home L10 assigns here (`L10.md §2`; the R2 isolation-regression grep
  §8 catches any regressed `Config.`-read in per-instance `rpc` code).
- **Engine-API fork gating — declarative.** Replace the `july-fourth` imperative per-call `versionError`
  `match` with fork-gated method **registration** (besu `protocolSchedule.milestoneFor(fork)` shape):
  an un-activated fork's method is absent from the dispatch map, driven by the `ForkActivation`
  dispatch (beacon owns the timestamp-fork condition). No unconditional-register-then-reject.
- **Subscriptions/filters.** Pekko Typed `Behavior[Command]` (sealed ADT + `replyTo`), fed by the L9
  reorg-aware `Topic`/notification seam — so `logs` subscriptions carry a real `removed` flag on
  reorg (§6), not a hardcoded `false`.
- **grpc-seam notifications.** The `enum ChainNotification { case Committed(chain); case Reorged(old,
  new); case Reverted(chain) }` (reth 3-case segment shape) is **imported from `consensus-api` (L5),
  not defined here** — L5 owns reorg authority and is the sole home of the wire ADT (`L5.md §6.5`); the
  `grpc-seam` is its cross-process *transport*. L9 adds: a typed `FinishedHeight` ack protocol; the WAL
  as an effectful append-before-deliver; the write-side payload tagged with a typed-reason
  `enum MutationReason` (geth `Hooks`, from `execution`); gRPC via a sentinel-gated library (fs2-grpc /
  ScalaPB). L9 relies on L5's replay-by-height + monotonic-notification-ID guarantee for the
  `retain(id >= min_id)` buffer and `ExExHead` resume cursor (§4). The DRPC-Provider adapter is one
  `given` over the same push+pull service.
- **agentic-interface — MCP/A2A/ACP as typed transports over the service layer.** MCP tool schemas
  `derive` from the request/response DTOs (one source of truth, not hand-written `{}` placeholders);
  a `sealed trait McpTransport { case Stdio; case Sse }` runs the stdio + SSE servers; each tool is a
  thin adapter over an existing `*Service`'s `ServiceResponse[T]` (no parallel query stack). A2A/ACP
  are additional transports over the same registry, not new business logic.
- **The R11 auth gate — one seam, per-request, per-instance.** `case class Principal(...)` +
  `enum Capability { case ReadOnly, Operational, Administrative }` + an audit-log effect, resolved
  **once** in the dispatch registry and threaded to every transport (JSON-RPC, WS, MCP write-ops,
  Engine-API JWT, external-signer). Not a per-transport check; not a global singleton (per-instance
  under R2). MCP-2026 OAuth 2.1 maps `Principal`→scopes; Engine-API JWT is one `Principal` issuer.
  **Every secret/token/tag equality in the auth gate uses L0's `constantTimeEquals` primitive — not just
  the JWT (`coherence-pass-03` L9-D1; `requirements.md` R11: "all three verification paths call
  `constantTimeEquals`").** The R11 gate converges **three** credential surfaces and all three compare a
  server-held secret in constant time: the **Engine-API JWT/HMAC tag** (nethermind `FixedTimeEquals` ref),
  the **MCP-2026 OAuth 2.1 / session token**, and the **external-signer shared secret**. A data-dependent
  `Arrays.equals`/`==` on *any* of them is a timing oracle. This closes the L0→L9 constant-time consumer
  link (R11-3) across the whole auth surface, not only JWT.

## 6. Improvements over old fukuii (`july-fourth` gaps this layer closes)

From `.local/docs/research/clients/fukuii/{rpc-api,exec-extensions}.md`:

- **rpc: one JSON codec (circe), not two.** `july-fourth`: "JSON4S for JSON-RPC/WS/IPC, circe for GraphQL —
  two codec libraries by transport" and `RpcClient` "explicitly discards the JSON4S-typed
  `data: Option[JValue]` field because circe can't decode it" (`client/RpcClient.scala:39-45`). circe
  unifies the codec and kills the decoder hack.
- **rpc: Caliban, not Sangria.** `july-fourth` GraphQL is Sangria + `sangria-circe` (`GraphQLSchema.scala`,
  `GraphQLService.scala:19`). The rebuild writes GraphQL on Caliban from line one.
- **rpc: METHOD_NOT_ENABLED vs METHOD_NOT_FOUND.** `july-fourth` "collapses both to `MethodNotFound`
  (`-32601`)" (`JsonRpcBaseController.scala:55-63`) — "exactly the SR-03 gap." The rebuild preserves
  the distinction.
- **rpc: declarative Engine-API fork gating.** `july-fourth` registers every `engine_*VN` unconditionally and
  rejects mismatches "inline with a long, carefully-commented `versionError` match… in one very large
  method" (`EngineApiController.scala:42-85`). The rebuild gates registration by fork.
- **rpc: feeHistory percentile validation.** `july-fourth`: "`eth_feeHistory` reward-percentile input is not
  validated" (`EthBlocksService.scala:324-331`) — FEEHISTORY-PERCENTILE-VALIDATION-01. Reject
  malformed percentile arrays with `-32602`, reproducing geth's **three** distinct checks
  (`feehistory.go:249-261`): **(a)** count ≤ `maxQueryLimit` (array-length cap), **(b)** each
  percentile ∈ [0,100] (range), **(c)** strictly monotonically increasing order (`p[i] > p[i-1]`).
- **rpc: WS backpressure + IPC/ratelimit hardening.** `july-fourth` WS uses `Source.queue(256,
  dropHead)` — "silently discards… no error surfaced" (`JsonRpcWsServer.scala:85`); IPC is a raw
  `Thread`-per-connection with `unsafeRunSync()` — "a thread-exhaustion vector" with no size/count cap
  (`JsonRpcIpcServer.scala:44-51`); rate limiting is "HTTP-only and IP-keyed." The rebuild adds WS
  backpressure signalling, an IPC connection/size cap on reactive I/O, WS/IPC rate-limit parity, and a
  **JSON-RPC batch-size cap** (`july-fourth` has none — `JsonRpcHttpServer.scala:104-121` only rejects batches
  outright when rate-limiting is on).
- **rpc: keep the good `july-fourth` parts.** GraphQL/MCP reuse the service layer (the anti-besu-gotcha); the
  `ServiceResponse[T]` seam; and the Engine-API's dedicated `ActorSystem` + `IORuntime` isolation
  (`EngineApiHttpServer.scala`) — all retained.
- **agentic-interface: MCP from 7.2%-placeholder to first-class.** `july-fourth` `McpService` covers 7/97
  endpoints with empty `{}` schemas and placeholder data, over the JSON-RPC port only. The rebuild
  ships schema'd tools bound to real actor-state, stdio + SSE transports, read-only-default, and the
  R11 auth gate — under the built-but-unshipped guard (every tool wired + tested or it doesn't ship).

## 9. Risks & consensus-critical flags

- **NOT consensus — transport → conduit.** JSON-RPC/WS/IPC/GraphQL/gRPC are transport; route
  transport bugs to conduit. **Exception:** the Engine-API fork-version gating touches PoS consensus
  (which method version is valid at a given timestamp fork) → **beacon** co-review on the
  `ForkActivation` gating, even though the transport itself is not consensus. **ETC never exposes the
  Engine API** (inert/omittable on PoW).
- **Built-but-unshipped is the DOMINANT L9 risk.** The grpc-seam / DRPC gateway is a forward-looking
  product-family idea (`exec-extensions.md`: "a forward-looking product-family idea, NOT built"). The
  DoD bar is **GREEN and wired**, never "exists but dormant" (`README.md` risk register) — the
  precise old-fukuii failure mode. Do not scaffold the gRPC service, the RPCDaemon read seam, or the
  plugin-namespace SPI without a wired, tested default consumer.
- **circe / Caliban / gRPC dep-adds are sentinel-gated.** No other agent edits `build.sbt` /
  `project/Dependencies.scala`; route the Caliban 3.1.2 + `caliban-pekko-http` + `caliban-cats` and
  the fs2-grpc/ScalaPB adds to **sentinel** (evidence-based, operator-gated). The MCP OAuth 2.1 / SSE
  / A2A / ACP libraries route the same way.
- **The auth gate is STRUCTURAL, not additive — the one thing that must exist before any write-op.**
  A per-request `Principal` + `Capability` + audit-log seam, per-instance (R2), designed **now** and
  threaded through the dispatch registry — because MCP-2026 write-ops, Engine-API JWT, and the
  external-signer custody boundary all converge on it, and retrofitting it per-transport after ship is
  the exact "auth as an afterthought" failure. Read-only-by-default is the safe interim (MCP ships
  read-only until the gate is live).
- **MCP built-but-unshipped is a live instance of the DOMINANT risk, not hypothetical.** fukuii's
  current MCP is 7.2%-coverage placeholder-data scaffolding — precisely "exists but dormant." The DoD
  bar (GREEN and wired) means no schema'd tool ships without a tested consumer; do not expand the tool
  surface ahead of real actor-state wiring.
- **Per-instance (R2) at the serving boundary.** RPC routing, the MCP server, the auth `Principal`
  state, and the Engine-API endpoint are **per-`ChainInstance`**, never process-global — one binary
  hosting N networks must not share a metrics registry, a credential store, or an RPC route table
  across instances.
- **The WAL/prune-barrier crosses into storage (L2).** The `FinishedHeight` gate wires into fukuii's
  pruning path; the state-diff on-disk/wire contract must be **version-less-additive** (nethermind
  positional-RLP "absent = zero") for out-of-process readers, and must map or stay storage-agnostic
  over fukuii's RocksDB (watch erigon's `AccountChange.incarnation` and besu's Bonsai `TrieLog`
  storage-format assumptions — `exec-extensions.md`). Coordinate with vault on the prune-barrier seam.

## Feature-completeness doctrine

L9 is **default + multiple-additive**, not "one transport, take it or leave it." The baseline (circe
JSON-RPC / Caliban GraphQL / Engine-API) is the DEFAULT; MCP/A2A/ACP, the gRPC/dRPC seam, the RPCDaemon
read-seam, plugin namespaces, per-module concurrency, and the R8 RPC serving modes (archival vs relay)
are **role-gated additives whose seam is designed now** even where occupancy defers. The completeness
hunt applies: any genuinely-worth-having transport/role capability from a reference client (erigon
RPCDaemon + MCP, nethermind per-module pools + plugin SPI, besu plugin namespaces) is scheduled with a
seam, never silently dropped — but nothing ships as a dormant scaffold (§9).

## Layer boundaries

- **L9 owns:** the JSON-RPC/WS/IPC/GraphQL serving surface and its circe/Caliban codecs (`rpc`); the
  native MCP/A2A/ACP agentic transport (`agentic-interface`, a concern in `fukuii-rpc`) and the R11
  `Principal`/`Capability` auth gate + audit log threaded through the dispatch registry; the
  exec-extension notification framework + cross-process gRPC data plane (`grpc-seam`).
- **L9 does NOT own:** the Engine-API *driver*/fork-version *semantics* (consensus-pos, L5 — L5's driver
  speaks the typed verb-pair, `L5.md §6.7`; L9's HTTP/JWT transport translates JSON-RPC ↔ that verb-pair
  and calls **down** into it, never the reverse — no L5→L9 reuse of `rpc` wire types); the reorg-aware
  `ChainNotification` ADT (consensus-api, L5 — `grpc-seam` imports it, does not define it); the
  composition that binds transports to ports and isolates the Engine-API system (L10 `node`); consensus
  method *values* (core-geth authority); storage/pruning internals the prune-barrier gates (L2
  `storage`, vault).
- **Down-only edges:** `rpc → {chain, execution, consensus-api, sync, network, txpool, keystore}`,
  `grpc-seam → {rpc, consensus-api, execution}` (`consensus-api` for the imported `ChainNotification`
  ADT; `execution` for the `MutationReason`/state-diff types). Nothing above L9 is imported; nothing
  depends on `grpc-seam` except the L10 composition root.
- **The dRPC seam is a definition, not a split at L9:** the remote-KV read seam and embed-or-standalone
  boundaries are *defined* here (one narrow interface); L10 decides the in-proc-shim-vs-gRPC wiring
  per deployment (the product-family / DRPC-GATEWAY-01 lever).
