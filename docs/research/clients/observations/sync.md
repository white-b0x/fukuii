# Observations — sync
_Phase-2 synthesis 2026-07-13. Sources: 6 `{client}/sync.md` + `initial-assessment.md` §1e + `historical-distribution.md` cross-refs (besu checkpoint anchor / ERA1; erigon OtterSync segments; nethermind Init.Snapshot + Era1/EraE; reth ERA/static-file; geth/core-geth era1)._

Scope: how each reference client decomposes sync, where its authority lies, and what fukuii (single actor-based snap/v1 today) can borrow. **Verdicts are use-case-aware** — a mode that is OBSOLETE for one node role is DEFAULT for another. Node-role taxonomy: enterprise/full, custody, validator, light, archival, multi-network.

## Best-practice synthesis

**DEFAULT (what fukuii should run today):**
- **snap/v1 range-proof state download + trie-node heal**, wire semantics matched **byte-for-byte to go-ethereum** (`GetAccountRange`/`GetStorageRanges`/`GetByteCodes`/`GetTrieNodes`, first/last-account proof placement, DoS-bounded serving with size + lookup + per-request-time caps). This is fukuii's existing single snap/v1 path and the correct network-citizen default.
- **PoW-from-genesis peer-driven head selection retained** for ETC (master-peer + TD head + ancestor search), authority = **core-geth**. Plus **MESS/ECBP-1100 in the sync loop** for ETC subjective-reorg resistance.
- **Checkpoint anchor** for fast cold-start (fukuii's checkpoint-service), pattern = **besu** (data anchor consumed automatically, not a mode).

**OPTIONAL menu (the Phase-4 "multi-sync expansion" — via SEAMS, not more mode enums):** the lesson across besu/nethermind/erigon/reth is that "more sync approaches" is expressed as **orthogonal, auto-bound seams**, never a longer `SyncMode` enum (besu's enum actually *contracted* to `{FULL,SNAP}`). Expand fukuii's single snap/v1 by adding, independently:
1. **besu `PivotBlockSelector`-per-family** — one snap engine, swap target-selection by consensus family (peers / FCU safe-block / BFT). The cleanest seam for fukuii's PoW+PoS dual-family goal.
2. **nethermind parallel feeds + combinable mode selector** — map each data-type to a supervised actor + a selector actor publishing a mode-set, gaining "backward headers ∥ forward full ∥ state heal" concurrency (incl. FastBlocks parallel backward fill) and per-context peer allocation.
3. **erigon/reth staged resumability discipline** — persist a small durable per-phase checkpoint for cheap crash-resume; make **unwind a first-class ordered inverse pass** (erigon hand-tuned; reth plain-reverse + centralized error policy); bounded-batch backpressure ("not done, re-enter me").
4. **besu checkpoint anchor** as the fast-bootstrap seam (already aligned with fukuii's checkpoint-service).

**ETC-authority caveat (load-bearing):** the staged-pipeline and CL-driven-head clients (erigon, reth, go-ethereum HEAD) **dropped PoW-from-genesis by construction** — reth/geth cannot sync a PoW chain without a CL, and erigon's shape is not a PoW/ETC reference. **core-geth is the sole authority for ETC PoW-from-genesis + MESS.** Aligning fukuii's ETC sync toward geth-HEAD/reth would remove the only path a CL-less PoW node has to find and follow the heaviest chain — a regression, not a modernization. Snap *state* protocol (geth-authoritative) and PoW *head-selection* (core-geth-authoritative) are separate concerns: adopt geth on the wire, keep core-geth for the head.

## fukuii implications (forward-ref to Phase 3–4, do NOT act here)

Seeds, not verdicts — the multi-sync-approach expansion is a **Phase-4 theme**, and any consensus-adjacent sync change routes through forge (PoW) / beacon (PoS) first.

- **Today:** fukuii = single actor-based snap/v1 path (fast/regular/SNAP Pekko actors, per `blockchain/sync/AGENTS.md`) — message-passing, structurally closer to nethermind's feed model than to erigon/reth's serial stages. This is the right baseline; the snap/v1 wire path is a **capability to keep**, matched to geth.
- **Multi-sync expansion (Phase-4):** the target is **seams + feeds + staged resumability + checkpoint anchor**, not new mode enums. Concretely: (a) a `PivotBlockSelector`-style per-family target-selection seam (besu); (b) parallel supervised feed-actors + a mode-selector actor + per-context peer allocation (nethermind); (c) durable per-phase resumable checkpoints + first-class ordered unwind + bounded-batch backpressure (erigon/reth); (d) checkpoint-anchor fast-bootstrap (besu). Each is independently adoptable; none requires abandoning the actor model.
- **ETC authority is non-negotiable:** core-geth remains authoritative for ETC PoW-from-genesis (master-peer/TD head, ETChash/ECIP-1017 continuity) **and** MESS/ECBP-1100-in-sync. Do not let a staged/CL-driven reference erase the peer-driven head path.
- **Checkpoint-service alignment:** fukuii's checkpoint-service maps directly onto besu's **checkpoint-as-chain-spec-data anchor** (trusted `(number,hash,TD)` consumed automatically to skip download below a trusted block) — the cleanest existing convergence with a reference client; formalize the anchor as data, not a mode.
- **Storage coupling caveat:** besu's SNAP⇒Bonsai and erigon's staged⇒flat-state show sync mode and storage format are a **coupled pair**. fukuii's MPT-with-inline-roots means erigon's staged *Execution* and its no-heal model are **structurally inapplicable** — extract erigon/reth's *resumability discipline and unwind ordering*, not their pipeline. Cross-ref `storage-persistence.md` before any sync-storage co-change.
- **snap/2 (BAL):** not a fukuii need — experimental in geth, unwired in besu, and its network-wide BAL-retention assumption does not hold for ETC. Track, do not adopt.
