## 1. Scope & modules

One sbt module, `network`; package `com.chipprbots.fukuii.network.*`. DAG edge (down-only, per
`.local/docs/phase4/target-architecture.md`):

```
network → domain, crypto, rlp, common
```

The devp2p/RLPx networking tier — everything between a raw TCP socket and a decoded, chain-compatible
peer handing typed messages up to L7 sync / L8 txpool. Nine concerns:

- **RLPx transport** — ECIES auth handshake (pre-EIP-8 + EIP-8/v4 forms), AES-CTR + Keccak-MAC frame
  codec, Snappy compression policy, the per-connection owning behavior.
- **devp2p discovery** — discv4, discv5, ENR (EIP-778), DNS discovery (EIP-1459), the fork-ID pre-dial
  filter, the Kademlia routing table.
- **ETH wire protocol** — eth/68, eth/69, eth/70, eth/71 (+ the eth/72 landing slot), the per-version
  decoder set, the wire-version negotiation/multiplex layer.
- **ForkId** — EIP-2124 (block forks) + EIP-6122 (timestamp forks) CRC32 rolling checksum and the
  **4-rule fork-checksum ruleset** (3 accept-rules + reject-otherwise, per go-ethereum `core/forkid/forkid.go:155-222`).
- **Snappy** — the compress-outbound / expect-inbound framing policy and its post-Hello timing.
- **Peer management + admission/DoS policy** — admission gate, dial scheduling, reputation scoring,
  DialRatio/inbound-throttle, and — **new at L6** — the `Blacklist`/`BlacklistId` peer-state type
  *and its ban/blacklist policy* (relocated out of `blockchain.sync`, closing the old
  network↔blockchain cycle). L6 owns the type → **owns the policy** (R11).
- **Network-infrastructure serving** — bootnode *serving*, ENR/DNS-tree *authoring/publishing*,
  network-identity-as-data (F7/F8, R9) — the *write/serve* side of discovery, not just consume.
- **TCP server infra** — the listener bind, inbound-connection acceptance, external-IP detection.
- **Wire-version extensibility** — a generic range-advertising multiplexer separating *which versions
  exist / which are advertised / why*.

L6 is **not consensus** (`README.md` layer table: "no · formatting → herald"). But **reference-client
interop is the pass/fail bar** — a byte error here is a network partition, not a local bug.

**Authority discipline:** where go-ethereum and besu diverge on a byte value, that divergence is a
signal to **investigate**, not a free choice (`README.md` authority model). ForkId output is
**gated on forge/beacon golden hashes per network** before it is trusted (SR fukuii-implications:
"the CRC32 output must be validated against reference-client hashes per network — core-geth for ETC,
geth for ETH").

**Network-identity fact (carry it — `best-practices/evm-clients/p2p.md` §1):** ETC's `networkId = 1`
(**NOT 61** — 61 is `chainId`; ETC split from ETH before EIP-155 and kept networkId=1). networkId alone
cannot tell an ETC peer from an ETH peer — both are `networkId=1`; **forkId is the distinguishing
filter** (order: networkId → genesisHash → forkId). A bootnode/ENR-authoring path (§7 F8) that emits
`networkId=61` would silently fail to attract the right peers.

## 4. besu structural mirror

The concrete besu shapes L6 follows (read alongside geth's Go for the bytes):

- **`CapabilityMultiplexer`** (`p2p/.../rlpx/wire/CapabilityMultiplexer.java`) — the generic
  wire-version layer. besu computes cumulative offsets (`calculateAgreedCapabilities:118-145`) starting
  at `WIRE_PROTOCOL_MESSAGE_SPACE=16` (the p2p wire reserves codes 0–15), one disjoint `Range` per
  agreed subprotocol in an `ImmutableRangeMap`; the reserved range width is the per-version **wire
  code-span** (`EthProtocol.messageSpace` → 17/18/18/20), not the transport's business. This is the
  reference for replacing old-fukuii's hand-computed two-family offset translator (§6) — a generic
  **N-subprotocol** multiplex that keeps eth **and** snap simultaneously, not a single `best()`-collapse.
  `Capability.java` + `AbstractSnapMessageData.java` show the ETH+SNAP multiplex done generically. **`getMin/MaxEthCapability`** (§7) is the same class's
  config-bounded advertisement knob — a fleet caps the advertised window without a code change.
- **`RlpxAgent`** — the owning object for the connection set (maxPeers, dial admission, disconnect
  reasons). Maps onto the L6 `PeerManagerActor` single-owner behavior.
- **`PeerDenylistManager` + `PeerPermissionsDenylist`** — the direction-keyed ban policy (node-ID-keyed
  via `remotePeer.getId()`, in-memory/cleared-on-restart, maintained-peer-exempt). The full direction
  rule (`:31-36,68-71`): self-initiated `{BreachOfProtocol, INCOMPATIBLE_P2P_PROTOCOL_VERSION}` deny,
  peer-initiated `{INCOMPATIBLE_P2P_PROTOCOL_VERSION}` only — `INCOMPATIBLE` both directions, `Breach`
  self-only. LRU eviction is besu's `LimitedSet` `DROP_LEAST_RECENTLY_ACCESSED` mechanism with a
  **caller-supplied `maxSize`** (fukuii's cap, not a besu `500` literal). The structural reference for
  the L6 blacklist *policy* (§7), replacing fukuii's IP-keyed 365-day-`Permanent` outlier.
- **`rlpx/handshake/` + `rlpx/framing/`** — the ECIES-auth → frame → snappy → session pipeline as
  discrete stages. besu's per-connection channel pipeline (handshake→frame→snappy→session) is the
  structural template for the L6 RLPx **stream stages** (§5), not a Classic-actor bridge.
- **`p2p/discovery/{discv4,discv5,dns}/`** with `NodeRecordManager`/`DiscoveryPeer` — the discovery
  package split. Mirrors fukuii's "self-impl DNS + vendored discv4/v5" division (besu self-impls discv4,
  vendors discv5 from Teku). besu's ENR-authoring path is the reference for the F8 serve side.
- **`PeerReputation`** + rich named disconnect reasons — the reputation-scoring shape (corroborated by
  nethermind `NodeStatsLight`, reth `ReputationChangeWeights`). A **pre-disconnect** signal, orthogonal
  to the post-disconnect denylist.

## 5. Scala 3 idiom targets (Pekko Typed — from line one)

L6 is the first actor-heavy layer; the Classic→Typed invariants
(`.agents/protocols/code-style/pekko-typed-api.md` P1–P25 + `target-architecture.md` §"Classic→Typed
design invariants") are **baked in, not migrated later**. The actor boundaries come from the SR
CSP→channel-ownership mapping (`cross-cutting-themes.md` Theme 1), not a 1:1 port of Mantis's Classic
actor set (R5):

- **TCP = `pekko.stream.scaladsl.Tcp` (Streams-Tcp), never Classic `pekko.io.Tcp`** (MOD-13). The old
  `RLPxConnectionHandler`/`ServerActor` were stuck on Classic IO Tcp because no Typed equivalent existed;
  Streams-Tcp is current/non-deprecated in Pekko 1.6 and needs no new dependency. **RLPx framing is
  designed as stream stages** (ECIES-auth stage → frame stage → Snappy stage → message-codec stage),
  mirroring besu's channel pipeline — not a mechanical actor swap. This is flow/herald co-owned work.
- **Every actor a sealed `Command` ADT + explicit `replyTo`** — `Behavior[Command]`, never
  `Behavior[Any]`, never `sender()`. `PeerManagerActor`, `PeerDiscoveryManager`, `ServerActor`, and the
  per-connection owner all carry a closed command set. The old code's ~179 `Behavior[Any]`/`Any`-selector
  narrowing debt never comes into existence.
- **Channel-ownership granularity** (the SR DEFAULT): one owning Typed actor's private state = what one
  geth goroutine would exclusively own. `PeerManagerActor` owns the peer set (geth's serialized
  `Server.run()` loop — lock-free, two-phase admission re-validated inside the single owner, avoiding
  TOCTOU); one owning behavior owns each connection; the request-ID dispatcher maps onto `replyTo`/ask
  correlation. Do **not** 1:1-port Mantis's finer-grained Classic actors.
- **Constructor-injected `ActorRef[Command]`** passed at spawn (besu `ServiceManager` DI), never
  `actorSelection`/global lookup. **No global-static curve/config/registry** — per-instance state so R2
  multi-instance isolation holds (besu `SignatureAlgorithmFactory`'s process-global is the anti-pattern).
- **Cats-Effect `Resource` wrapped in Typed self-messages** — the vendored discovery service runs as a
  `Resource[IO, DiscoveryService]`, started/stopped via `.allocated`/`release` with completion routed
  back through `ctx.self ! StartAttempt(...)` — never calling into actor state from an IO callback
  (the reusable pattern from old-fukuii `PeerDiscoveryManager`, preserved). TL1/TL2 rules apply
  (`ctx.log` captured once on the actor thread, never from an IO callback).
- **Typed test kit only** — `ActorTestKit`/`BehaviorTestKit`, never Classic `TestActorRef`/`sender()`.
  Those probes existed in old-fukuii only because production was Classic Tcp; Streams-Tcp removes the
  reason. The geth **`transport`-interface `MsgPipe`** shape (§7) — whole stack over an in-memory pipe —
  maps onto a Streams-Tcp in-memory `Flow` so the RLPx/wire stack is exercised with zero sockets.
- **Wire-version registry as a Scala 3 `given`/enum seam** — capabilities as an `enum`, the multiplex
  offsets derived generically (besu RangeMap), so a third/fourth subprotocol registers additively. This
  is where the B7.0.5 `NetworkFamily` typeclass surfaces for the wire layer: **each family contributes
  its advertised set through the `given`, never an `isEtc()` branch** (R3). **Both families contribute the
  full {68,69,70,71} range** — PoW is not restricted to {68} (the difference between families is *TD
  sourcing*, not wire version: PoW derives chain-weight from local header `difficulty`, §5 TD-sourcing
  invariant; eth/68 is a compat fallback both keep). The multiplexer is family-blind. **The per-subprotocol `messageSpace` reserved
  in the RangeMap is the wire code-span** (eth/69=18, eth/70=18, eth/71=20 — including the reserved
  `0x0b–0x0e` gap), **not** the live-message count (13/14/14/16); offsets begin at besu's
  `WIRE_PROTOCOL_MESSAGE_SPACE=16`. Reserving the count instead of the span desyncs every downstream
  subprotocol offset — the same collision class as the hand-picked `0x30` smell.
- **TD-sourcing invariant — fork choice reads TD from LOCAL chain-weight, never the wire. This is how PoW
  supports eth/69+ (R1/R3, forge-cosigned). Closes `coherence-pass-03` L6-D1.** eth/69 **removed
  `TotalDifficulty` from `Status`** (go-ethereum `eth/protocols/eth/protocol.go:93-103`; RX-L6-21) — but
  `Status.td` was only ever a **handshake optimization**, never the wire's to own. TD/chain-weight is a
  consensus quantity: the cumulative sum of the permanent, consensus-critical header **`difficulty`** field
  (which no wire version can remove — it is required to *validate* a PoW block), computed and stored locally
  via the L7 `chain` facade. **fukuii therefore advertises the full eth/68–71(+) range for PoW networks
  exactly like PoS — eth/68 is NOT a PoW ceiling.** But eth/68 is also **NOT a mere fallback: the *entire
  current ETC network runs eth/68 via core-geth*, so eth/68 backward-compat is a HARD REQUIREMENT** for
  fukuii to join the live network at all and to carry it *through* Olympia. fukuii is therefore
  **dual-capable** — it negotiates eth/68 with today's core-geth peers and eth/69+ with fukuii peers
  (highest common per peer, family-blind multiplexer) — and it introduces eth/69+ precisely to move the
  network forward as core-geth (frozen on 68) sunsets. **Freezing PoW at 68 strands fukuii on a deprecating
  wire; dropping 68 strands it from the live core-geth network — both are required through the migration.**
  On eth/69+ a peer advertises its head
  (number/hash) but not its TD; the heaviest-chain election recovers the peer's weight by walking headers
  to the common ancestor and summing `difficulty` **from PoW-VALIDATED headers only** — because an
  advertised head (or, on eth/68, an advertised `Status.td`) is an **unverified claim on every wire
  version, and was never the security boundary.** A liar's attack ("headers claiming `difficulty=2^200`
  each → fake huge weight") is defeated at header validation: a header's `difficulty` counts **only if its
  Ethash seal actually hashes below that difficulty target** (+ the difficulty-adjustment formula from
  parent + parent-hash linkage — L5/forge consensus rules), so weight cannot be manufactured without doing
  the work. **Anti-spoof pipeline (before a peer's weight is trusted): download headers → per-header PoW
  seal + difficulty-formula + parent-link verify → backlink-verify the chain reverse-links to a common
  ancestor within a bounded depth → PoW-forged / parentHash-discontinuous ⇒ reject + blacklist outright
  (shared `Blacklist`, cross-mode)**; only then does the verified `difficulty` sum count, majority-voted
  across G1-gated voters. fukuii's `july-fourth` `fast/PivotBlockSelector` **ETH69 G1 chainWeight-gate + G5 20-block
  backlink-verify + PoW-forged-header blacklisting already do exactly this** (the `ETH69` prefix is
  deliberate — the `july-fourth` was built for a no-wire-TD world). The *network-steering* variant — a peer with a
  **genuinely-mined** heavier chain attempting a deep reorg — is rejected by **MESS/ECBP-1100** artificial
  finality (banksy-owned, forge-cosigned, wired into the sync loop via `BranchResolution`), not by weight
  comparison. **The vanilla wire is never modified:** TD is
  **not** re-added to eth/69+ (that would be a non-interoperable fork); it is derived from the `difficulty`
  every wire version already carries in the header. **The enforced invariant (correcting the earlier
  "cap PoW at 68" framing): the fork-choice + MESS/ECBP-1100 chain-weight comparison MUST source TD from
  local chain-weight and MUST NOT read `Status.td`** — which makes the wire version irrelevant to PoW fork
  choice and lets PoW ride eth/69/70/71 like everyone else. forge co-signs the chain-weight-sourcing path
  (consensus-adjacent). **DoD:** a PoW node negotiating **eth/69+ (no wire TD)** still elects the heaviest
  chain correctly via header-derived chain-weight; MESS/ECBP-1100 chain-weight checks work on eth/69+;
  **fukuii interoperates with the live core-geth eth/68 network AND fukuii eth/69+ peers simultaneously**
  (dual-capable, per-peer negotiation); no code path reads TD from a `Status` message for fork choice; **a
  peer advertising a fake heavy head backed by PoW-invalid headers (Ethash seal not meeting stated
  `difficulty`) is rejected and blacklisted, never synced to — no weight is counted from unvalidated
  headers**; a genuinely-mined deep-reorg chain is rejected by MESS/ECBP-1100. This anti-spoof pipeline is
  the same on eth/68 and eth/69+ — the wire TD field was never the security boundary.

## 6. Improvements over old fukuii (`july-fourth` gaps this layer closes)

From [`clients/fukuii/networking-p2p.md`](../../../../.local/docs/research/clients/fukuii/networking-p2p.md):

1. **Kill the Classic-Tcp boundary (MOD-13).** Old-fukuii's `RLPxConnectionHandler` is a Typed
   6-state behavior that delegates raw I/O to a Classic `OutboundTcpBridge`/`InboundTcpBridge` child
   (`RLPxConnectionHandler.scala:185-240`) and `ServerActor` uses a Classic `TcpEventBridge` to capture
   `sender()` for `Tcp.Connected` (`ServerActor.scala:198-203`). L6 has **no Classic bridge** — RLPx is
   Streams-Tcp stages; there is no `sender()` to capture.
2. **Move `Blacklist` into `network` (break the network↔blockchain cycle) and schedule its policy.**
   Old-fukuii's `ServerActor`, `PeerManagerActor`, and `Peer` (via `PeerId extends BlacklistId`) all
   import `com.chipprbots.ethereum.blockchain.sync.Blacklist` — an upstream package consuming a
   downstream type (`dependency-graph.md:51` back-edge). L6 **owns** `Blacklist`/`BlacklistId`; L7 sync
   depends *down* on it. Owning the type means owning the *policy* (§7) — the SR blacklist survey's
   central finding is that fukuii's 365-day `Permanent` tier is a ~2-orders-of-magnitude outlier that L6
   must ratify or re-scope, not silently inherit.
3. **Replace `best()`-collapse + SNAP-bolt-on with a generic multiplexer** (the §1f gap). Old-fukuii
   collapses negotiation to a single `Option[Capability]` via `Capability.best()`
   (`Capability.scala:85-104`), then recovers SNAP as a side-channel whose wire offset depends on the
   negotiated ETH version, translated by a hand-computed `InboundTranslator` special-cased to exactly two
   families (`RLPxConnectionHandler.scala:346-397`), with a **hardcoded `0x30` SNAP offset that already
   needed one manual widening** to avoid colliding with eth/69 `BlockRangeUpdate` (`SNAP.scala:21-29`).
   L6 uses a generic `List[SubProtocol]`→disjoint-RangeMap multiplexer (besu shape) — offsets computed,
   not hand-picked; a future version needing >15 codes cannot re-trigger the same collision class. **The
   improvement is "N-subprotocol computed multiplex," not "eliminate best-per-protocol selection":** besu
   *also* picks best-version-per-subprotocol (`CAPABILITY_COMPARATOR`, name-asc then version-desc), but
   keeps **all** subprotocols (eth **and** snap) simultaneously, each with its own computed disjoint range
   — whereas old-fukuii collapses to one capability total via `best()` then bolts snap back with the
   hand-picked `0x30` offset.
4. **Wire ETH70 at the handshake layer.** Old-fukuii is **decoder-complete but not handshake-wired** for
   ETH70: `ETH70MessageDecoder`, `Status70`, and the `InstanceConfig` `p.eth70` flag exist, so two
   ETH70 peers negotiate `Capability.ETH70` — but `HelloExchangeState` (`:72-108`) has only ETH68/ETH69
   arms, so a negotiated ETH70 falls through to `IncompatibleP2pProtocolVersion` and disconnects. L6
   builds the `EthNodeStatus70ExchangeState` arm so ETH70 reaches Connected. **eth/70 reuses eth/69's
   message list** (`protocolLengths[ETH70]=18`, same as eth/69 — the change is partial-block-receipt
   *serving semantics* via `lastBlockIncomplete`/`RequestPartialReceipts`, **not** new message codes),
   so the handshake arm + receipt-buffer semantics, not a new decoder set, are what's missing.
5. **Add eth/71 and fix the ETH70 EIP attribution.** geth HEAD advertises 69/70/71; old-fukuii lacks
   eth/71 (**EIP-8159 Block Access Lists** — `GetBlockAccessListsMsg=0x12`/`BlockAccessListsMsg=0x13`,
   raising the code count to 20; **partial serving-only at geth HEAD** per `a484a8506` — treat as
   in-progress, land the message pair + serve side, gate the requester). And `ETHPackets.scala:279`'s
   own docstring mislabels eth/70 as **"EIP-7706"** while geth (`965bd6b6a`) attributes eth/70 to
   **EIP-7975** (partial block receipt lists). L6 lands eth/71 in the multiplex layer and uses the
   correct EIP attribution (WIRE-ETH71-PARITY finding, §7). reth's codec already carries **eth/72
   (EIP-8070)** — the leading edge, advertised nowhere by default → fukuii's forward landing slot.
6. **Config-surface the "enterprise mode" switch.** Old-fukuii's static-nodes-only mode is a JVM system
   property (`fukuii.network.discovery.use-bootstrap-nodes` via `System.getProperty`,
   `DiscoveryConfig.scala:52-54`), invisible in `application.conf`. L6 makes it a HOCON key (R2 — two
   instances can't select modes via a process-global sysprop).

**Preserved as correct** (port, don't rewrite): the config-driven ForkId derivation with the
Olympia-sentinel exception (`ForkId.gatherBlockForks`), the decompress-first/heuristic-fallback Snappy
policy, the reject-before-decoder DNS/ENR fork-ID filter (`EnrForkIdFilter` — cites the real BSC/Core-Chain
dial-slot-burning incident), the non-exception `AuthHandshakeResult` return path (NETWORK-02), the
CVE-2026-26313 frame-body-size bound (`FrameCodec.scala:130-136`), and the `PeerScore` weighted
composite reputation (handshake/response/latency/compliance/recency). The `snapCapableHosts` scarcity
exemption is preserved but re-evaluated on its own merits (§7) — it exists because the `Permanent` tier
+ tiny ETC snap-server population interact; a re-scoped ban policy may reduce the need for it.

## 9. Risks & consensus-critical flags

- **PoW TD-sourcing (consensus-adjacent) — see the §5 TD-sourcing invariant.** eth/69+ removes
  `TotalDifficulty` from `Status`; fork choice + MESS/ECBP-1100 MUST source TD from local, PoW-validated
  chain-weight (the L2 `chain-weight` CF), never `Status.td`, so PoW rides eth/69+ while staying eth/68
  backward-compatible with the live core-geth network. The anti-spoof pipeline (weight counts only from
  headers whose Ethash seal validates; PoW-forged → reject+blacklist) is the security boundary, not the
  wire field. forge/banksy co-sign the seal-validation + MESS ends (implemented at L5/L7). Flagged here for
  discoverability; the full statement is §5.
- **Not consensus, but interop is pass/fail.** L6 changes no state root; formatting/wire routes to
  **herald**, not forge/beacon. But a ForkId byte error is a **network partition** and a wrong-network
  Status handshake burns peers — so ForkId output is **gated on forge (ETC golden hashes) / beacon (ETH
  timestamp forks)** before trust, and eth-message encodings are held byte-exact to go-ethereum. Treat
  wire byte-exactness with consensus-grade discipline even though the litmus (state-root change) says
  non-consensus.
- **Stream-materialization / backpressure traps → flow.** Re-architecting RLPx framing as Streams-Tcp
  stages introduces the exact class `flow` owns: a `Future` that never completes, silently-dropped
  frames, `preMaterialize` misuse, backpressure stalls. Every stage graph gets flow review + the
  `pekko-resource-audit` skill (uncancelled timers, missing `watchWith`, materialization leaks).
- **The hand-picked SNAP-offset trap is a design smell to eliminate, not reproduce.** The generic
  multiplexer must compute offsets; do not carry the `0x30` constant forward. If the RangeMap is
  short-cut back to a fixed offset, the eth/69 `BlockRangeUpdate` collision class returns. The
  per-subprotocol range must reserve the wire **code-span**, not the live-message count (§5) — reserving
  the count desyncs downstream offsets, the same collision class.
- **eth/68 retention is deliberate — do not "modernize" it away.** Dropping eth/68 to match geth HEAD
  would reduce peer compatibility; the SR is explicit this is a geth-internal cleanup, not a wire signal.
- **The blacklist policy is R11-security, not cosmetic.** A too-lenient ban policy invites peer-DoS; a
  too-harsh one (the 365-day outlier) partitions a low-population network like ETC/Mordor from its few
  snap servers. Neither reference-client extreme (geth's flat 35s / reth's 12h) transfers unchanged —
  the ETC network condition is genuinely different, so ratify against besu/reth precedent **and** the
  ETC/Mordor snap-server scarcity, with a recorded decision (herald + the peer-disconnect-blacklist
  coding standard).
- **Discovery correctness lives in the vendored `scalanet` module, not `network/discovery/`.** Any
  wire-level discv4/v5/ENR bug is a scalanet bug; the L6 discovery package is a lifecycle/glue wrapper.
  Check go-ethereum `p2p/discover` for the protocol truth, not the wrapper. The F8 *authoring* side is
  new fukuii code and must be validated against besu's ENR-authoring + core-geth's ETC DNS-tree config.
- **The `NetworkFamily` wire seam must inject through the typeclass, never a shared reader.** A family's
  advertised capability set is contributed *through* the `given`, not gated by `isEtc()`/`isPoS()` inside
  the multiplexer (the erigon `FrozenBorBlocks` leak is the cautionary counter-example) — R3.
- **networkId=1-not-61 is a silent-failure trap for the F8 serve side.** An authored ENR/bootnode config
  emitting `networkId=61` (the chainId) attracts the wrong peers; carry the core-geth fact.
- **The `IORuntime` is injected from composition, never a per-builder `lazy val` (R2-F4).** The old
  `ioRuntime` diamond formed because `PeerDiscoveryManagerBuilder` and `PortForwardingBuilder` — **both
  L6 components** — each declared the same `lazy val IORuntime` (`NodeBuilder.scala:1172`). L6's builders
  take the runtime as a constructor/`using` parameter from L10's composition; a per-builder
  `lazy val IORuntime` in `network` is an R2 isolation break that re-forms the diamond. L10 retires the
  existing diamond (`L10.md §2`); L6 states the constraint here so it cannot re-form where the components
  actually live (R2's matrix marks L6 `—`, but this prevention rule belongs at L6, per R5's effect
  discipline).

### Layer boundaries

- **Owns:** the RLPx transport, wire protocol, ForkId, discovery glue, peer management, the blacklist/ban
  **policy**, the network-infrastructure serve side (bootnode/ENR/DNS authoring, F7/F8), and the
  `Blacklist`/`BlacklistId` peer-state type. Everything from raw socket to typed, chain-compatible peer.
- **Depends down on:** `domain` (Peer/PeerId, block/header/tx types on the wire), `crypto` (ECIES, ENR
  signing, secp256k1), `rlp` (message codecs), `common` (config/logging leaf).
- **Does not own:** how peers are *used* to sync (L7 `sync` depends down on `network`), transaction
  admission (L8 `txpool`), JSON-RPC transport (L9 `rpc`/conduit), or the vendored discv4/v5/ENR protocol
  bodies (sibling `scalanet` module). The Sentry P2P-as-service lift (L6→a narrow gRPC/message seam) is
  an OPTIONAL(product-family) future, not part of the L6 boundary.
- **Upward edges are compile errors** — nothing in `network` may import `sync`, `txpool`, `rpc`, or
  `node`. This is the structural fix for the old network↔blockchain cycle.
