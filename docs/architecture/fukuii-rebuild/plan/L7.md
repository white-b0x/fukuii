## 1. Scope & modules

**Two sbt modules in the L7 band** — `chain` (the block/blockchain store facade) and `sync` (the
acquisition tier); packages `com.chipprbots.fukuii.{chain,sync}.*`. DAG edges (down-only, per
`.local/docs/phase4/target-architecture.md`):

```
chain → storage, trie, domain
sync  → chain, network, consensus-api, execution, storage, trie
```

| Module | sbt id | Delivers |
|---|---|---|
| **chain** | `fukuii-chain` | The `Blockchain` / `BlockchainReader` **facade traits** over storage — block/header/body/receipt/total-difficulty read+write (relocated out of the old `domain` god-object, `L1.md §Layer-boundaries` "SCC-breaking move #1"). A store facade only: no sync/execution/consensus logic. Consumed by `sync` (this band) and `rpc` (L9); **not** by L2–L5 (execution/consensus reach state through `storage`/`trie`/`WorldStateProxy` directly, so the facade sits *above* them, at the L7 band). **besu couples block-added/reorg observers (`Blockchain.observeBlockAdded`/`observeChainReorg`) onto `Blockchain` itself; fukuii deliberately does not** — reorg-event authority + the `ChainNotification` ADT are L5's (L9's resume-cursor reorg stream comes from L5's `grpc-seam`, never from `chain`), so the `chain` facade stays a pure store with no observer registration. |
| **sync** | `fukuii-sync` | The acquisition tier below. |

Placing `chain` at the L7 band (not lower) is exactly why the old `domain ↔ Blockchain*` SCC dissolves:
the facade's only consumers are `sync` and `rpc`, both at/above L7, so a downward-only edge suffices and
no lower layer imports it (`L1.md:206/376`). `sync` depends on `chain` to persist/read blocks.

The `sync` module is the block/state acquisition tier: discover the heaviest chain (or take the CL's
head), download state fast, download the chain, heal, and hand a synced head to steady-state import.
Five strategies + shared plumbing:

- **SNAP sync** — snap/v1 range-proof state download (account/bytecode/storage ranges) + trie-node heal;
  the default/entry path. **SNAP serving** (F9) is a role-gated capability on the same wire.
- **Chain backfill** — headers/bodies/receipts forward from genesis, concurrent with SNAP state.
- **Regular sync** — steady-state fetch→validate→import→broadcast once caught up.
- **Fast sync** — legacy `GetNodeData` trie-node-by-hash download; retained only as an ETH68-only-network
  fallback + escape hatch.
- **Checkpoint sync** — bootstrap a fresh datadir from a trusted anchor.
- **Shared peer plumbing** — peer selection, rate tracking, pivot-header fetch, MESS branch-resolution
  hook (`Blacklist` now depends *down* into L6 `network`).

L7 is **not consensus** (`README.md` layer table: "no"). But it *invokes* consensus rules (MESS/ECBP-1100
node-local fork-choice, ETC PoW head selection) — those specific hooks are banksy-owned/forge-co-signed.

**Load-bearing ETC caveat** (SR best-practice synthesis): "the staged-pipeline and CL-driven-head clients
(erigon, reth, go-ethereum HEAD) **dropped PoW-from-genesis by construction**… **core-geth is the sole
authority for ETC PoW-from-genesis + MESS.** Aligning fukuii's ETC sync toward geth-HEAD/reth would remove
the only path a CL-less PoW node has to find and follow the heaviest chain — a regression, not a
modernization." Snap *state* (geth-authoritative wire) and PoW *head-selection* (core-geth-authoritative)
are **separate concerns**: adopt geth on the wire, keep core-geth for the head.

### R8 role → sync-mode table (the explicit mapping, R8)

Sync is not one path — the mode is **selected per node role × network** (`requirements.md` R8). Each cell
composes from the seams below (per-family pivot selector × SNAP-serve gate × backfill depth × checkpoint):

| Node role | Sync mode | Serves SNAP? | History backfill |
|---|---|---|---|
| **Archival** (deep data for dApps) | **FULL** (or SNAP→FULL) + full history backfill | **yes** (default-on) | full, from genesis |
| **Tip / server** (tip-of-branch data server) | SNAP → regular; stays at tip | **yes** (default-on) | to pivot only |
| **Mining pool** (fukuii's #1 GTM, PoW) | SNAP → regular; stays at tip + **SNAP serving** for pool nodes | **yes** (default-on) | to pivot only |
| **RPC relay** (pruned public relay) | SNAP + checkpoint-pivot fast-bootstrap | optional | bounded |
| **Light / resource-light** | checkpoint-pivot; minimal state | no | none below anchor |
| **Bootnode** (F7/F8 infra — beyond the six R8 roles) | checkpoint-pivot + **SNAP serving** for joiners | **yes** (default-on) | as configured |
| **Validator** (PoS) | SNAP → regular; CL-driven by-hash pivot | optional | to pivot |

Every one of the six canonical R8 roles (archival · tip-server · **mining-pool** · pruned-relay ·
resource-light · validator — `requirements.md` R8, `L2.md` doctrine, matching L2's `MiningPool`
`StorageProfile`) is mapped; **bootnode** is an intentional *addition* for the F7/F8 serving-infra role,
not a substitution for a canonical role. The role selects the composition; the composition is built from
orthogonal seams, **not a longer `SyncMode` enum** (besu's enum actually *contracted* to `{FULL,SNAP}` —
"more sync approaches" is expressed as auto-bound seams).

## 4. besu structural mirror

The concrete besu shapes L7 follows (read alongside geth's Go for the snap bytes):

- **`PivotBlockSelector` + `DynamicPivotBlockSelector`** (`eth/.../sync/PivotBlockSelector.java`,
  `.../snapsync/DynamicPivotBlockSelector.java`) — the injected per-family seam. besu binds the selector
  once at controller build (`PivotSelectorFromPeers` for PoW, `PivotSelectorFromSafeBlock` for PoS/FCU).
  This is the target shape replacing old-fukuii's source-tag (§6). **For the frozen-ETC PoW-from-genesis
  arm specifically, the JVM cross-check is besu-etc's OWN `PivotBlockSelector`** (peer-driven, `FastSyncState`,
  no TTD) — vanilla besu removed ETC, so its `PivotSelectorFromPeers` serves only as the generic peer-pivot
  structural mirror. **`PivotSelectorFromSafeBlock` carries a
  dual-purpose CL-liveness guard** (`PivotSelectorFromSafeBlock.java:167-200`): (a) **fail-loud** when
  `effectiveThreshold = pivotBlockWindowValidity − millisSinceLastFcu/slotDuration <= 0` → "consensus client
  appears offline" (the shrink is **per-slot**, estimated missed slots since the last FCU), *and*
  (b) **pivot-reuse / anti-churn** — reuse the existing or cached-safe pivot while `head − pivot <
  effectiveThreshold` rather than re-pivoting on every head advance. Not just the offline-abort; the
  reference for the embedded-CL arm (R9/F9).
- **`DefaultSynchronizer`** (`eth/.../sync/DefaultSynchronizer.java`) — composes an initial-snap
  downloader + a permanent full-sync downloader. The clean composition L7's `SyncController` should
  express as supervised behaviors, not one 5,488-line file.
- **`SnapSyncDownloader` / `SnapWorldDownloadState` / `RequestDataStep` / `PersistDataStep`**
  (`snapsync/`) — the SNAP download-state + request/persist pipeline; the structural template for the L7
  SNAP feed actors (account/bytecode/storage/heal coordinators).
- **`SnapSyncChainDownloader` / `ChainDownloader`** — the chain-download-overlapping-state pattern
  (old-fukuii's `ChainDownloader` already cites "the Geth/Nethermind pattern"); keep it forward-from-genesis.
- **Checkpoint anchor** — besu's genesis-embedded `Checkpoint (number,hash,TD)` seeding `SyncState`,
  consumed automatically under SNAP. The reference for formalizing fukuii's checkpoint as data, not a mode.
- **SNAP serving caps** — besu bounds a serve response by **size + wall-clock** (geth uses `softResponseLimit`
  + `maxTrieNodeTimeSpent`); the reference for the DoS-bounded SNAP-serve role capability (§7, F9).

## 5. Scala 3 idiom targets (Pekko Typed — from line one)

L7 continues the L6 Typed invariants (`.agents/protocols/code-style/pekko-typed-api.md`); the actor
boundaries come from the SR nethermind-feed → channel-ownership mapping (`cross-cutting-themes.md`
Theme 1 — the actor-decomposition target), **decomposing the two monoliths structurally from the start**,
not a 1:1 port (R5/R6):

- **`SyncController` as a sealed `Command` ADT + named `Behavior` states**, never `Behavior[Any]`,
  never `context.become`. The runtime strategy transitions (`FallbackToSnapSync`, `RegularSyncStuck`,
  `SnapSyncFinalized`) stay message-driven events — but split across **supervised child feed behaviors**,
  not one monolith (§6.1).
- **Channel-ownership granularity — a supervised actor per feed** (account-range / bytecode / storage /
  trie-heal / chain-backfill), each owning exactly the state one geth goroutine would, plus a **selector
  actor publishing a mode-set** (the nethermind `MultiSyncModeSelector` shape). This is the
  OPTIONAL(enterprise/full) Phase-4 shape already *partially present* in the concurrent SNAP
  coordinators. **Per-context peer allocation** (nethermind `AllocationContexts`) partitions the shared
  pool so Snap and FastHeaders feeds don't starve each other. nethermind's `[Flags]` partition already
  reserves a distinct **`BlockAccessLists`** context (`AllocationContexts.cs:9-20`) — so when the snap/2
  versioned `Syncer` lands (§6.7), fukuii's partition should carry a BAL context so a v2 BAL feed doesn't
  starve v1 state feeds.
- **The pivot selector as an injected seam, `given`-bound per family** — besu's `PivotBlockSelector`
  becomes a `NetworkFamily`-typeclass-provided target selector (peers for PoW / FCU-safe-block for PoS),
  bound once at construction. **Inject through the typeclass, never `if (isPoSChain)` scattered through
  the loop** — old-fukuii's `CLPivotHint`/`isPoSChain` gate is a single boolean computed once
  (a good pattern to preserve), but the rebuild upgrades it to a proper injected selector.
- **Constructor-injected `ActorRef[Command]`** for every collaborator (peer client, storage, execution,
  consensus-api), never global lookup.
- **STOP-AND-ALERT death-watch** (`.agents/protocols/.../alert-wrapper-protocol.md`) — the
  `SnapSyncCriticalFailure` marker (crash while actively syncing = do not restart, in-flight session
  state is unsafe to resume) swapped to the benign `SnapSyncTerminated` at the finalize→backfill
  boundary. Preserve this narrow-window pattern.
- **Streams for chain download** — headers/bodies/receipts fetch as backpressured stream stages
  (flow-reviewed), consistent with the L6 Streams-Tcp direction; bounded-batch "not done, re-enter me"
  backpressure (the erigon `ErrLoopExhausted` / reth `ExecOutput{done:false}` discipline).
- **Typed test kit only** — `ActorTestKit`/`BehaviorTestKit` + stream test synchronization
  (`syncProbe`/`take(N)+Sink.seq`) for the feed graphs.

## 6. Improvements over old fukuii (AS-IS gaps this layer closes)

From [`clients/fukuii/sync.md`](../../../../.local/docs/research/clients/sync.md):

1. **Split the 5,488-line `SNAPSyncController` (and 2,487-line `SyncController`).** Old-fukuii's
   `SNAPSyncController.scala` mixes phase orchestration, six retry/backoff subsystems, and inline
   incident documentation in one file (the largest in the subsystem). L7 decomposes into supervised feed
   actors (besu `SnapSyncDownloader` + nethermind `SyncFeed` shape) with a thin `SyncController` selector
   — the parallel-feed decomposition the SR names as the Phase-4 target, expressed structurally from the
   start rather than by accretion of point-fixes (61 commits / 90 days).
2. **Pivot selection: source-tag → injected seam.** Old-fukuii records *which* mechanism produced the
   pivot (`PivotSelectionSource`: `NetworkPivot`/`LocalPivot`/`CLDrivenPivot`,
   `SNAPSyncController.scala:4928-4941`) with a buffered `clPivotHint`. L7 makes it besu's **injected
   `PivotBlockSelector` seam bound per family** — the SR's "single most directly portable abstraction,"
   which old-fukuii approximates with a tag rather than an interface. The PoS arm gains besu's
   **CL-liveness guard** (fail loud when the CL appears offline) for the embedded-CL future (R9).
3. **Checkpoint: standalone archive → data anchor consumed by SNAP; interoperable ERA1 for archival.**
   Old-fukuii's `CheckpointArchive` (magic `0xC4C4C4C4`, CRC32) is a full-state-import container that
   **bypasses SNAP entirely** (`CheckpointImporter` marks all sync-done flags and SNAP never spawns) —
   effectively a 5th mode, and **bespoke / non-interoperable** with the ecosystem. The SR's guidance
   ("formalize the anchor as data, not a mode") is **not yet followed**. L7 reshapes the checkpoint into
   a besu-style trusted `(number,hash,TD)` anchor that **seeds** SNAP rather than replacing it — and if
   the archival full-import path is retained, it uses **ERA1** (geth/besu/nethermind/reth all consume it),
   not the bespoke container (§6.7).
4. **`Blacklist` now depends down into L6 `network`.** Old-fukuii declares `Blacklist` inside
   `blockchain/sync/` and lets `network` import it upward (`dependency-graph.md:50-51` back-edge). In the
   rebuild, **L6 owns `Blacklist`** (and its policy); L7 sync depends *down* on it — the cross-mode
   penalty-propagation shared cache (SNAP-blacklisted peer stays blacklisted into fast/regular) is
   preserved, just relocated.
5. **Uniform resumability + first-class unwind (state the unwind-order design choice).** Old-fukuii's
   resumability is ad hoc per strategy (`SnapSyncProgressStorage` + preserved account-range cursors +
   coarse `AppStateStorage` done-flags; "no uniform per-stage progress/unwind abstraction"). L7 adopts
   the erigon/reth discipline: a durable per-phase checkpoint integer + a first-class ordered unwind pass
   + bounded-batch backpressure — the *portable pieces*, not the staged pipeline. **The unwind-order
   design choice, stated explicitly:** reth uses **plain-reverse unwind + a centralized `on_stage_error`
   policy**; erigon uses a **hand-tuned `DefaultUnwindOrder`**. fukuii's **MPT-with-inline-roots means
   unwinds don't have erigon's cross-stage flat-state ordering hazards** — so **plain-reverse (reth) is
   the default choice** unless a specific cross-feed dependency forces a hand-tuned order; the decision is
   recorded, not left implicit.
6. **Config-surface the recovery levers.** Old-fukuii's manual-recovery escape hatches are JVM system
   properties (`-Dfukuii.reset-fast-sync-done`, `-Dfukuii.snap.clearDoneOnStart`,
   `-Dfukuii.seed-chain-weights`, read via `System.getProperty` inside `SyncController.start()`),
   invisible in HOCON. L7 makes them part of the config surface.
7. **SNAP serving as a first-class role capability + a versioned `Syncer`.** Old-fukuii covers serving
   *caps* in the DoD but not SNAP serving as a **role feature** (default-off → on for
   server/archival/bootnode). L7 makes it R8/R9-role-gated, DoS-bounded (geth `softResponseLimit` +
   `maxTrieNodeTimeSpent`; besu size+wall-clock). And it introduces a **versioned `Syncer` seam** (geth's

## 9. Risks & consensus-critical flags

- **Not consensus, but MESS + PoW head are consensus-adjacent.** L7 changes no state root — but the
  **MESS/ECBP-1100 branch-resolution hook is banksy-owned/forge-cosigned** (node-local fork-choice
  preference, never a state-root rule), and the **PoW-from-genesis head election** is a core-geth-authority
  path forge cross-checks. Route those two hooks through the consensus-change protocol; the rest of L7 is
  ordinary layer work.
- **PoW-from-genesis regression is the standing trap.** The staged/CL-driven reference clients (erigon,
  reth, geth HEAD) *deleted* PoW-from-genesis by construction. Extracting their *resumability discipline*
  is correct; extracting their *head-selection model* would erase the only path a CL-less PoW node has to
  the heaviest chain. **Keep snap-state (geth wire) and PoW-head (core-geth) as separate concerns** — a
  reviewer who "modernizes" the head path toward geth-HEAD has introduced a regression.
- **Storage coupling caveat — do NOT adopt the staged *Execution* pipeline.** besu's SNAP⇒Bonsai and
  erigon's staged⇒flat-state show sync mode and storage format are a coupled pair. fukuii stores an
  **MPT with inline roots**, so erigon's staged Execution and its no-heal model are *structurally
  inapplicable* — the single-phase trie-only heal (flat slots inline) is correct here. Extract erigon/
  reth's *resumability + unwind ordering*, not their pipeline. This is also why **plain-reverse unwind
  (reth) is the default** — fukuii lacks erigon's cross-stage flat-state ordering hazards that force a
  hand-tuned `DefaultUnwindOrder`. Cross-ref `storage-persistence.md` before any sync↔storage co-change.
- **Stream-materialization / backpressure traps → flow.** The chain-download and feed graphs are exactly
  `flow`'s domain (a `Future` that never completes, silently-dropped elements, backpressure stalls). Every
  stream graph gets flow review + `pekko-resource-audit` (uncancelled timers, missing `watchWith`,
  materialization leaks) — the risk grows when the monolith is split into supervised feed actors.
- **The SNAP↔Fast bounce forces sync-done flags true even when state is incomplete** — a deliberate
  liveness-over-completeness trade in old-fukuii (`checkSnapFastEscapeHatch`). Preserve the *bounded-exit*
  intent, but the rebuild's on-demand `StateNodeFetcher` (`GetTrieNodes`) backstop must be provably wired
  so deferred state-completeness risk is actually covered, not silently dropped.
- **Pivot-freeze is tuned by constants against observed incidents.** The 128-block roll window, roll
  margin, and heal-hold-on-stagnation are empirical (dated production stalls, e.g. "ETC stalled 70+ min
  at 16.8M accounts"), not first-principles — a peer-population change (a shorter/longer core-geth serve
  window) would require re-discovering the constant. Keep them as named, documented tuning knobs, not
  buried magic numbers.
- **CL-liveness guard is a fail-loud requirement for the embedded-CL arm (R9).** The PoS pivot must not
  silently stall when the CL goes away — besu's shrinking `effectiveThreshold` → "consensus client appears
  offline" is the model; a silent stall here looks like a sync bug and hides an ops failure.
- **`core-geth is NOT SNAP-authoritative.** Its snap is inherited verbatim from geth — cite go-ethereum
  for every snap wire question; core-geth is authoritative only for the PoW head path + MESS.

### Layer boundaries

- **Owns:** the `chain` module — the `Blockchain` / `BlockchainReader` facade over storage (block/
  header/body/receipt/TD read+write), relocated out of the old `domain` god-object; and the `sync`
  module — the sync strategies (SNAP / chain-backfill / regular / fast / checkpoint), SNAP **serving**
  (role-gated), the per-family pivot-selection seam, the versioned `Syncer` seam, the shared
  peer-selection/rate-tracking plumbing (incl. per-context allocation), and the MESS branch-resolution
  hook wiring (the policy is banksy-owned; L7 wires it into the loop).
- **Depends down on:** `network` (peers, wire messages, the relocated `Blacklist` + its policy),
  `consensus-api` (fork dispatch, validation, `ProtocolSpec`), `execution` (block import/validate via the
  consensus adapter), `storage` (state/progress persistence), `trie` (MPT heal).
- **Does not own:** the wire protocol itself (L6 `network`), block execution / state transition (L4
  `execution` — L7 calls down into it), consensus rules (L5 — L7 references the engine, forge/beacon own
  the semantics), or the RocksDB storage layer (L2 — vault). The Engine-API driver that pushes the PoS
  head lives with `consensus-pos`; L7 consumes the head as a by-hash pivot.
- **Upward edges are compile errors** — nothing in `sync` may import `txpool`, `rpc`, or `node`, and the
  old `db/storage → blockchain.sync` back-edge (`FastSyncStateStorage`/`StateStorage` reaching up into
  sync) cannot re-form: storage is strictly downward.
