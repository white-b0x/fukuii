# L1 — domain: `domain`

_Forward-looking layer plan, written **before** the build (per [`plan/README.md`](README.md)'s
inverted order: plan → build → gate → record). Governed by the Systemic Review
[`observations/accounts-signer.md`](../../../research/clients/observations/accounts-signer.md) (tx
signing slice) and [`observations/primitives.md`](../../../research/clients/observations/primitives.md)
(value-type + RLP-codec rows); old-fukuii AS-IS in
[`.local/docs/research/clients/fukuii/accounts-signer.md`] and `.../primitives.md`. Byte layout matched
against go-ethereum `core/types/`, besu `datatypes/` + `ethereum/core/`, and core-geth for ETC tx/fork
specifics. Cross-layer optimization dispositions live in [`optimizations.md`](optimizations.md) §L1; the
downward constraints this layer must carry are [`requirements.md`](requirements.md) R1/R4/R6/R11. This is
the plan the gate will **confirm**, not discover._

**Feature-completeness doctrine (`REVIEW.md`).** fukuii targets best-practice DEFAULTs **and** the most
feature-complete client. At L1 that means: model **every** tx/header/receipt variant the ecosystem defines
(DEFAULT shape), **seam-shape** the signing operation so the OPTIONAL(role) custody backends drop in at L8
without touching consensus code, and **name-and-avoid** the OBSOLETE shapes (compile-time family
monomorphization; permanent in-node unlock) so they are never reintroduced. An optimization the SR
documented that this layer neither adopts nor consciously defers is a gap.

## 1. Scope & modules

- **sbt module:** `fukuii-domain` (dir `modules/domain`). **Package:** `com.chipprbots.fukuii.domain.*`.
- **DAG edge (down-only):** `domain → bytes, crypto, rlp, common`. **No upward edges** — this is the
  structural fix for the Phase-3 13-package SCC (`domain` used to import up into `db`/`mpt`/`vm`/
  `ledger`/`jsonrpc`/`network`). An upward `.dependsOn` is a compile error.
- **★ The `Blockchain` / `BlockchainReader` facade traits do NOT live here.** In old fukuii they sat in
  `domain` and reached up into `db`/`ledger`/`jsonrpc` — the primary SCC edge. They **relocate to L7
  `chain`** (target-architecture SCC-breaking move #1). `domain` is *pure value types only*.
- **★ L1 holds no custody / unlock / signer-backend state.** The signing *operation* lives here as a pure
  function; *where the key lives* (in-heap keystore, external clef, HSM, validator-remote) is an **L8**
  seam decision (§2, §7). This keeps the OBSOLETE permanent-in-node-unlock model (`personal_*`
  `ExpiringMap`) out of `domain` by construction.

**What L1 builds** (pure, immutable value types + their codecs + the signing gate):

| Group | Types |
|---|---|
| Account state | `Account` (nonce, `balance: Wei`/L0 `UInt256` — the 32-byte width, **not** a bare `BigInt`; geth migrated the state balance to `*uint256.Int`, `state_account.go:34`), storageRoot, codeHash) |
| Block | `Block`, `BlockBody`, `BlockHeader` (**fork-variant**, trailing-optional fields) |
| Transaction | `Transaction` — a Scala 3 **enum** of typed envelopes: `Legacy` / `AccessList` (EIP-2930) / `DynamicFee` (EIP-1559) / `Blob` (EIP-4844) [+ `SetCode` EIP-7702, ETH-family] |
| Signed tx | `SignedTransaction` (envelope + `ECDSASignature`); the **tx-signing + sender-recovery gate** |
| Receipts / logs | `Receipt` (legacy + typed, status-vs-postState), `Log`, `Bloom` (logs-bloom) |
| Semantic wrappers | `Wei` (opaque over `UInt256`), `ChainId` (opaque, EIP-155), `Nonce`/`GasLimit` where they earn their type-distinctness |

**Not redefined here:** `Address`, `Hash`, `UInt256` are **L0 `bytes`** value types (per `01-L0-primitives.md`);
`domain` *consumes* them. `ECDSASignature`, `kec256`, sender-recovery math, and the R11
`constantTimeEquals` primitive are **L0 `crypto`**; the RLP engine + `derives RLPCodec` are **L0 `rlp`**.
`domain` is the first layer that *composes* the L0 leaves into ecosystem consensus objects.

## 2. SR slots & verdicts (honor, do not invent)

### From `observations/primitives.md`

- **RLP codec — DEFAULT: typeclass/`derives`-derived codecs.** _"reth's alloy `#[derive(RlpEncodable)]`
  and nethermind's per-type decoder registry both map onto a Scala 3 `given RLPCodec[T]` / `derives
  RLPCodec` … Prefer it over hand-rolled encoders. besu's streaming-cursor `RLPInput`/`RLPOutput` is the
  JVM *structural* analog … not a competing codec-authoring model."_ (primitives.md §Best-practice
  synthesis.) → Account/Log/Receipt/Body use `derives RLPCodec`; the **typed-tx envelope** and the
  **fork-variant header** stay explicit hand-written `given`s (the reth pattern of hand-writing the
  special cases), consuming L0's `PrefixedRLPEncodable` (EIP-2718) and `DerivationPolicy`.
- **nethermind named-variant RLP registry (2 forms/type)** — nethermind's `[Rlp.Decoder(key)]` keys
  *more than one* decoder per type (storage-vs-wire). (`optimizations.md` §L0, OPTIONAL(additive).) This
  is the **reference model for L1's blob consensus-encoding-vs-network-wrapper split** (§9): one
  `Transaction.Blob` type, two RLP forms — the **consensus** encoding (no sidecar; `tx.hash`/tx-trie use
  this) and the **network wrapper** (blobs+commitments+proofs). fukuii expresses the two forms as two
  explicit `given`s over the same enum case (named-variant discipline), never one codec that conditionally
  includes the sidecar — hashing the wrapper is a consensus split.
- **Value types — DEFAULT: fixed-width wrapper value types** _"in Scala 3 this is opaque types over
  `Array[Byte]`/`ByteString`, type-distinct so `Wei` can't silently mix with a raw `UInt256`."_ (§Best-
  practice synthesis.) → `Wei`/`ChainId` are opaque over the L0 numeric type.
- **OBSOLETE(for JVM port): zero-alloc structs** (`ValueHash256`, `Span`, `ref struct`) — _"does NOT
  port … Scala opaque types erase the wrapper but cannot inline 32 bytes."_ We do **not** chase inline
  layout; we chase erigon's pooling/benchmark discipline (deferred, §7) and its `atomic`/lazy tx-hash
  memoization (§5, §7).
- **KZG/BLS handling — DEFAULT behavior go-ethereum.** Blob-tx `versionedHashes`/`KZGCommitment`
  encoding is a value-type concern here; the crypto verify is L0, the precompile is L3.

### From `observations/accounts-signer.md` (the L1 = "domain (signing/tx)" slice; keystore is L8)

- **Tx signing is chain-agnostic value logic.** accounts-signer's DEFAULT/OPTIONAL verdicts (geth-v3
  keystore DEFAULT; `ISigner`/`ISignerStore` seam DEFAULT; clef/HSM OPTIONAL(custody)) are **L8
  keystore** concerns, not L1. What lands at L1 is the **signing operation + EIP-155 sender recovery**
  the keystore's `Wallet.signTx` and the txpool's admission both call down into. L1's signing is therefore
  **seam-shaped**: a pure `(tx, privKey, chainId) → SignedTransaction` / `(signedTx) → Address` function
  that an `ISigner` implementation *calls*, never a class that owns the key.
- **The `ISigner`/`ISignerStore` read/write split (nethermind) is DEFAULT — as the seam.** _"Consensus/
  sealing depends only on `ISigner`; swapping key location is a plugin decision, zero block-production
  change. Split read (`ISigner`) from write (`ISignerStore`) so a remote signer can honestly implement
  'sign this' while making 'here is the private key' a compile-visible unsupported operation."_ (accounts-
  signer §Best-practice synthesis.) **The seam abstraction and its backends live at L8**; L1's contribution
  is that the pure signing function it exposes is exactly what the *read* side (`ISigner.sign`) delegates to
  — so the split is *possible* because L1 never couples the key to the operation. The four OPTIONAL(role)
  backends are **relocated to L8 and scheduled with proving tests** (§7), not silently listed:
  besu `SecurityModule`/HSM (OPTIONAL custody/enterprise); geth+nethermind clef external signer
  (OPTIONAL custody); nethermind `ClefSigner` validator remote-signing (OPTIONAL validator); erigon
  `Authorize(SignerFn)` callback (OPTIONAL validator).
- **OBSOLETE: permanent in-node account unlock** (_"don't model fukuii on permanent in-node unlock"_) —
  fukuii **sits on this today**: `PersonalService.unlockAccount` holds decrypted keys in an in-heap
  `ExpiringMap[Address, Wallet]` (300 s default, lazy/passive expiry, no zeroing), and `duration=0` unlocks
  *forever* (`addForever`) (`jsonrpc/PersonalService.scala:104,128,135`). This is a keystore/RPC concern
  (L8/L9), named here only so L1's signing gate carries **no** unlock/custody/expiry state; it is a pure
  function.
- **OBSOLETE(for R2): reth compile-time `NodePrimitives`/`NodeTypes` family.** reth monomorphizes the
  primitive family (tx/header/receipt types) at compile time via associated types. (`optimizations.md`
  §L1.) fukuii **consciously rules this out**: compile-time-monomorphized families conflict with R2 (the
  single binary must select the network family **at runtime**, N isolated instances of possibly-different
  families in one process). fukuii keeps the family a **runtime** selection (the L5 `NetworkFamily`
  typeclass over immutable data), so `domain` types are plain values, not type-parameters of a
  `NodeTypes` bound. Naming this avoids reintroducing it under an "idiomatic generics" banner.
- **Strict node-identity-key vs account-key separation (reth/erigon):** the P2P node key is **not** a
  domain type and never becomes a signable account — enforced structurally by keeping it out of `domain`.
  fukuii already ALIGNS here (`node.key` plaintext hex on a wholly separate code path,
  `network/package.scala:32`, `nodebuilder/NodeBuilder.scala:101`); L1 preserves the invariant by never
  admitting a node-identity key into any signable type. The corollary reth/erigon carry — **an
  account-signing path that fails closed (`NoAccount`) with an empty-signer-list-by-construction rather
  than silently degrading** — is honored: L1 models *no* implicit default account, so "no account
  configured" is a total, representable state, not a null.

## 4. besu structural mirror

besu splits **`datatypes/`** (leaf value types: `Address`, `Hash`, `Wei`, `TransactionType`,
`AccessListEntry`, `CodeDelegation`, `Blob`, `VersionedHash`, `KZGCommitment`, `Log`, `LogTopic`,
`LogsBloomFilter`, `AccountValue`) from **`ethereum/core/`** (the heavier consensus objects:
`Transaction`, `BlockHeader`, `BlockBody`, `Block`, `TransactionReceipt`, `BlockHeaderBuilder`).

fukuii's mapping of that split onto the DAG:
- besu's leaf `datatypes` primitives (`Address`/`Hash`/`UInt256`) → **already at L0 `bytes`** (per
  `01-L0-primitives.md`). besu's *semantic* datatypes (`Wei`, `TransactionType`, `Log`, `AccessListEntry`,
  `VersionedHash`) + all of `ethereum/core/` → **L1 `domain`**.
- besu `Transaction.java` is **one class with `Optional<>` fields** discriminated by a `TransactionType`
  enum (`chainId`, `maxPriorityFeePerGas`, `maxFeePerGas`, `accessList`, `versionedHashes`,
  `maxFeePerBlobGas` are all optional). **fukuii diverges deliberately** (§5): a Scala 3 **`enum
  Transaction`** with per-variant cases replaces the optionals-on-one-class shape — exhaustive, no
  illegal field combinations representable, one `given RLPCodec` arm per variant.
- besu's **first-byte → type dispatch** (`TransactionType.transactionTypeByOpaqueByte`, `0xc0..0xfe` ⇒
  FRONTIER/legacy, else typed) is the model for L1's EIP-2718 aggregation decode (§7).
- besu `RLPInput`/`RLPOutput` streaming cursor is the **reader/writer plumbing** shape under our
  typeclass; the codec-authoring model stays L0's `derives` + AST (primitives.md verdict).
- besu `BlockHeaderBuilder` (staged, fork-aware construction) informs how the fork-variant header is
  assembled without a mutable header — a per-fork factory returning an immutable `BlockHeader`.
- besu `SecurityModule` (the signer/HSM seam) is the JVM structural mirror for the **L8** signer seam;
  L1's pure signing function is what a `SecurityModule`/`ISigner` `sign` implementation delegates to when
  the key *is* local. (The seam and backends are L8, per §2/§7.)

## 5. Scala 3 idiom targets

- **`enum Transaction`** — `case Legacy(...)`, `case AccessList(...)`, `case DynamicFee(...)`,
  `case Blob(...)` (+ `SetCode` for ETH 7702). Exhaustive `match` in validation; the type id is a method
  on the enum, not a stored discriminator + optionals. Replaces old fukuii's trait hierarchy and besu's
  optionals-on-one-class. (`optimizations.md` §L1 — DEFAULT.) The **`SetCode`** (7702) case carries an
  inner `AuthList` of `SetCodeAuthorization(chainId, address, nonce, yParity/r/s)` tuples (geth
  `tx_setcode.go:61/72`), each with its **own** `SigHash()`/signature — a **second signing/recovery surface**
  beyond the outer tx signature. Model the authorization tuple as an L1 value type with its own recovery
  (ETH-family; **beacon** gate); the base enum models it, ETC admissibility rejects it pre-Olympia.
- **Opaque semantic wrappers** — `opaque type Wei = UInt256`, `opaque type ChainId = BigInt` (EIP-155),
  zero-cost, type-distinct (`Wei` can't be passed where a raw `UInt256` is wanted; an `assertDoesNotCompile`
  test guards it, as L0 did for `Address`/`Hash`).
- **`derives RLPCodec`** for the genuinely straight-field-list types — **`Account` and `Log` only**. This
  is L0's now-working `derives` (the old `type RLPCodec = A & B` alias that _"could never be a `derives`
  target"_ is fixed to a `trait RLPCodec[T]` in L0). **`BlockBody` is NOT a naive-derive** — it carries a
  trailing-optional `Withdrawals` list (geth `block.go:186/228`, `rlp:"optional"`), so it takes the same
  `DerivationPolicy(omitTrailingOptionals)` treatment as the fork-variant header (or a hand-written `given`),
  never a blanket `derives` — a pre-Shanghai ETH body / any ETC body must **omit** withdrawals. **`Receipt`
  is NOT a naive-derive either** — its status-vs-post-state RLP is a mutually-exclusive union (a pre-fork
  receipt encodes a 32-byte post-state root, Byzantium+/Atlantis+ a 1-byte status) plus a typed-receipt
  prefix, so it needs a policy-aware derive or explicit `given`, not a plain field-list derive.
- **Explicit hand-written `given RLPCodec[Transaction]`** — the typed-envelope EIP-2718 arm (legacy =
  bare RLP list; typed = `PrefixedRLPEncodable(typeByte, payloadList)`), exactly as reth hand-writes the
  special tx cases while `derives` covers the rest. For `Blob`, **two** named `given`s (consensus form,
  network-wrapper form) per the nethermind two-form reference (§2, §9) — never one conditional codec.
- **Explicit hand-written `given RLPCodec[BlockHeader]`** with `DerivationPolicy(omitTrailingOptionals)`
  for the fork-variant trailing fields (§7).
- **`extension` methods** for derived quantities calling down to L0 crypto — `header.hash`, `tx.hash`
  (the **consensus tx hash**, over the typed-envelope encoding, **never** the blob network-wrapper),
  `signedTx.senderAddress` (sender recovery). No `implicit class`/`implicit def` anywhere.
- **Lazy/`atomic` tx-hash memoization** (erigon; `optimizations.md` §L1 — OPTIONAL(perf)) — `tx.hash` /
  `signedTx.senderAddress` may cache into a private lazily-populated field. Per
  `best-practices/evm-clients/mutable-state-parity.md`, a parity-correct in-place memo on an
  otherwise-immutable value **needs no purity justification** — every reference client memoizes the tx
  hash. Scheduled with a proving bench (§7), not built speculatively; the cache is transparent (same value,
  computed once) and does not weaken the R2 no-global-mutable-state rule (it is per-instance value-local).
- **`given` sender-recovery gate** — a pure `SignedTransaction.getSender: Either[SigError, Address]`
  that runs `ValidateSignatureValues` **before** recovery (§7, N-1).
- **Total "no account" state** — the account-signing seam's absence is a representable value
  (`Option`/`NoAccount`), never a null default — the reth/erigon fail-closed corollary (§2).

## 7. Deferrals landing here, with tests (a floor, not optional — `planned-work-is-scope-floor`)

**N-1 — the low-S / `ValidateSignatureValues` gate** (carried from `L0-review.md` forward-note N-1;
_"`domain`/tx-admission must enforce `ValidateSignatureValues`"_). L0 `crypto` exposes low-S/range
primitives but does not **gate**; L1 wires the gate into `getSender`/signing.
- **Rule (byte-exact to geth `crypto/crypto.go:240` + core-geth `transaction_signing.go:615`):** reject
  `r < 1 || s < 1`; reject `r ≥ N || s ≥ N`; reject `s > N/2` for EIP-2/homestead-and-later (all ETC
  post-Homestead, all ETH); require recovery-id `v ∈ {0,1}` (after EIP-155/2718 normalization).
  **For all fukuii live networks `homestead=true`** — the full-N Frontier acceptance branch (geth
  `crypto.go:249-250`) is **dead code** for ETC/ETH, so fukuii hard-codes `s ≤ N/2` and does **not** plumb a
  live `homestead` bool that is never false (record for the forge/beacon gate, not a runtime path).
- **Tests:** accept a canonical low-S signature; reject `r=0`, `s=0`, `r=N`, `s=N`, `s=N/2+1`
  (high-S malleable), and a bad `v`; a golden **sender-recovery KAT** (known signed tx → known sender
  address) for each of Legacy(EIP-155, chainId 61 and 1), AccessList, DynamicFee, Blob. For **`SetCode`**
  (7702, ETH-family/**beacon**) add a **separate authorization-recovery KAT** — a known `SetCodeAuthorization`
  tuple (chainId, address, nonce, y/r/s) recovers to its known authority address, distinct from the outer
  tx sender recovery (the inner `AuthList` is a second recovery surface).

**RLP trailing-optional-omission policy** (from [`02-L0-rlp.md`](../02-L0-rlp.md) Layer-boundaries →
_"the consumer layer that needs it (`domain`, fork-variant block headers)"_). The fork-variant
`BlockHeader` is the consumer: geth encodes the trailing-optionals **in this exact order** — `BaseFee`
(EIP-1559, `block.go:86`) / `WithdrawalsHash` (EIP-4895, `:89`) / `BlobGasUsed` (EIP-4844, `:92`) /
`ExcessBlobGas` (EIP-4844, `:95`) / `ParentBeaconRoot` (EIP-4788, `:98`) / `RequestsHash` (EIP-7685, `:101`)
/ `BlockAccessListHash` (EIP-7928, `:104`) / `SlotNumber` (EIP-7843, `:107`) — **8** fields, all
`rlp:"optional"`, with the contract **present-from-a-fork, omitted-before, and once present all later ones
must be present**. **The tail is open-ended** — new ETH forks (Osaka+) keep appending, so the codec must be
built for a growing tail and **must not assume a fixed max field count** (no hardcoded stop at
`requestsHash`).
- **Tests:** per-fork header RLP round-trip, asserting the **exact tail present at fork F** for each fork —
  ETH: legacy(15) → London(+baseFee) → Shanghai(+withdrawalsRoot) → Cancun(+blobGasUsed,+excessBlobGas,
  +parentBeaconRoot) → Prague(+requestsHash) → **Osaka+(+blockAccessListHash EIP-7928, +slotNumber
  EIP-7843)** — "tail is open; new ETH forks append, the test list grows with them." These trailing fields
  are ETH-family (**beacon** gate); ETC: pre-Olympia has **none** of them (a base-fee field on a Mordor
  header is a consensus bug), and ETC stays at **zero** trailing fields. Assert a mid-run gap is rejected
  (can't have `excessBlobGas` without `blobGasUsed`).

**EIP-2718 typed-tx aggregation** (from `02-L0-rlp.md` → _"reading a stream of EIP-2718 envelopes back …
`domain`; the engine provides `PrefixedRLPEncodable` (encode side) and `nextElementIndex` (stream walk)"_).
The `Transaction` decoder dispatches on the first byte: `0xc0..0xfe` ⇒ legacy RLP list; `0x01..0x04` ⇒
strip the type byte, decode the variant payload (besu `TransactionType.transactionTypeByOpaqueByte`).
- **Tests:** a mixed-type block body (`legacy + 2930 + 1559 + 4844`) round-trips; an **unknown type byte**
  (`0x05`) is **rejected** (not silently treated as legacy); a bare legacy list still decodes.

**tx-hash `atomic`/lazy memoization** (erigon; `optimizations.md` §L1 — OPTIONAL(perf), `mutable-state-
parity`). The `tx.hash`/`senderAddress` cache (§5). **Deferred with a proving bench, not built
speculatively** — schedule only once a real serialization/recovery hot path exists to profile (the
erigon profile-driven discipline, `primitives.md` §Zero-alloc). **Test/bench:** a parity test proving the
memoized value equals the recomputed value byte-for-byte; a micro-bench showing the memo removes the
repeated-hash allocation on a block-body decode. No `unsafe` tricks (JVM caveat, `primitives.md`).

**`ISigner`/`ISignerStore` seam + custody backends → relocated to L8, scheduled with proving tests.**
L1 owns only the pure signing function; the seam and its OPTIONAL(role) backends are **L8** deferrals,
listed here so they are not lost (§2):
- **`ISigner`/`ISignerStore` read/write split** (nethermind; DEFAULT-as-seam) — **L8**. Test: consensus/
  signing paths compile against `ISigner.sign` only; `ISignerStore` (key-export) is a compile-visible
  unsupported op on a remote impl.
- **besu `SecurityModule`/HSM** (OPTIONAL custody/enterprise) — **L8**. Test: a stub `SecurityModule`
  signs a tx via the seam without the key entering the L1 signing function's local path.
- **clef external signer** (geth+nethermind; OPTIONAL custody) — **L8**. Test: `account_signTransaction`
  round-trip against a mock clef endpoint yields a sender-recovery-valid `SignedTransaction`.
- **validator remote-signing** (nethermind `ClefSigner` / erigon `Authorize(SignerFn)`; OPTIONAL
  validator) — **L8**, ties to `CL-RESEARCH-EMBED-01`. Test: a header/message signed via the injected
  callback recovers to the expected author, with no local key.

**Keystore hardening (AS-IS gaps) → L8, flagged.** From `.local/.../fukuii/accounts-signer.md` §Gotchas —
named here so L1's clean signing boundary doesn't obscure them; **all land at L8**:
- **Constant-time MAC (R11)** — the L0 `constantTimeEquals` primitive replaces `createMac(...) == mac`
  (`EncryptedKey.scala:70`). L0 owns the primitive; **L8** owns the keystore call site (a second call site
  is any L1/L9 MAC/tag compare). Test: a timing-invariant compare unit test + the MAC-gate still rejects a
  wrong passphrase.
- **Atomic-rename / verify-after-write on save** — `KeyStoreImpl.save` does a direct `Files.write`
  (`KeyStore.scala:116`) with no temp-file-then-rename and no read-back-decrypt (geth does both) →
  torn-keyfile risk. **L8** deferral, test: interrupted write leaves the prior keyfile intact.
- **Parity/`aes-128-cbc` Keccak-twist read-compat** — `decrypt` uses `secret = dk.take(16)` uniformly and
  omits the extra `keccak256(derivedKey[0..16])` twist the legacy Parity/`aes-128-cbc` convention (and
  nethermind `FileKeyStore`) apply → a legacy CBC keyfile in twist form fails MAC verification. **L8**
  deferral (`VERIFY` whether real Mantis-era twist-form keyfiles exist), test: a twist-form CBC keyfile
  decrypts.
- **`ProtectedPrivateKey` heap-protection** — unlocked keys are bare `ByteString` in the JVM heap, evicted
  lazily, never zeroed (contrast nethermind `ProtectedPrivateKey`/DPAPI). **L8** deferral, test: key bytes
  are zeroed on lock/eviction.

**`RLPSerializable` convenience trait** → added to `domain` only if a concrete consumer wants it
(`encode`/`decode` already cover the API surface — not built speculatively).

## 8. Exit DoD (GREEN bar)

**Gate lenses** (≥3, none the builder, per `plan/README.md`): (a) **correctness / byte-alignment** —
**forge** for ETC tx/fork/chainId values (vs core-geth) + **beacon** for ETH typed-tx/blob/header (vs
go-ethereum); (b) **besu JVM-implementation lens** (the L0-proven pass — big-int widths, unsigned
recovery, Optional-vs-enum modelling, no Go slice-aliasing assumptions); (c) **mithril** Scala 3 idiom
(enum/opaque/derives, no `implicit class`); (d) **eye** runs the suites.

**Reference vectors that must pass (GREEN *and wired* — never dormant):**
- **Tx RLP round-trips** — EIP-155 legacy, EIP-2930, EIP-1559, EIP-4844 (consensus encoding, not the
  blob wrapper), byte-exact vs go-ethereum / core-geth; from `ethereum/tests` `TransactionTests` +
  geth's own tx vectors.
- **Blob two-form separation** — the consensus encoding and the network-wrapper encoding of the same
  `Transaction.Blob` produce **different bytes**, `tx.hash` uses the consensus form only, and
  `versionedHash = 0x01 ‖ sha256(commitment)[1:]` links them (nethermind two-form reference, §2/§9).
- **Sender-recovery KATs** — golden `signedTx → sender` per tx type, incl. EIP-155 chainId 61 (ETC) and
  1 (ETH), and pre-EIP-155 unprotected (v=27/28).
- **`ValidateSignatureValues` fail-set** — the N-1 rejection vectors above.
- **Fork-variant header RLP** — per-fork tail round-trips (ETH London→Prague→Osaka+; ETC pre-Olympia = zero
  trailing), omission correctness; the codec assumes no fixed max field count (open tail).
- **`BlockBody` RLP** — body round-trip asserting the trailing-optional `Withdrawals` list is **omitted**
  for any ETC body and pre-Shanghai ETH, present post-Shanghai ETH (same `omitTrailingOptionals` contract
  as the header; geth `block.go:186/228`).
- **Receipt RLP** — legacy + typed, logs-bloom byte-exact, plus the **status-vs-post-state fork switch**:
  a **pre-Atlantis ETC / pre-Byzantium ETH** receipt encodes a 32-byte **post-state root** (not a status
  byte), a post-fork receipt encodes the 1-byte status — the two are **mutually exclusive** in the RLP
  (geth `receipt.go:38-57,92-100`). The DoD vector must include a pre-fork post-state-root receipt to prove
  the switch (per-network fork boundary: **forge** for ETC Atlantis, **beacon** for ETH Byzantium), plus the
  typed-receipt prefix vectors.
- **`Account` RLP** — state-account round-trip vs geth `state_account.go` (field order
  Nonce→Balance→Root→CodeHash), **asserting `Balance` encodes as a 32-byte-bounded quantity** (L0 `UInt256`
  width, matching geth's `*uint256.Int`), not an unbounded big-int.
- **tx-hash memoization parity** (if the memo is built this pass) — memoized == recomputed, byte-for-byte.

A layer is not "done" until **every** type is GREEN under all lenses (the L0 gate caught F-BN-1, a
chain-split bug, *before* L2 built on it — the reason the gate exists).

## 9. Risks & consensus-critical flags

- **Tx signing + RLP layout are byte-exact / consensus — forge (ETC/PoW) + beacon (ETH/PoS) gate,
  mandatory.** Tx hash, sender recovery, and every RLP field order/length feed the tx-trie root and the
  block hash. State-root/tx-hash litmus (`consensus-change-protocol.md`): any change here is a one-way
  door.
- **The fork-variant `BlockHeader` trap.** An `Eth*` trailing field (baseFee/withdrawalsRoot/blob*) must
  **never** appear on an ETC header, and ETC's ECIP header fields must never appear on an ETH header.
  Field **order and trailing-optional omission** are consensus (geth `rlp:"optional"`). Enforce with the
  network-prefixed, positive-keyed per-fork layout — **not** an `else-means-ETC` / `else-means-legacy`
  fallthrough (the dormant-marker anti-pattern from the risk register). The ETH-family tail is **open-ended**
  — geth is already at 8 trailing-optionals (through `BlockAccessListHash` EIP-7928 + `SlotNumber` EIP-7843)
  and each new ETH fork appends more (**beacon** gate); the codec must never assume a fixed max field count.
  ETC stays at **zero** trailing fields.
- **Framework, not ETC/ETH binary — but per-network admissibility is real (R1).** `domain` **models all**
  tx variants (Legacy/2930/1559/4844/7702) because it's a multi-network framework; whether a variant is
  **admissible** is a per-network validation decision at L4/L5, not a modelling omission. `ChainId` is
  opaque data, not a type-level fork; the family is a **runtime** selection (reth's compile-time
  `NodeTypes` monomorphization is ruled out for R2, §2). Flag: a blob (4844) or dynamic-fee (1559) tx must
  **not** validate on ETC's current (pre-Olympia) gas model — the type exists, the network policy rejects
  it. Do not let "the type compiles" imply "the network accepts." **Name-and-avoid — no `DepositTx`
  (0x7E):** 0x7E is an OP-stack (Optimism) type, absent from **both** core-geth (the ETC authority;
  `grep -E '0x7[eE]|DepositTx' core-geth/core/types/*.go` → no match) and go-ethereum mainline. ETC's and
  ETH's admissible tx-type set is exactly {0x00–0x04}. A future OP-stack `NetworkFamily` would add 0x7E as
  *that family's* variant — it must **not** be baked into the base ETC/ETH enum.
- **Blob tx: consensus encoding vs network wrapper.** EIP-4844 has two encodings — the **consensus** tx
  (no sidecar; `tx.hash` and the tx-trie use this) and the **network wrapper** (blobs + commitments +
  proofs, besu `BlobsWithCommitments`). Hashing or trie-rooting the wrapper is a consensus split. The
  `versionedHash` (`0x01 ‖ sha256(commitment)[1:]`) is the consensus link. Model the two forms as two
  named `given`s over one enum case (nethermind named-variant discipline), never one conditional codec.
- **EIP-155 `v` / chainId recovery.** Legacy protected: `v = {0,1} + 2·chainId + 35`; unprotected 27/28;
  typed txs carry a bare `yParity ∈ {0,1}`. core-geth chainId **61 (ETC) / 63 (Mordor)**, go-ethereum
  **1 / 11155111**. A wrong chainId in the sighash silently produces the wrong sender — covered by the
  per-chainId recovery KATs.
- **Low-S is consensus, not hygiene.** Accepting a high-S signature admits a malleated duplicate tx
  (different hash, same effect) — the N-1 gate is a hard requirement on both families.
- **Signer-seam integrity is structural.** L1 must never couple the private key to the signing operation
  (else L8 cannot honestly implement a remote/HSM `ISigner`), and must never admit the node-identity key
  as a signable account. Both are structural invariants, not runtime checks — enforced by what `domain`
  *does not* model.
- **Timing side-channels are R11-real.** The keystore MAC-gate compare must be constant-time
  (`constantTimeEquals`, L0 primitive; the fix lands at the L8 call site). Named here so the signing
  boundary's cleanliness doesn't hide the inherited `==` finding.

## Agentic alignment (who gates what)

_Per `CLAUDE.md` Specialist subagents + the Consensus-Critical Change Protocol._

- **Tx envelopes, sender recovery, EIP-155, ECIP fork values, ETC chainId 61/63** → **forge** (PoW
  consensus): impact analysis *before* implementing, byte-perfect vs core-geth. Any RLP field order/length
  is state-root-affecting → the state-root litmus routes it here.
- **ETH typed-tx / blob (4844) / withdrawals / 7702, fork-variant header trailing fields, timestamp
  forks** → **beacon** (PoS consensus): byte-perfect vs go-ethereum.
- **Scala 3 idiom** (`enum Transaction`, opaque `Wei`/`ChainId`, `derives`/hand-written `given`,
  `extension` methods, no `implicit class/def`) → **mithril**, on non-consensus refactors only; consensus
  shape stays with forge/beacon.
- **Compile errors during the build** → **wraith**; **test/vector execution + chain-compat** → **eye**
  (read-only, runs the suites).
- **The keystore + signer-seam work points to L8, not L1.** The `ISigner`/`ISignerStore` seam, the custody
  backends (clef/HSM/validator-remote), and the keystore-hardening gaps (constant-time MAC, atomic-write,
  CBC twist, heap-protection) are **L8** deliverables (§7). The L0 `constantTimeEquals` primitive is
  **sentinel/L0**-adjacent (R11 security); L1 only guarantees its signing boundary is seam-shaped so those
  land cleanly.

## Layer boundaries (what lives elsewhere, and why)

_Durable placement decisions — not build-status (see the `../README.md` index for what's committed)._

- **`Blockchain` / `BlockchainReader` facade traits** → **L7 `chain`**. They read persisted blocks/state
  (an upward dependency from a pure value layer); keeping them here re-forms the SCC. `domain` defines
  the *values*; `chain` defines *access to stored values*.
- **The keystore, `Wallet`, `personal_*` unlock, the `ISigner`/`ISignerStore` seam, the custody backends
  (clef/HSM/validator-remote), and the keystore-hardening gaps** → **L8 `keystore`** / **L9 `rpc`**
  (accounts-signer DEFAULT/OPTIONAL verdicts, §7). L1 owns only the pure signing *operation* + sender
  recovery; it holds no unlock/custody/expiry state (the OBSOLETE in-node-unlock model stays out by
  construction).
- **The L0 `constantTimeEquals` primitive** → **L0 `crypto`** (R11 STRUCTURAL). L1/L8/L9 *call* it (MAC,
  ECIES-tag, JWT compare); L1 does not define it.
- **Gas-metered / opcode `UInt256` semantics** (EXP gas, SIGNEXTEND, SDIV/SMOD/SAR), **tx gas
  *validation*** (intrinsic gas, base-fee checks), and **fork *dispatch*** → **L3 `evm`** / **L4
  `execution`** / **L5 `consensus`**. `domain` carries the *shapes* (typed envelopes, fork-variant
  header fields); the *rules over them* live at their execution/consensus layer.
- **Txpool admission policy** (tip floors, replacement, ordering) → **L8 `txpool`** / banksy. L1's
  `getSender` gate is the pure signature-validity check admission *calls*, not the policy itself.
- **Alloc-benchmark harness** (erigon's profile-driven discipline; the AST's eager allocation and the
  tx-hash memo are the things to measure) → a `Benchmark`-config item once a real serialization hot path
  exists to profile (§7).
- **Runtime family selection** (the `NetworkFamily` typeclass) → **L5**; the compile-time
  `NodePrimitives`/`NodeTypes` monomorphization (reth) is **ruled out** for R2 (§2) — `domain` types stay
  plain values, not `NodeTypes`-bound type-parameters.
- **RLP engine, `derives RLPCodec`, `PrefixedRLPEncodable`, canonical-form decode** → **L0 `rlp`**;
  fixed-width `Address`/`Hash`/`UInt256`, hashing, `ECDSASignature`, sender-recovery math →
  **L0 `bytes`/`crypto`**. `domain` composes these; it does not re-implement them.
