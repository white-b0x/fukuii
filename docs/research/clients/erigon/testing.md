# erigon — testing
_Commit/branch documented: f1d79d699e / upstream. Documented 2026-07-13._

## Architecture summary

Erigon's testing splits into four layers, each with a distinct oracle and cadence:

1. **Reference-fixture tests** (`execution/tests/`) — consume the `ethereum/tests`
   fixtures two ways: (a) the **legacy** JSON corpus vendored as a git submodule
   (`execution/tests/legacy-tests`, from `github.com/ethereum/tests`) driven by
   in-tree Go runners, and (b) the modern **EEST** (`execution-spec-tests`)
   fixtures, downloaded as pinned tarballs and replayed through `cmd/evm`
   sub-runners (`statetest`, `blocktest`, `enginextest`, `zkevmtest`). go-ethereum
   remains the semantic oracle: fixtures are generated by the spec's `t8n`/`evm`
   tooling, and Erigon just re-executes them.
2. **Staged-pipeline tests** (`execution/stagedsync/*_test.go`) — the
   architecture-specific layer. The sync *orchestrator* is tested with synthetic
   mock stages (closures), and individual stages are tested for forward / unwind /
   prune against a real temporal DB.
3. **RPC-conformance-via-external-repo** — an out-of-tree Python repo
   (`erigontech/rpc-tests`, pinned to `v2.20.0`) replays canned request/response
   pairs against a live node; plus the in-tree `cmd/rpctest` differential tool that
   diffs Erigon's RPC output against geth's.
4. **Hive** — external `ethereum/hive` simulators (pinned by commit in
   `hive-versions.json`), run against a Docker image of the client.

Go table-driven tests with `testify` (`require`/`assert`) are the unit convention
throughout. CI shards everything through `make test-group` (a Python
`tools/test-groups` partitioner) and `-race` variants.

## Design decisions & rationale

- **Two fixture corpora on purpose.** EEST is the forward-looking spec-test source
  (statetest/blocktest via `cmd/evm`), but the legacy `ethereum/tests` submodule is
  retained because it carries fork variants EEST dropped; keeping both means the
  regression class is caught on every CI run, not only the weekly out-of-tree Hive
  run (`state_test.go:52` comment).
- **Fixtures are pinned by content hash, not floating refs.** `test-fixtures.json`
  carries sha256 + size for every tarball; `rpc_version.env` and `hive-versions.json`
  pin the external suites by tag/commit. Determinism and supply-chain integrity of
  the test corpus itself.
- **Mock-stage orchestrator tests.** The sync engine's ordering/unwind/interrupt
  logic is tested with trivial closure-stages so the test exercises *control flow*
  (which stage runs, in what order, how far unwind rewinds) with zero dependence on
  any real stage's I/O — fast, deterministic, and pinpoints orchestration bugs.
- **RPC conformance lives out-of-tree.** Correctness of a large archival RPC surface
  is validated by replaying a versioned corpus (`rpc-tests`) against a synced node
  and optionally diffing a reference client — decoupling RPC-response conformance
  from the Go unit-test cycle and letting it version independently.
- **Failure budgets, not all-or-nothing.** EEST shards carry explicit
  `max-allowed-failures` (mostly 0) with a rule that bumping requires a comment +
  tracking issue — a governed ratchet rather than a silent skip.

## Notable patterns (the reusable idea)

- **Mock-stage orchestrator harness** (`sync_test.go`): model each pipeline step as
  a closure that records its own execution into an ordered `flow` list, then assert
  `flow == expectedFlow`. This tests the *scheduler* (ordering, disable, error
  propagation, unwind depth, interrupt/restart) in isolation from step semantics.
- **`TestMatcher` policy object** (`matcher.go`): a reusable driver that walks a
  fixture tree and carries declarative regex policy — slow/skip/expected-fail/
  whitelist/per-test-config — so known-broken fixtures are *asserted to fail with a
  reason* instead of being commented out. Expected-failure tracking is first-class.
- **Content-hash-pinned external corpora**: fixtures and conformance suites pinned by
  sha256/tag/commit in checked-in manifests, provisioned on demand.
- **Differential testing against the reference client** (`cmd/rpctest --needCompare`
  and `run_rpc_tests.sh --verify-external-provider`): diff this client's RPC output
  against geth's rather than against hand-written expectations.

**Transferable to fukuii:** fukuii already has tiered testing (`testEssential`/
`testStandard`/`testComprehensive`) and 12 hive workflows. The two highest-value
imports are (1) the **`TestMatcher` expected-failure-with-reason pattern** — replace
any `-- SKIP`/ignore of a failing consensus fixture with an asserted, reasoned
expected-fail entry so regressions can't hide and re-passing fixtures flip loudly;
and (2) the **content-hash-pinned fixture manifest + failure-budget shard config**
(`test-fixtures.json` + `eest-spec-shards.yml`) to make fixture provenance and the
"how many known-failing is OK" line explicit and reviewable. The mock-stage
orchestrator idea maps less directly (fukuii's sync is Pekko-actor, not a linear
stage list) but the principle — test the scheduler with synthetic steps recording an
ordered trace — transfers to any pipeline/actor-flow assertion.

## Authority note

go-ethereum is the reference-oracle: the `ethereum/tests` / EEST fixtures are
generated by the spec's `t8n`/`evm` tooling, and `cmd/rpctest`/`run_rpc_tests.sh`
diff against a live geth node. Erigon re-executes and compares; it does not define
the expected values. Erigon is *notable* here for two client-specific harnesses layered
on top of that shared oracle: the **staged-pipeline test rig** (mock-stage orchestrator
+ per-stage unwind/prune tests, unique to its staged architecture) and the
**external-repo RPC-conformance approach** (`erigontech/rpc-tests`, pinned). For
fukuii/PoW-ETC, note that this whole stack is Ethereum-mainnet/EEST-oriented — the
ETC-specific fork variants (ECIP forks, ECIP-1017 rewards) are *not* covered by these
fixtures; core-geth remains the PoW/ETC authority for those.

## Gotchas / anti-patterns / things they later changed

- **Test-group partitioner ordering is a footgun.** `tools/test-groups` greedily
  claims packages in declared order; a group whose packages are a subset of a later
  group's (e.g. `./execution/tests/X/...` under `./execution/tests/...`) must be
  declared *first* or it resolves empty and its tests run silently inside the broader
  shard — a source's own comment warns about this.
- **EEST corpora are huge.** All corpora together are 20 GB+ extracted and don't fit
  smaller CI runner disks, so each shard provisions only its own fixture set
  (`tools/run-eest-spec-test.sh`); naive "download everything" breaks CI.
- **Slow/perf fixtures overrun timeouts under `-race`.** `state_test.go` `SkipLoad`s
  `stTimeConsuming/` and `VMTests/vmPerformance/` because they overrun the 1h package
  timeout under race instrumentation — race and long fixtures don't mix.
- **Hive pinned to a fork, not upstream.** `test-hive-eest.yml:157` currently pins
  `erigontech/hive` (a warm-daemon client-pool branch) rather than `ethereum/hive`,
  with a note to revert once the change lands upstream — an explicitly temporary
  divergence.
- **`macOS ramdisk` special-casing** in `test-filtered` (mounts a ramdisk for the
  execution-tests tmpdir on Darwin) — environment-specific perf hack that's easy to
  overlook when reasoning about where fixtures get written.
