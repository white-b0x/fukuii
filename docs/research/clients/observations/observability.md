## Best-practice synthesis

fukuii is a JVM client, so **besu is the closest reference** — same runtime, same available ecosystem (Micrometer / OpenTelemetry Java SDK / Prometheus `client_java`), same MXBean-based JVM/GC instrumentation, same enterprise expectation of scrape + OTLP + health probes.

**DEFAULT (always-on baseline):**
- **Provider-agnostic `MetricsSystem`-style seam + no-op fallback** — one instrumentation interface (labelled counter/gauge/timer/histogram, grouped by an extensible category), a factory that binds it to a concrete exporter at boot, and no-op instruments when disabled so call sites are always safe (besu).
- **Attributed / registered-once per-module metrics** — a Scala `object Metrics` per subsystem (nethermind's static `Metrics` convention, adapted to instance-scoped counters) fronted by a single scraper, or the Micrometer-registration equivalent; derive names from field identifiers, descriptions from annotations/doc so metric docs can't drift.
- **A pluggable Prometheus / OTLP exporter picked once at boot** (besu/geth) — instrumentation never knows which sink is active.
- **First-class HealthChecks** — `/health` readiness plus an RPC method, consensus-aware (PoW block-production liveness vs PoS CL-alive), machine-readable errors, decoupled from the metrics port (nethermind + besu) — the k8s / custody surface.

**OPTIONAL (enterprise ops menu):**
- **OTLP distributed tracing** on the request path, opt-in behind a feature/dep gate (besu spans on JSON-RPC; reth's `tracing-otlp` with ratio sampling + credential-stripping).
- **Semantic diagnostics subsystem + support tunnel** — typed per-stage sync / peer / resource events over a single best-effort channel, beyond raw metrics (erigon `diaglib`) — a multi-network support-desk differentiator.
- **Shipped Grafana dashboards** versioned in-repo alongside the metrics they read, optionally a cross-network regression-QA dashboard (erigon).
- **ethstats push telemetry** for the ETC/mining-pool community netstats dashboards.

**OBSOLETE for a JVM successor:** vendoring/forking a self-contained metrics library (geth/core-geth) — the JVM gets the registry + pluggable-exporter pattern for free from Micrometer/Dropwizard (itself the Coda Hale lineage geth's fork descends from), without inheriting frozen-fork drift.

## fukuii implications (forward-ref to Phase 3–4, do NOT act here)

fukuii's metrics + healthcheck work is the **SR-11 basket**. besu is the JVM observability authority here — fukuii can adopt Micrometer / OpenTelemetry Java SDK / Prometheus `client_java` directly rather than porting an in-house registry, and mirror besu's `MetricsSystem`-behind-a-plugin-service shape for an exporter-agnostic seam. First-class HealthChecks (nethermind's consensus-aware dual RPC+HTTP surface) and a semantic diagnostics subsystem (erigon's `diaglib`) serve the enterprise / multi-network use case specifically — the readiness probe for k8s/custody and the support tunnel as a differentiator. This is a **comparatively low-consensus-risk, high-enterprise-value adopt**: none of it alters state roots or consensus, and it maps cleanly onto the JVM ecosystem fukuii already runs on. These are **seeds, not verdicts** — Phase 3–4 sizes the actual Micrometer-vs-hand-rolled-seam decision, the per-module `object Metrics` authoring convention, and whether OTLP/diagnostics/dashboards land in the first enterprise cut or a later one.
