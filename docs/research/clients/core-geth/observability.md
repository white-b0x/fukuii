# core-geth — observability
_Commit/branch documented: 4185df450 / upstream (deprecated ETC byte-authority). Documented 2026-07-13._

> **Read `../go-ethereum/observability.md` first.** core-geth is a go-ethereum fork; its
> observability plane — the `metrics/` library, the pluggable exporters, and `ethstats/` — is
> **inherited essentially unchanged** (at an older vintage). This file documents only the diffs.
> The one genuinely core-geth-specific addition is the **OpenRPC discovery service**.

## Architecture summary

**Metrics: inherited fork of `rcrowley/go-metrics` (same commit `e181e09`).** core-geth ships
geth's self-contained metrics library (`metrics/`, `FORK.md` declares the identical
`e181e09` fork point) with the same primitives (`Counter`/`Gauge`/`Meter`/`Timer`/`Histogram`/
`Healthcheck`) in a process-global `Registry`, read by the same pluggable exporters —
Prometheus (`metrics/prometheus/`), expvar (`metrics/exp/`), InfluxDB v1 & v2
(`metrics/influxdb/`), plus the carried-over graphite/opentsdb/syslog/librato reporters. One
instrumentation API, many sinks, chosen by flags at startup. See the geth doc for the full
architecture — it applies verbatim here.

**ethstats: inherited unchanged.** `ethstats/ethstats.go` is the same WebSocket push-telemetry
reporter (node/block/pending stats to a netstats dashboard), including the same placeholder
`Client: "0.1.1"` and `Uptime: 100` legacy fields.

**OpenRPC discovery: the core-geth (ETC Labs) addition.** core-geth adds a service-discovery /
API-introspection endpoint that upstream geth does not ship — `node/openrpc.go`, an
`RPCDiscoveryService` whose `Discover()` method (exposed as the `rpc_discover` JSON-RPC method)
returns a machine-readable **OpenRPC document** describing the node's entire RPC surface,
generated by reflection. This is an ETC-Labs-specific observability/introspection capability.

## Key types / interfaces / files

**Metrics library (inherited — older gate form):**
- `metrics/FORK.md:1` — same fork of `rcrowley/go-metrics` at `e181e09`.
- `metrics/metrics.go:25` — **the notable diff: `var Enabled = false`** (a plain bool
  kill-switch) plus `var EnabledExpensive = false`, gated by `Init()` and CLI flag `metrics` /
  env `GETH_METRICS` (`metrics.go:32-45`). This is the *older* go-metrics gate form; current
  geth refactored to `Enabled()` / `Enable()` **functions**. Same intent (near-zero cost when
  off, one-way enable at startup), different surface.
- `metrics/registry.go` — same `Registry` interface + `GetOrRegister*` idempotent registration.
- Exporters present and unchanged: `metrics/prometheus/{prometheus.go,collector.go}`,
  `metrics/exp/exp.go` (`/debug/metrics` + `/debug/metrics/prometheus`),
  `metrics/influxdb/{influxdbv1.go,influxdbv2.go}`, plus `opentsdb.go`, `syslog.go`,
  `graphite.go`, `librato/`.
- `cmd/utils/flags.go:1002` `MetricsEnabledFlag` (`--metrics`), `:1030+` the
  `--metrics.influxdb*` / `:1095+` `--metrics.influxdbv2*` flag block — same wiring as geth.

**ethstats (inherited):**
- `ethstats/ethstats.go:84` `Service`, `:501` `Client: "0.1.1"`, `:828` `Uptime: 100` — same
  placeholders/legacy values as geth; don't trust them as real telemetry.

**OpenRPC (core-geth-specific):**
- `node/openrpc.go:31-37` — `RPCDiscoveryService` and `func (r *RPCDiscoveryService)
  Discover() (*meta_schema.OpenrpcDocument, error)` — reflection-driven OpenRPC document
  generator, wired as the `rpc_discover` method.
- Depends on the ETC-Labs stack: `github.com/etclabscore/go-openrpc-reflect` and
  `github.com/open-rpc/meta-schema` (imports at `node/openrpc.go:18,26`).
- `docs/JSON-RPC-API/openrpc.md` — the checked-in, generated OpenRPC service description for
  the ETC RPC surface.

## Design decisions & rationale

- **Metrics/ethstats inherited because they are chain-agnostic.** The registry+exporter model
  and the netstats reporter carry no ETC assumptions, so core-geth took them wholesale; the
  only diff is vintage (older `var Enabled` gate).
- **OpenRPC as a first-class discovery method** reflects the ETC-Labs emphasis on
  machine-discoverable, standards-described RPC — `rpc_discover` lets tooling introspect the
  node's exact method set/types without out-of-band docs. This is core-geth's distinctive
  observability/introspection contribution over upstream geth.

## Notable patterns (the reusable idea)

Same load-bearing pattern as geth: **a backend-agnostic in-house metrics registry with
`GetOrRegister(name)` + pluggable exporters**, near-free when disabled. The core-geth-specific
reusable idea: **reflection-generated OpenRPC service discovery** (`rpc_discover`) — a node
that can describe its own RPC contract as a standard machine-readable document, valuable for
tooling/monitoring integration. For a JVM successor, both come cheaply from the ecosystem: a
Micrometer/Dropwizard Prometheus registry for the metrics plane, and an OpenRPC document
generator for discovery.

## Authority note

For observability, go-ethereum is the authority for the metrics-library + pluggable-exporter
architecture and for ethstats — core-geth is a strict, older-vintage inheritor and adds
nothing there except an earlier gate form. core-geth *is* the reference for the **ETC-Labs
OpenRPC discovery** (`node/openrpc.go`, `rpc_discover`), which upstream geth does not ship.
Contrast for cross-referencing: nethermind/reth do **not** fork a metrics library — they use
off-the-shelf Prometheus client libs (increasingly OTLP/OpenTelemetry) with a conventional
`/metrics` scrape endpoint.

## Gotchas / anti-patterns / things they later changed

- **Older enable gate.** core-geth uses `var Enabled bool` + `Init()`, not geth's later
  `Enabled()`/`Enable()` functions — same one-way-at-startup constraint (a late enable misses
  early metrics), different API. Cross-referencing geth code line-for-line will mismatch here.
- **ethstats placeholders.** `Client: "0.1.1"` and `Uptime: 100` are hardcoded legacy netstats
  fields, inherited as-is — not real node metadata.
- **Exposure risk inherited.** metrics/expvar and pprof endpoints default to `127.0.0.1`
  because `/debug/pprof` and `/debug/vars` leak internal state; the OpenRPC `rpc_discover`
  method likewise advertises the full RPC surface — mind what namespaces are exposed on an
  untrusted interface.
- **Forked-library drift.** As with geth, `metrics/` is a hard fork frozen at rcrowley
  `e181e09`; core-geth froze it at an even earlier internal state than current geth (`var
  Enabled` rather than the function-based gate) — a consumer copying the pattern maintains the
  library, it does not track an upstream dependency.
- **OpenRPC dependency surface.** `node/openrpc.go` pulls the ETC-Labs `go-openrpc-reflect` and
  `open-rpc/meta-schema` modules — extra third-party dependencies specific to this feature that
  a JVM reimplementation would replace rather than port.
