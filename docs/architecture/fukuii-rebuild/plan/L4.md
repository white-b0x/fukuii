## 1. Scope & modules

**Module:** `execution` · **package:** `com.chipprbots.fukuii.execution.*` · **depends on:** `evm`,
`trie`, `storage`, `domain` (down-only). **MUST NOT depend on `consensus`** — this inverts the old
`ledger ↔ consensus` cycle (Phase-3 finding): **consensus (L5) calls execution**, never the reverse.
An upward edge to `consensus` is a **compile error** — that is the structural fix.

What the layer builds — the single-block execution pipeline, family-agnostic above one economics
seam:

- **Block execution** — the per-block apply order (besu-canonical): pre-execution system calls → the
  tx-apply loop → withdrawals (EIP-4895) → post-execution request system calls (6110/7002/7251) → the
  reward/finalize seam → state commitment. The reward is the **last** state mutation before commitment
  (besu `AbstractBlockProcessor` withdrawals `:419` → requests `:443` → `rewardCoinbase` `:485` →
  `persist` `:532`). This order is currently **inert** — PoW has a nonzero reward but no
  withdrawals/requests, PoS has withdrawals/requests but a zero reward, so the two never both mutate
  state in one block — but it is the reference order and the safe one (it would become a real
  state-root divergence if a future family ever had both a nonzero reward and withdrawals).
- **Transaction processing** — the per-tx engine: upfront gas deduction, EIP-7702 authorizations,
  VM run (into L3), refund cap (EIP-3529), EIP-7623 floor, tip-vs-base-fee settlement, account
  cleanup.
- **Receipt generation** — EIP-658 typed receipts per tx type, bloom, receipts-root.
- **Rewards** — **ECIP-1017 era emission** (the ETC byte-authority target) and the **ECIP-1111**
  base-fee-floor/treasury credit (ETC Olympia); the **EIP-1559 base-fee burn / tip split** (ETH).
- **Withdrawals (EIP-4895)** and the **EIP-7685 request** phases (EIP-7002/7251 system calls,
  EIP-6110 deposit log-scrape) for the ETH path.
- **A per-block execution outcome** — the block + a serializable state-diff (besu `BonsaiTrieLog`
  `{prior,updated}` leaf-diff shape) that L5's branch-import driver aggregates into the reorg-aware
  `ChainNotification` event source (L5 owns reorg authority; L4 owns the state-diff computation). The
  R7 gRPC seam carries L5's aggregate, not L4's per-block outcome (§4, §7, §"Layer boundaries").
- One executor serving **both verify and produce** (import, miner produce, PoS proposer build).

Out of scope (lives elsewhere — see §"Layer boundaries"): engine selection, sealing, block
production *policy*, Engine-API driver, and **MESS / ECIP-1100 subjective fork-choice** (all
`consensus` L5 — MESS relocates *up* out of the ledger package); the opcode/gas machine (`evm` L3);
world-state persistence (`trie`/`storage` L2).

## 2. SR slots & verdicts (binding)

Governing slot: **`observations/block-execution.md`**. Cross-ref: `observations/consensus-engines.md`
(engine selection / merge-decorator — owned by L5, not re-litigated here). The verdicts to honor,
quoted:

1. **Family-agnostic executor + reward/finalize as the SOLE economics seam** — *"One narrow interface
   method is the entire boundary between 'execute EVM transactions' (family-agnostic) and 'apply
   consensus economics' (family-specific) … ETC's ECIP-1017 emission goes exactly where ETH's
   withdrawals go, so the ETC/ETH split needs no `if(isPoW)` anywhere in the pipeline."* → **DEFAULT.**
   The single most load-bearing verdict for this layer. **R1/R3:** the reward is a per-family hook
   selected by the fork bundle, never a branch.

2. **Immutable per-fork `ProtocolSpec` bundle (besu)** — *"Replace 'mid-execution
   `EvmConfig.forBlock(...)` + branch' with 'hand the loop a fully-resolved immutable per-fork
   bundle.' Build once at startup, look up by header … the reward is just one field of the bundle."*
   → **DEFAULT (for the fork-collaborator bundling).** This is the layer's chief AS-IS gap to close,
   and it **wraps L3's `EvmConfig` so the fork is resolved ONCE** (§2.1, §6).

3. **One executor serves both verify and produce (reth/besu)** — *"production and validation cannot
   diverge."* → **DEFAULT.** AS-IS already aligns (`BlockPreparator` backs both) — preserve it.

4. **Two-phase system calls bracketing the tx loop; besu `RequestType`→processor map** — *"`PreExecution`
   (4788/2935) before txs; `PostExecution` (7002/7251/6110) after … besu's data-driven `RequestType`
   → processor map (with `noOp()` degradation) is the cleanest form."* → **DEFAULT.** Adopt the
   `RequestType` registry (AS-IS hard-codes the loop — §6).

5. **Per-block merge decorator (nethermind `MergeRewardCalculator`)** — *"decide the reward per block
   via an `IsPostMerge`-style predicate … correct across cross-boundary reorgs."* → **DEFAULT-adjacent
   (the per-block-transition principle).** Inert for ETC (permanently PoW); the ETH path binds the
   reward per block, never "set a boolean once." **fukuii already satisfies this principle** without a
   decorator object — the reward reads `header.isPoS` *per block* (§6, §9).

6. **ECIP-1017 era reward** — *"It IS ETC consensus — non-negotiable … byte-exact: era index off-by-one
   `(blockNum-1) mod eraLength`, separate integer exponentiation of `4^era` and `5^era`, Era-0-vs-Era-≥1
   uncle formula switch."* → **DEFAULT (non-negotiable).** **core-geth is the SOLE living byte-authority.**
   The AS-IS `BigDecimal.precision` reduction-rate derivation is the top correctness fix (§6, §9).
   **Clarification (both authorities):** the era index is integer **DIVISION** — `era =
   (blockNum-1)/eraLength` (as §5 states) — not `mod`; the `mod eraLength` in the quoted verdict is the
   intra-era *remainder* (an intermediate core-geth computes en route to the division), and besu-etc
   drops core-geth's `mod 1` no-op entirely and returns the division directly.

7. **Parallel Block-STM exec3 (erigon)** → **OPTIONAL(archival/perf role).** Deferred — two
   byte-identical paths, hard conflict-detection edges, experimental at tip; not for a validating/
   mining node. Distinct from the *lighter* nethermind prewarming split (§7).

8. **Queue-driven async processing (nethermind)** → **OPTIONAL(Engine-API-latency role).** Deferred —
   heavy thread-static machinery; adopt only if PoS `NewPayload` latency is a named goal. The
   **prewarming + parallel post-loop** half is a separate, lighter OPTIONAL (§7).

**Authority caveat (non-negotiable):** the family-agnostic-executor DEFAULT validates *keeping ETC/ETH
reward on one seam* — but the ETC reward *value* is reproduced byte-for-byte from core-geth, never
from geth/reth/erigon/besu (whose reward code is vanilla-ETH or ETC-removed). besu = structural
reference for ETC, never behavioral.

### 2.1 The L3↔L4 seam — `ProtocolSpec` wraps `EvmConfig`, fork resolved ONCE

The load-bearing seam between the two layers, and the AS-IS's largest structural gap. The AS-IS
re-derives `EvmConfig.forBlock(...)` at **6+ use-sites mid-execution** (`BlockExecution.scala:151`,
`BlockPreparator.scala:226/252/373/413/476`) plus scattered `forkBlockNumbers.*`/`isXTimestamp(...)`
inline predicates. The fix:

- **L3 (§2.1 of L3.md) collapses fork resolution into one `forBlock(header, schedule)`.** L4's
  `ProtocolSpec` bundle **wraps that single resolution** — the fork is resolved **once** at bundle
  build (keyed by header), and *both* L3's opcode/gas config *and* L4's fork-varying collaborators
  (reward scheme, system-call processors, validators, the base-fee handling) come from the **one**
  resolution. The contract is directional: **L3 exposes `forBlock(header, schedule)` returning a value
  the L4 bundle can *hold*, not a factory L4 re-invokes** — the bundle holds the resolved config and
  never re-resolves. **Scope the bundle to fukuii's actually-varying collaborators** (EvmConfig, reward
  scheme, system-call processors, validators, fee/base-fee handling), not besu's full ~30-field
  `ProtocolSpec` — many besu fields (BAL, blob-gas, EIP-7778 dual-gas) are ETH-future the two current
  families do not vary.
- **Why "once" matters:** if L3 resolves the fork (for the VM) *and* L4 re-resolves it (for rewards/
  system-calls), that is **two resolutions of the same fork** — the exact "ask `EvmConfig.forBlock(...)`
  mid-execution and branch" shape besu's `ProtocolSpec` eliminates. Resolve once, hand the loop the
  bundle, call methods on it. Adding a fork = one definition + one milestone entry; the loop never rots.

## 4. besu structural mirror

Concrete besu shapes to follow (read alongside geth's Go), under `clients/besu/ethereum/core/…`:

- **`AbstractBlockProcessor.processBlock()` — a fork-agnostic loop reading all behavior off a per-fork
  bundle**, with **`rewardCoinbase` as the one abstract method** of an otherwise concrete loop. PoS
  sets `blockReward = Wei.ZERO, skipZeroBlockRewards = true`. This is the exact "family-agnostic
  executor, single economics seam" shape — the reward is the only thing the loop delegates.
- **`ProtocolSpec` immutable per-fork value object, built once, looked up by header** —
  `ProtocolSpecBuilder` + `MainnetProtocolSpecs` (`shanghaiDefinition` calls `parisDefinition`,
  mutates the delta) + `milestones/` for the `MilestoneType` (block-number vs timestamp) dispatch.
  ~30 fork-varying collaborators bundled; the loop is *handed* a resolved bundle and calls methods on
  it — replaces "ask `EvmConfig.forBlock(...)` mid-execution and branch." **The bundle wraps L3's
  resolved `EvmConfig`** (§2.1), so there is one fork resolution, not two.
- **`MainnetTransactionProcessor`** — the per-tx engine (upfront deduction, VM run, refund, receipt),
  the structural mirror for fukuii's tx-apply body.
- **`RequestProcessorCoordinator` = `RequestType`→processor map** — `SystemCallRequestProcessor` (the
  reusable "call a system contract, wrap output as a `Request`" primitive) + `DepositRequestProcessor`
  (the EIP-6110 log-scrape), with `noOp()` degradation for pre-Prague/PoW. The data-driven form that
  replaces the AS-IS hard-coded loop.
- **One `ProtocolSpec` behind both `MainnetBlockValidator` (import) and the block-creation path
  (produce)** — `getForNextBlockHeader` gives the producer the next spec. The shared-executor
  guarantee.
- **Per-block state-diff — besu `BonsaiTrieLog` as the *diff-content* reference (payload wire-shape is
  PROVISIONAL, `coherence-pass-02` WB-R2).** besu's `BonsaiTrieLog{prior,updated}` per-account/slot diff
  is a good structural reference for the diff *content* (fukuii's node-refcount snapshots are not, per
  `optimizations.md` L2) — but its **on-disk/wire shape is NOT settled here.** besu's `TrieLog` is
  **Bonsai-path-based-tree-specific**; fukuii (RocksDB/MPT-inline) must map it or make it
  **storage-agnostic**, and the out-of-process contract must be **version-less-additive** (nethermind
  positional-RLP "absent = zero") — the two SR caveats (`exec-extensions.md`) this must carry. **L9 holds
  the payload wire contract OPEN** (`L9.md`), so L4 must NOT freeze `MutationReason` + the diff type as
  public API until the **joint L4/L5/L9 WB-R2 review** fixes the payload contract once. **L4 owns computing
  the per-block state-diff** (state mutation happens in execution) and hands each block's outcome
  (`BlockExecutionOutcome`) up to L5's branch-import driver. **L5 owns the reorg-aware event source** —
  it aggregates L4's per-block outcomes with its own fork-choice/reorg decisions into the reth-ExEx
  `ChainNotification` segment stream (`{reverted, committed}`), with the `FinishedHeight` prune barrier
  and WAL restart-safety. The transport (L9 grpc-seam) and the `FinishedHeight`-gated pruning (L2) live
  above/below (§7). L4 does **not** define the wire `ChainNotification` — that is L5's (L5 decides
  reorgs; L4 only executes blocks).

**Note the `FinalizeAndAssemble` finding (dead-code review).** current geth removed
`Engine.FinalizeAndAssemble` (assembly is now the free function `AssembleBlock`); **core-geth still has
it** (Mantis-era shape). fukuii's AS-IS already has *no* distinct finalize-and-assemble method —
production reuses `payBlockReward` + `persistState` through `prepareBlock`/`executeForProposer`. Keep
the **single `finalize` seam**; do not reintroduce the Mantis extra method.

## 5. Scala 3 idiom targets

- **Per-fork bundle as an immutable `given` value object — the besu `ProtocolSpec` analog.** Build a
  `ProtocolSpec` case class (the L3 `EvmConfig` from the single `forBlock(header, schedule)` resolution,
  reward scheme, system-call processors, validators) **once per fork**, resolve it by header, hand the
  loop the resolved bundle. The executor references it; no `EvmConfig.forBlock(...)` call mid-execution,
  no scattered `forkBlockNumbers.*` predicates. **R2:** the bundle is immutable and per-instance-threaded
  (no process-global execution state — no `object … { var … }`).
- **The reward/finalize seam declared *in* execution, implementation injected — this is what breaks
  the cycle.** A `sealed trait RewardScheme` (or `FinalizeHook`) lives in `execution`; the fork
  bundle carries the resolved instance (`Ecip1017RewardScheme` for PoW, `PosNoRewardScheme` for PoS).
  The reward *math* (ECIP-1017 era emission, ECIP-1111 treasury) is consensus-critical code that
  **lives in the `execution` module** (target-arch: "L4 execution → rewards (ECIP-1017)") and is
  selected by config/bundle — **not** imported from `consensus`. consensus (L5) drives fork-choice
  and calls `execution.processBlock`; it does not supply the reward math. **The scheme selection must
  fail LOUD** (§6) — nethermind's quiet-zero-reward path is the trap `fail-loud-invariants.md` bans.
- **`RequestType` enum + a `given` `Map[RequestType, RequestProcessor]`** (besu data-driven) —
  `enum RequestType { case Deposit; case Withdrawal; case Consolidation }`, each mapped to its
  processor; `noOp` for the PoW/pre-Prague path. Replaces the AS-IS hard-coded `processPragueSystemCalls`
  loop. **Adopt besu's fail-loud construction idiom:** an empty processor map is reachable **only** via
  an explicit `RequestProcessors.noOp`, never a silent empty `Map()` — besu's
  `RequestProcessorCoordinator.build()` throws on an accidental empty map (`:66-73`), so you cannot get
  a degraded coordinator by accident; the degraded path is the named `noOp()` factory only (consistent
  with fail-LOUD, §6).
- **Two-phase system calls as explicit phases** — `PreExecution(4788, 2935)` before the tx loop,
  `PostExecution(withdrawals, 7002, 7251, 6110)` after — modelled as pseudo-txs with the
  `SystemAddress` sender and the fixed 30M budget. **The post-phase order is a deliberate pick of besu's
  `withdrawals → requests → reward` sequence** (matching the single-block-processor JVM structure fukuii
  mirrors), not left ambiguous: go-ethereum instead runs requests in `PostExecution` then
  withdrawals+reward in `Engine.Finalize`, so the two references genuinely differ in internal order. The
  orderings are **state-root-commutative** for the current two families (withdrawals credit validator
  balances; requests act on disjoint queue-contract state on the ETH path; the ETC path binds `noOp`),
  so either yields the same root today — but the pick is besu's, deliberately.
- **Receipts typed by `enum TxType`** (Legacy / Type01–04) — EIP-658 status receipts.
- **Immutable per-call `SimulationOptions`** threaded through the tx engine — replaces the AS-IS
  `@volatile` mutable simulation flags on the preparator (§6). This is an **L4→L3 API change, not a
  local L4 cleanup:** removing the mutable global flag means L3's `precompileRelocations` must accept
  `SimulationOptions` as a **parameter** (L3 §6 Chesterton-review) rather than reading a mutable global.
- **A per-block execution outcome** (R5 effect discipline; the L4 half of the R7 seam) —
  `enum BlockExecutionOutcome { case Executed(block, stateDiff); case RolledBack(block) }` produced per
  executed block, where `stateDiff` is the besu-`BonsaiTrieLog`-shaped serializable leaf-diff L4
  computes. **Each mutation in the diff carries a typed `enum MutationReason { case Reward; case
  FeeBurn; case Transfer; case SystemCall; … }` (geth `Hooks` shape) — L4 owns this type** (the reason
  is known only at the point of state transition, which is execution's job); L9's `grpc-seam` imports it
  *from* `execution` to tag the notification payload (`L9.md §5`); tagging is ~free when no consumer is
  attached because the hooked state wrapper is **not installed** (geth `state_processor.go:77` +
  per-hook nil-guards `statedb_hooked.go:44,168` — geth has **no `HasHook()` symbol**), not a
  per-mutation branch. L5's branch-import driver consumes
  these outcomes and emits the reorg-aware wire ADT
  (`ChainNotification`, reth 3-case segment shape — **defined in `consensus-api`, not here**, §"Layer
  boundaries"). L4 hands outcomes up to L5; it does not itself decide reorgs or own the segment-level
  wire type. Not ad-hoc synchronous callbacks (the besu limitation ExEx improves on).
- **ECIP-1017 era math as explicit integer arithmetic** — `(blockNumber - 1) / eraDuration` for the
  era index, **separate integer `4^era` and `5^era` before multiply-divide** (core-geth's exact
  form), the Era-0-vs-≥1 uncle/nephew formula switch — **not** a `BigDecimal.precision` derivation of
  the 4/5 ratio (§6, the byte-critical divisor).

## 9. Risks & consensus-critical flags

**All reward/economics and state-commitment code in L4 is byte-exact / consensus-critical** — `forge`
(PoW/ETC) + `beacon` (PoS/ETH) gate, with `banksy` a required consult on ECIP-1111. Every reward-value,
gas-accounting, and commitment change routes through the Consensus-Critical Change Protocol
(state-root litmus). Specific traps:

- **ECIP-1017 era math byte-exactness (core-geth SOLE frozen authority; besu-etc a second cross-check)
  — the top correctness item.** The era index off-by-one — integer **DIVISION** `era =
  (blockNumber-1)/eraLength`, **not** `mod` (the intra-era remainder is only an intermediate) — the
  **separate integer exponentiation** of `4^era` and `5^era` before multiply-divide, and the
  Era-0-vs-Era-≥1 uncle/nephew formula switch are each individually byte-critical. Reproduce from
  core-geth `rewards_classic.go`, never a prose spec, never *currently-shipping*
  geth/reth/erigon/besu (vanilla-ETH or ETC-removed). **Second authority (operator directive):** besu's
  own pre-removal ETC — `besu-etc` `ClassicBlockProcessor.java` (commit `eb4248c997`) — agrees
  byte-for-byte (integer division; `BigInteger.pow`/`divide` = Go `big.Int.Exp`/`Div`, both
  truncate-toward-zero; base `Wei.fromEth(5)`) and is the strongest available cross-check; validate
  against **both**. The AS-IS `BigDecimal.precision` reduction-rate derivation is replaced with explicit
  integers (§6) — reconstructing 4/5 from a floating config value is the byte-exactness hazard.
- **One canonical divided-reward form + the divisibility rationale (two-authority finding).** core-geth
  and besu-etc use algebraically-equal but arithmetically-**different** formula shapes for the two
  divided rewards — era-0 uncle: core-geth `(uncleNum+8−headerNum)·R/8` (mul-then-div) vs besu-etc
  `R − R·distance/8` (subtract); nephew: core-geth `R + ommers·⌊R/32⌋` vs besu-etc `R + ⌊R·ommers/32⌋`
  (mul-then-div-once). They coincide byte-for-byte **only because the canonical era reward
  `R = 2^(18+2·era)·5^(19−era)` is divisible by 8 and 32.** fukuii must **pick one canonical form —
  core-geth's mul-then-div** (core-geth is the frozen spec authority) — and record *why* the shapes
  coincide, so a future custom-network base reward that is **not** divisible by 8/32 cannot silently
  take the 1-wei-diverging path. Resolved: **no divergence on ETC; latent divergence off-canonical.**
- **The reward seam must stay family-agnostic — no `if(isPoW)` in the apply loop, and selection fails
  LOUD.** ETC's ECIP-1017 emission goes in exactly the slot ETH's withdrawals go; the family split is
  *which `RewardScheme` is bound at the seam*, not a branch scattered through the pipeline. An
  unresolved/mismatched scheme `sys.error`s (`fail-loud-invariants.md`) — never nethermind's quiet
  zero-reward. The reward reads `header.isPoS` **per block**, which is the merge-correctness guarantee
  across cross-boundary reorgs (nethermind's `MergeRewardCalculator` principle, satisfied without a
  decorator). Withdrawals apply *outside* the reward seam (never double-credited with issuance). On the
  PoS path the seam carries `blockReward = ZERO` **and `skipZeroBlockRewards = true`**: the zero-reward
  short-circuit is not cosmetic — it prevents a spurious empty-coinbase `addBalance(0)` that would dirty
  an account and shift the state root (besu `AbstractBlockProcessor:485` threads the flag through to the
  one abstract method).
- **The `ledger ↔ consensus` inversion is the load-bearing DAG fix.** The reward-scheme trait lives in
  `execution`; consensus calls down. An upward `import consensus.*` is a compile error — do not
  reintroduce it to "reach" the engine (the AS-IS back-edge). MESS/`BranchResolution` moves up to L5,
  not down here.
- **EIP-1559 burn (ETH) vs ECIP-1111 base-fee-floor/treasury (ETC) diverge at the base-fee handling.**
  ETH burns the base fee; ETC routes it to the treasury with a floor. ECIP-1111 is fukuii's own work
  (no ref-client equivalent) — **`forge` owns it, `banksy` must be consulted** because it defines the
  network security-budget economics ECIP-1122's tip floor is sized against.
- **Withdrawals hard-rejected on ETC.** The ETC path must **not** silently apply EIP-4895 withdrawals
  or any post-Merge request call (core-geth rejects them). The `RequestType` map degrades to `noOp` on
  the PoW path.
- **Atomic block+weight write.** A crash between the block-data write and the chain-weight write leaves
  the DB inconsistent → wrong fork choice on restart (AP-9 / BUG-W7). Write both in the **same** storage
  batch (`error-recovery.md` §6). This is a durability-correctness flag on the multi-block driver.
- **Dual fork clock kept distinct.** The axis-tagged `ForkActivation` (L3) feeds the bundle build once;
  do not conflate the axes into one flat struct at L4 any more than at L3, and do not re-resolve the
  fork mid-execution (§2.1).
- **R2 — no process-global execution state.** No mutable statics / `@volatile` instance flags threaded
  into `runVM`; per-call `SimulationOptions`, per-instance bundle. Two `ChainInstance`s in one binary
  must not share mutable execution state.
- **Parallel/async execution are perf-role seeds, not baseline.** exec3 Block-STM (two byte-identical
  paths, hard conflict edges) and queue-driven async (thread-static global state) are OPTIONAL(role);
  the lighter nethermind prewarming/parallel-post-loop split is a separate perf OPTIONAL. A
  correctness-first baseline executor is serial with per-tx commitment.

## Layer boundaries (what lives elsewhere, and why)

_Durable placement — not build-status (see the README index)._

- **Engine selection, sealing, block-production policy, Engine-API driver, MESS / ECIP-1100
  fork-choice** → **`consensus` (L5)**. L4 executes and rewards a block; *which* block to build on and
  *whether* to reorg is L5. MESS relocates *up* out of the old ledger package. consensus calls
  `execution.processBlock` — never the reverse.
- **Transaction selection / ordering, tip & gas-target floors (ECIP-1122)** → **client-layer policy
  (`banksy`, L8 txpool + L5 production)**. L4 applies the txs it is handed; it does not choose or
  order them. ECIP-1111's *economics* are forge-owned execution code, but the *policy* floors sized
  against them are banksy's.
- **The reorg-aware event source (`ChainNotification`) + its gRPC/dRPC transport + the `FinishedHeight`
  prune barrier** → **L5 (consensus-api owns the ADT) + L9 (grpc-seam transport) + L2 (pruning)**. L4
  *emits per-block `BlockExecutionOutcome`s* (block + state-diff) up to L5's branch-import driver; **L5
  owns the reorg-aware `ChainNotification` wire ADT** (it decides reorgs); L9 carries L5's notifications
  over gRPC to consumers and L2 gates pruning on `min(consumer heights)`. L4 owns the state-diff
  computation, not the reorg segmentation.
- **Opcode/gas machine, precompiles** → **`evm` (L3)**. L4 drives the VM per tx; it does not define
  opcodes or gas costs. The fork is resolved **once** at L3 (`forBlock(header, schedule)`) and the L4
  bundle wraps it (§2.1).
- **World-state persistence / MPT** → **`trie`/`storage` (L2)**, reached through the `WorldStateProxy`
  seam. L4 computes the state root via `persistState`; it does not own the trie or RocksDB.
- **RLP trailing-optional-omission + typed-tx (EIP-2718) aggregation** → **`domain` (L1)** DoD. L4 is
  a consumer of the fork-variant `BlockHeader`/`Transaction` types, not their definer.
