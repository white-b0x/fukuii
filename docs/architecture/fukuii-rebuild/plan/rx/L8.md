- **fukuii `july-fourth`:** `PendingTransactionsManager.validateAgainstState` = "3 sequential `Set.filter` stages"

- **Reference source (byte-cited):**

  - go-ethereum `core/txpool/validation.go:57-63` — `ValidateTransaction` is the shared **stateless** rule set, explicitly "does not check state-dependent validation," a public helper "to allow different transaction pools to check the basic rules without duplicating code"; `ValidateTransactionWithState:245` is the stateful half.

- **Verdict:** CONFIRMS.

- **Verdict:** CONFIRMS. (Draft-spec design confirmed sound against geth `MinTip` / core-geth `TxPoolPriceLimit`; no spec-edit proposal. Ordering composition remains a banksy+forge co-sign, already flagged.)

### RX-L8-20 · Keystore MAC uses the L0 `constantTimeEquals` primitive, not `==` · Tier A (R11 floor) · owner-layer L8
- **Plan claim / disposition:** DEFAULT(R11) — the keystore MAC uses the L0 `constantTimeEquals`
  primitive, never `==`; `L8.md §6/§9` frames the `july-fourth` `==`-MAC as "a real timing finding."
- **fukuii `july-fourth`:** `decrypt` MAC-gates with `createMac(dk, ct) == mac` (`fukuii/accounts-signer.md:42`) —
  Scala `ByteString` structural `==`, not constant-time.
- **Reference source (byte-cited):**
  - **go-ethereum `accounts/keystore/passphrase.go:268`** — `if !bytes.Equal(calculatedMAC, mac) { return ErrDecrypt }` — the byte-authority's own keystore MAC check is **`bytes.Equal`, i.e. NON-constant-time** (also `:322` for V1). geth does **not** use a constant-time compare on the keystore MAC.
  - besu **does** have a constant-time primitive — `ethereum/p2p/.../ecies/ECIESEncryptionEngine.java:276 if (!Arrays.constantTimeAreEqual(T1, T2))` — but it uses it for the **ECIES handshake auth-tag**, not for any Web3-keystore MAC (besu uses `SecurityModule`, no v3-decrypt MAC path).
  - L0 authority for the primitive: BouncyCastle `Arrays.constantTimeAreEqual` (as besu uses).
- **Q1 appropriate decision?** Adopt the primitive: **yes** — it's free, and R11's L0 `constantTimeEquals` is genuinely required for the ECIES-tag and Engine-API-JWT sites where a server holds a secret expected value. Using it uniformly (incl. the keystore MAC) is sound consistency.
- **Q2 what we should implement?** Yes — call `constantTimeEquals` on the MAC. **But the rationale is over-stated.** For the *keystore-decrypt* MAC specifically, the threat model is weak: the attacker who mounts the timing attack already **possesses both operands** (the stored `mac` is in the keyfile they hold, and `calculatedMAC` is computed from their own password guess). A timing oracle here leaks nothing they don't already have — which is why geth ships `bytes.Equal`. So this is **defense-in-depth / consistency**, not "a real [exploitable] timing finding."
- **Q3 understanding + blast radius correct?** Mechanism correct; the **characterization** is wrong (Q3 understanding "no"). The live, genuinely timing-critical constant-time sites are **ECIES-tag (L6, besu `:276`)** and **Engine-API JWT / MCP-OAuth HMAC (L9)** — where a secret expected value is server-held. Blast radius: the L0 primitive (downward dep) feeds L6/L9, not just L8.
- **Q4 correct answer + why:** Keep the `constantTimeEquals`-on-MAC adoption (free, consistent, and the primitive must exist for L6/L9 regardless), but reframe the keystore-MAC use as **defense-in-depth/consistency**, and relocate the "real timing finding" language to the sites that actually hold a secret (ECIES-tag, JWT/OAuth HMAC). Source: geth `passphrase.go:268` ships non-CT `bytes.Equal`; besu reserves `constantTimeAreEqual` for the ECIES tag (`:276`).
- **Verdict:** SHARPENS.
- **Plan edit:** §6/§9 — change "the `==`-MAC is a real timing finding" to "the `july-fourth` `==`-MAC is hardened to `constantTimeEquals` for **consistency/defense-in-depth** (go-ethereum itself uses non-constant-time `bytes.Equal` on the keystore MAC, `passphrase.go:268`, because the attacker holds both operands); the **exploitable** constant-time sites are the ECIES handshake tag (L6, besu `ECIESEncryptionEngine:276`) and the Engine-API JWT / MCP-OAuth HMAC (L9, R11), where a secret expected value is server-held." The L0-primitive-must-exist-first dependency (§9) is unchanged and correct.
