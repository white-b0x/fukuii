# Observations — storage-persistence
_Phase-2 synthesis 2026-07-13. Sources: the 6 {client}/storage-persistence.md docs + initial-assessment §1d._

|---|---|---|---|---|---|---|---|

## Approach catalog (use-case-aware — the point of the exercise)
| Approach | Clients using it | Good for (use-case / node-role) | Verdict | Why |
|---|---|---|---|---|
| **RocksDB + column families** (namespace/enum/segment) | besu, nethermind, **fukuii** | All roles; enterprise · multi-network | **DEFAULT** | Per-dataset independent tuning (cache, compression, BlobDB, GC) impossible in a single keyspace; the dominant JVM/CLR pattern and fukuii's existing shape |
| **Single-keyspace LSM + byte-prefixes + freezer** | go-ethereum, core-geth | ETH/PoS baseline; disk-constrained (freezer) | **OBSOLETE** (as fukuii's *primary* model) | Can't express per-dataset tuning; fukuii already moved past it to CFs. The **freezer/cold-tier idea** is separately valuable (see below) |
| **MDBX + real tables/DupSort + flat** | erigon, reth (primary) | Smallest-disk archival; data-serving | **OPTIONAL(archival/data-serving)** — long-term only | No mature JVM MDBX binding; COW-B+tree assumptions don't map onto RocksDB's LSM. A genuine re-architecture, not a swap |
| **Hash-keyed trie-node store** (content-addressed, archival) | besu Forest, nethermind Hash, geth hashdb, **fukuii** | **archival/data-serving+RPC**; historical-state queries | **OPTIONAL(archival)** | Node dedup across versions + full historical trie; unbounded disk + heavy GC. fukuii's current `ArchiveNodeStorage`/`ReferenceCountNodeStorage` |
| **Path/nibble-keyed trie nodes** (locality) | geth pathdb, nethermind HalfPath (default), reth nibble-path | **full/pruned** nodes; block-processing hot path | **DEFAULT-candidate** | Update locality (one path = one write, no hash-recompute cascade), better block-cache hit rate; bounded disk. The direction all three converged on |
| **Bonsai-style flat state + thin proof trie + trie-log diff journal** | besu Bonsai, nethermind `State.Flat`, reth (partial) | **light/end-user**; pruned full nodes; fast state reads | **OPTIONAL(end-user/pruned)** | Flat reads without a trie walk + retained proofs; bounded reorg window via trie-log. besu is fukuii's closest structural target here (fukuii already has `FlatAccountStorage`/`FlatSlotStorage`) |
| **Fully flat Domains, zero leaf trie** (commitment on demand) | erigon | archival with minimal disk | **OPTIONAL(archival)** — aspirational | Smallest footprint, no leaf-node store at all; but MDBX-coupled and re-org-window is a *correctness* parameter. Furthest from fukuii |
| **Online full-pruning** (copy-live-to-fresh-DB + atomic swap) | nethermind | **CEX/custody · light/end-user** (reclaim disk without resync) | **OPTIONAL(custody/end-user)** | Live-traffic-safe disk reclamation; nethermind is the strongest authority. Neither besu nor fukuii offer a live path today |
| **Freezer / static-file cold tier** (append-only flat files) | geth freezer, erigon snapshots, reth static files | **archival · disk-constrained**; sequential-range reads | **OPTIONAL(archival/disk-constrained)** | Moves immutable finalized data off the hot engine (LSM/B+tree) → less write-amp, cheaper range reads. besu achieves the same via **BlobDB per-segment** without a second engine |
| **BlobDB per eligible segment** (large values outside LSM/SST) | besu | static/append-only segments (receipts, trie-logs) | **OPTIONAL(default-adjacent)** | RocksDB-native write-amp reduction for static CFs — the in-engine analogue of a freezer; directly applicable to fukuii's RocksDB CFs |
| **Explicit on-disk schema-version check** | besu (`DATABASE_METADATA`), erigon (per-file), reth (multi) | **all roles** — corruption/mismatch safety | **DEFAULT** | Makes "what schema is this datadir" a checked precondition, not an assumption. **fukuii has NONE** (confirmed gap) |
| **Live-tunable compaction profiles** | nethermind `ITunableDb` | bulk-sync phases (fast/SNAP) then steady-state | **OPTIONAL(sync-phase)** | Switch write-bias/compaction mid-sync via `SetOptions`, revert after — measured write-amp wins |
| **Dual key-scheme + live migration** | nethermind Hash↔HalfPath | datadirs migrating storage layout without resync | **OPTIONAL(migration)** | Try-current-scheme-then-fallback read path lets a scheme flip happen during a pruning pass; HalfPath→Hash unsafe (write-during-copy) |
| **Secondary storage engine for workload-mismatched tables** | reth (RocksDB alongside MDBX) | high-write-fanout indices | **OPTIONAL(niche)** | `OptimisticTransactionDB` so the side-store keeps the primary's transactional guarantees; adds a real cross-engine sync surface |

## Best-practice synthesis
fukuii is **RocksDB + CF-namespace-prefix + hash-keyed trie**; **besu is its closest storage authority** (both JVM, both RocksDB CFs, `Namespaces.scala` ↔ `SegmentIdentifier`). The default + options menu:

**DEFAULT per dimension:**
- **KV backend + segmentation:** keep **RocksDB + column families**. This is already best-practice and matches besu/nethermind. No change of engine.
- **Schema-versioning:** **adopt an explicit, persisted, checked schema-version** (besu `DATABASE_METADATA.json` + a `(format, version)` enum with per-bump rationale). This is the single most exportable pattern and fukuii's clearest gap.
- **Iterator/cursor safety:** **keep the L1 batched `unboundedScan`** — it already sits at the strong (erigon/reth transaction-owned) end of the spectrum, structurally more defensive than besu's own `Stream.onClose`. Optionally add a **live-iterator/leak metric** (geth's `liveIterGauge`) so leaks are observable, not just prevented.
- **Trie node keying:** the convergent best-practice is **path/locality-keyed** nodes (geth pathdb, nethermind HalfPath default, reth nibble-path). fukuii's hash-keyed store is the archival default; a path-keyed scheme is the block-processing-hot-path default worth offering.
- **Static-segment write-amp:** **BlobDB per static CF** (besu) is the in-engine, no-second-store way to get freezer-like benefits under fukuii's existing RocksDB.

**OPTIONAL modes worth offering (role each serves):**
- **Archival/data-serving+RPC** → hash-keyed full trie store (fukuii's current `ArchiveNodeStorage`) + a freezer/cold-tier or BlobDB for immutable history.
- **CEX/custody · light/end-user** → **online full-pruning** (nethermind copy-live-and-swap) to reclaim disk without a resync.
- **Light/end-user · pruned full nodes** → **Bonsai-style flat + thin proof trie + trie-log** (besu; fukuii already has the flat-storage overlay pieces).
- **Sync phases** → live-tunable compaction profiles (nethermind `ITunableDb`) for fast/SNAP then steady-state.
- **Layout migration** → dual key-scheme with live fallback-read migration (nethermind), if fukuii ever adds a second node-key scheme.
- **Not for fukuii (yet):** MDBX/flat-Domains (erigon) and reth's secondary-engine split — no mature JVM MDBX binding; both are re-architectures, filed as archival-role aspirations, not near-term modes.

## fukuii implications (forward-ref to Phase 3–4, do NOT act here)
Seeds for Phase 3, not verdicts:

- **Confirmed gap — no schema-version check.** fukuii has **no** `DATABASE_METADATA`-equivalent (§1e Phase-4 gap #3). besu/erigon/reth all guard against silent stale-layout reads; fukuii should adopt the besu datadir-wide `(format, version)` pattern. **Highest-value single item.**
- **L1 iterator fix is well-aligned** (§1d, §4 seed #9). fukuii's batched `unboundedScan` (#1355) is at the strong structural end — preserve it; do **not** "align to besu" (whose `Stream.onClose` is weaker). Only additive move: export a live-iterator metric.
- **Closest authority is besu.** For any storage tuning question (per-CF cache, compression, BlobDB, high-spec sizing, `setStatsDumpPeriodSec(0)` JNI-crash guard), besu is the apples-to-apples reference; cross-check fukuii's `RocksDbConfig`/`RocksDbDataSource` against `RocksDBColumnarKeyValueStorage`.
- **Flat-storage overlay ↔ Bonsai.** fukuii already carries `FlatAccountStorage`/`FlatSlotStorage` as a read-path overlay *alongside* the hash-keyed trie — architecturally besu's Bonsai (flat + thin proof trie) is the direct Phase-3/4 comparison for whether to promote that overlay into a first-class pruned-node mode (end-user role).
- **Online full-pruning is the biggest missing operator capability.** nethermind's copy-live-then-swap (§4 seed #6) maps to the CEX/custody and end-user roles (reclaim disk, no resync). fukuii's per-`NodeStorage` fixed-pruning-mode model has no live path today.
- **Per-CF/per-table-shape tuning is under-explored.** reth's `tx_hash_numbers` (compression + bloom OFF for incompressible-always-hit tables) and nethermind's options-string-per-DB show table-shape-aware tuning; fukuii's namespace CFs likely use uniform options — a Phase-3 audit target.
- **`ETC introduces no storage-schema divergence`** (core-geth doc headline). The go-ethereum/besu storage references apply to fukuii's PoW family unchanged; storage authority does **not** route through core-geth's consensus authority. The one PoW-relevant storage detail is retaining **total-difficulty** state (core-geth's `diffs` freezer table) — don't "modernize away" TD, ETC fork choice needs it.
- **Multi-network angle** (core-geth's "fork the config system, not the storage schema"): network identity belongs in the config/type layer, not storage keys — the same datadir schema serves every family. Reinforces keeping fukuii's CF layout network-neutral.
