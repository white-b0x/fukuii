# go-ethereum — testing
_Commit/branch documented: 59e89e81e / upstream. Documented 2026-07-13._

## Architecture summary

go-ethereum's conformance test layer lives in the `tests/` package. It is a thin
Go harness that consumes JSON fixtures from the external `ethereum/tests`
repository (vendored as a git submodule at `tests/testdata`, per
`.gitmodules:1-5`) plus fixtures generated by execution-spec-tests (EEST). Four
fixture families are wired, each with its own runner file and a matching
`XxxTest` fixture type:

- **State tests** (`state_test.go` → `state_test_util.go`): per-transaction
  state transitions, validated by post-state root + logs hash.
- **Blockchain tests** (`block_test.go` → `block_test_util.go`): full block
  import against a genesis, validating header fields, post-state accounts, and
  imported-header consistency.
- **Transaction tests** (`transaction_test.go`) and **RLP / difficulty tests**
  (`rlp_test.go`, `difficulty_test.go`): narrow codec/algorithm fixtures.

All four sit on one shared engine: `testMatcher` (`init_test.go:93-282`), a
reflection-driven directory walker that turns every `.json` file into a Go
subtest, applies skip/slow/expected-fail patterns, and parallelizes.

Separately, `cmd/evm` ships the **t8n** (transition), **t9n** (transaction), and
**b11r** (block-builder) tools (`cmd/evm/README.md:1-8`). t8n is the stateless
state-transition binary that EEST and hive/retesteth drive to *generate and
validate* the very fixtures the `tests/` package later consumes — geth is both
the fixture producer and a fixture consumer.

Fuzzing is a third, orthogonal layer: `tests/fuzzers/` holds native Go
(`testing.F`) fuzz targets, several of which are **differential** (cross-check
geth's crypto against an independent library).

## Key types / interfaces / files

- `tests/init_test.go:93-100` — `testMatcher` struct: holds `configpat`,
  `failpat`, `skiploadpat`, `slowpat`, `runonlylistpat` regexp lists. The single
  reusable driver for every fixture family.
- `tests/init_test.go:196-219` — `(*testMatcher).walk`: `filepath.Walk`s a dir,
  emits a `t.Run` subtest per `.json` file. Prints "did you clone the tests
  submodule?" and `t.Skip`s if the fixture dir is absent (`:200-201`) — missing
  fixtures skip, never fail.
- `tests/init_test.go:221-253` — `runTestFile`: loads JSON into a
  `map[string]<TestType>`, sorts keys for determinism (`sortedMapKeys`,
  `:267-274`), and `t.Run`s each map entry as a nested subtest. Single-entry
  files are not wrapped (`:240-241`).
- `tests/init_test.go:255-265` — `makeMapFromTestFunc`: reflection glue that lets
  one `walk` serve any `func(t, name, *XxxTest)` runner. This is why all four
  families share one engine.
- `tests/init_test.go:112-160` — `slow`/`skipLoad`/`fails`/`runonly`/`config` +
  `findSkip`: the pattern-based test-selection vocabulary. `slow` = skip only in
  `-short`; `skipLoad` = never even parse; `fails` = expected-failure with a
  mandatory reason (`:126-127` panics on empty reason).
- `tests/init.go:28-30` + `Forks` map (`:28`..) — the canonical fork→`ChainConfig`
  table (Frontier … Prague/Osaka). Fixtures name a fork string; the harness looks
  up the config here. Single source of fork wiring for all fixtures.
- `tests/state_test.go:64-108` — `TestState` / `TestLegacyState` /
  `TestExecutionSpecState`: three entry points walking `GeneralStateTests`,
  `LegacyTests`, and the EEST `spec-tests/fixtures/state_tests` dir respectively.
- `tests/state_test.go:107-181` — `execStateTest`: runs each subtest under a
  **4-way execution matrix** — `{hash,path} × {trie,snap}` — via a bitmask
  (`hash/trie`, `hash/snap`, `path/trie`, `path/snap`). `-short` randomly runs
  only one permutation (`:114-117`).
- `tests/state_test_util.go:221-260` — `(*StateTest).Run`: executes the
  transition and asserts `post.Root` (`:257`) and logs hash (`:260`) mismatch —
  the golden-value check.
- `tests/state_test.go:186-215` — `withTrace`: runs the test bare; on failure
  **re-runs with the EVM struct-logger enabled** and dumps the trace (unless gas
  > `traceErrorLimit` = 400000, `:184`). Trace is a debugging artifact, not part
  of the assertion.
- `tests/block_test_util.go:116-207` — `(*BlockTest).Run`: commits genesis,
  checks genesis hash/root (`:150-153`), `InsertChain`s the fixture blocks
  (`:261`), validates decoded headers field-by-field (`validateHeader`,
  `:287`), post-state accounts (`validatePostState`, `:354`), and imported
  headers (`validateImportedHeaders`, `:380`).
- `tests/init_test.go:36-48` — the fixture-directory constants (`baseDir`,
  `blockTestDir`, `executionSpecStateTestDir`, `benchmarksDir`, …). Maps the
  submodule + EEST layout to Go paths in one place.
- `cmd/evm/internal/t8ntool/transition.go:95` — `Transition(ctx)`: the t8n
  entry: reads `--input.{alloc,env,txs}`, applies txs to the prestate, emits
  post-state root/txroot/receiptroot + rejected txs. The reference oracle.
- `cmd/evm/eest.go:23-49` — `testMetadata` / `parseTestMetadata`: parses the
  EEST-encoded filename (`fork`, python `module`, `file`, `function`,
  `parameters`) so failures point back to the generating spec test.
- `cmd/evm/t8n_test.go:34-49` — `TestMain` + `reexec`: golden-file testing of the
  t8n *binary itself* by re-exec'ing the compiled tool and diffing stdout against
  `cmd/evm/testdata/*` (validates the oracle's own output stability).
- `tests/fuzzers/` — native Go fuzz targets: `bls12381`, `bn256`, `difficulty`,
  `rangeproof`, `secp256k1`, `txfetcher`. Signatures like
  `tests/fuzzers/difficulty/difficulty_test.go:21` (`func Fuzz(f *testing.F)`).
- `tests/fuzzers/bls12381/bls12381_fuzz.go:34,46,91` — **differential fuzzing**:
  cross-checks geth's `gnark`-based BLS12-381 against `supranational/blst`,
  `panic`ing on any divergence (subgroup check, pairing). `//go:build cgo` gated.

## Design decisions & rationale

- **Fixtures are external, versioned by submodule.** `tests/testdata` pins an
  `ethereum/tests` commit (`.gitmodules`, `shallow = true`). The Go code carries
  zero fixture data; upgrading conformance coverage = bumping a submodule SHA.
  Missing submodule → `t.Skip`, not failure (`init_test.go:200-201`), so a fresh
  checkout still builds and the unit suite runs.
- **One reflective engine, many fixture types.** Rather than four bespoke
  loaders, `testMatcher.walk` + `makeMapFromTestFunc` reflect over the runner's
  third argument type. Adding a new fixture family is a new `XxxTest` struct + a
  one-line runner closure.
- **Skip taxonomy is code, not config.** `initMatcher` (`state_test.go:39-62`,
  `block_test.go:26-73`) enumerates every skipped/slow/broken fixture inline with
  a comment explaining *why* ("EOF is not part of cancun", "Uses 1GB RAM per
  fork", "After the merge we accept side chains…"). The skip list doubles as a
  living compatibility ledger.
- **Deterministic subtest naming.** Keys are sorted (`sortedMapKeys`) and subtest
  names are the slash-joined fixture path + JSON key, so `-run` can target one
  vector and CI output is stable across runs.
- **Test-matrix over storage backends.** State tests run the same vector against
  hash-scheme and path-scheme tries, with and without the snapshot layer
  (`state_test.go:107-181`). Conformance is asserted not just for the EVM but for
  every persistence path — a single fixture exercises four storage configs.
- **The oracle is specified strictly.** t8n's README explicitly frames it so
  "other node implementors can build replicas… and state generators can swap
  between a `geth`-based and a `parityvm`-based implementation"
  (`cmd/evm/README.md:30-31`). t8n's I/O contract *is* the interop spec.

## Notable patterns (the reusable idea)

1. **Pattern-driven test selection (`slow`/`skipLoad`/`fails`).** A small regexp
   vocabulary lets the harness (a) never-parse known-irrelevant fixtures, (b)
   downgrade heavyweight vectors to `-short`-only, and (c) mark known-broken
   vectors as *expected* failures with a mandatory human reason. This keeps CI
   green without deleting coverage and records the rationale next to the skip.
2. **Golden-value assertion = post-state root + logs hash.** The entire state
   test reduces to "does the computed root/logs-hash equal the fixture's?"
   (`state_test_util.go:257,260`). No behavioral introspection — one hash
   comparison catches any consensus divergence.
3. **Trace-on-failure, not trace-always.** Run cheap; only on a mismatch re-run
   with the struct logger and dump the EVM trace (`withTrace`). Keeps the happy
   path fast while giving a full opcode trace exactly when a human needs it.
4. **Binary golden-file tests via re-exec.** `cmd/evm/t8n_test.go` compiles and
   re-exec's the actual tool, diffing stdout against checked-in expected JSON —
   the oracle's own output is regression-locked.
5. **Differential fuzzing for crypto.** Cross-implementation fuzz targets panic
   on any divergence between geth's primitive and an independent library
   (`bls12381` vs `blst`), catching subtle crypto bugs no fixture enumerates.

## Authority note

**geth is the de-facto reference oracle.** The `evm t8n` transition tool is the
state-transition binary that execution-spec-tests (EEST) and hive/retesteth drive
to *produce and validate* the `ethereum/tests` and hive fixtures that every other
client — including fukuii — is then measured against. Its I/O contract is
deliberately specified as an interop boundary so other implementations can build
byte-compatible replicas (`cmd/evm/README.md:30-31`). When a fixture and a
client disagree, the fixture (i.e. geth's t8n output, cross-checked by the spec)
is the authority. Note: this authority is for **ETH/PoS EVM semantics**; for
ETC/PoW-specific rules (ECIP-1017 emission, ETChash), **core-geth** remains
fukuii's PoW oracle — geth's `tests/init.go` `Forks` table has no ETC/Olympia
entries.

## Gotchas / anti-patterns / things they later changed

- **Missing-submodule skip can silently zero coverage.** `walk` `t.Skip`s the
  entire suite if `tests/testdata` isn't cloned (`init_test.go:198-202`). A CI
  that doesn't init submodules reports "PASS" while running nothing. fukuii's
  equivalent must fail loudly (or assert a nonzero fixture count) rather than
  skip.
- **The skip lists rot.** `initMatcher` accumulates fork-specific broken-test
  regexps (`RevertInCreateInInit`, `create2collisionStorageParis`,
  `powToPosBlockRejection.json` "unrunnable" post-history-removal). These are
  load-bearing but easy to leave stale after the underlying fixture is fixed.
- **`-short` makes state tests non-deterministic-ish.** Under `-short`,
  `execStateTest` runs a *random* one of the four storage permutations
  (`state_test.go:114-117`, `rand.Int63()`). Reproducing a `-short` failure may
  require re-running until the same permutation is picked — full runs are the
  reliable gate.
- **EOF and post-merge divergences are hard-skipped, not handled.** e.g.
  `st.skipLoad("^stEOF/")` ("EOF is not part of cancun") and several
  `bcMultiChainTest`/`bcTotalDifficultyTest` skips ("After the merge we would
  accept side chains as canonical even if they have lower td",
  `block_test.go:56-63`) — the fixtures encode pre-merge fork-choice the current
  client no longer implements. A multi-network client must scope such skips per
  network, not globally.
- **cgo-gated differential fuzzers.** The strongest crypto cross-checks
  (`bls12381`) require `//go:build cgo` + a native `blst` — they silently don't
  run in a pure-Go/cgo-disabled build. Don't assume the differential coverage is
  active unless cgo is on.
- **Fork wiring is centralized but ETH-only.** `tests/init.go` `Forks` is the one
  place fixtures resolve a fork name to a config; it hardcodes ChainID 1 and the
  ETH fork ladder. There is no seam for an alternate (ETC) fork table — a
  multi-network harness needs a per-network `Forks` map, not geth's single global.
