## Best-practice synthesis
DEFAULT + OPTIONAL menu for fukuii (Scala 3 `bytes`/`crypto`/`rlp` modules).

- **RLP codec — DEFAULT: typeclass/`derives`-derived codecs.** reth's alloy `#[derive(RlpEncodable)]` and nethermind's per-type decoder registry both map onto a Scala 3 `given RLPCodec[T]` / `derives RLPCodec`: compile-time-resolved, per-type, explicit, no reflection walk. This wins on both correctness (explicit fork-conditional and storage-vs-wire variants stay visible per type) and perf (monomorphized, no runtime field walk), and it fits fukuii's existing RLP typeclass approach. Prefer it over hand-rolled encoders. **besu's streaming-cursor `RLPInput`/`RLPOutput` is the JVM *structural* analog** — the shape to mirror for the reader/writer plumbing under the typeclass (accumulate-then-single-walk encoder for nested lists), not a competing codec-authoring model.
- **Crypto — OPTIONAL(role): native fast-path + pure fallback behind one API.** Four of six clients ship a dual backend (geth/core-geth/besu/erigon); nethermind is managed-first with native only where decisively faster. Adopt one API with two impls selected once — the native path serves validator/archival/mining-pool throughput on the hot sign/hash/pair path; the pure path guarantees the enterprise single-binary builds and runs everywhere (no per-platform JNI). Caveat: the two paths are a correctness surface — they must be output-identical (the pure path may need to re-add checks the native lib does for free, e.g. low-S signature malleability rejection).
- **Value types — DEFAULT: fixed-width wrapper value types** (Tuweni `BytesHolder`/`BaseUInt256Value`, geth `[N]byte`) over raw `byte[]`/`BigInteger`; in Scala 3 this is opaque types over `Array[Byte]`/`ByteString`, type-distinct so `Wei` can't silently mix with a raw `UInt256`.
- **Shared-lib seam — OPTIONAL(role: tooling-family):** reth/alloy show primitives can be an ecosystem library, not client-private code; for fukuii the analog is module/artifact boundaries (already three sbt sub-modules) publishable across an ETC tooling family — inherits both granular-upgrade upside and version-skew/supply-chain cost.
- **NOTE — the JVM zero-alloc caveat:** nethermind's zero-alloc-struct machinery (`ValueHash256` as a SIMD `Vector256<byte>`, `Span<byte>`, `ref struct` readers) **does NOT port to the JVM**. Scala's ceiling is erasing the *wrapper* object via opaque types; it cannot inline 32 bytes into a containing object the way C# structs do — the backing array still heap-allocates. Chase erigon's *pooling/benchmark* discipline (which does transfer) rather than nethermind's memory-layout tricks (which do not).

## fukuii implications (forward-ref to Phase 3–4, do NOT act here)
fukuii's `bytes`/`crypto`/`rlp` modules are the natural **SR-10 first Phase-3 subsystem** — primitives sit at the low of the dependency graph, everything depends on them, and core-geth confirms this is an "inherit, do not fork" ecosystem-shared boundary (ETC/ETH diverge in consensus, never in primitives). Seeds for SR-10 to green-light there, not verdicts to act on now:

- Adopt derive/`given`-derived RLP codecs (reth alloy + nethermind registry → `given RLPCodec[T]`) over any hand-rolled encoders, with besu's streaming-cursor reader/writer as the underlying JVM shape.
- Assess the native/pure crypto dual-backend as an OPTIONAL(role) seam sized to fukuii's target roles (validator/archival/mining-pool throughput vs enterprise single-binary portability), keeping the two paths output-identical against go-ethereum byte-level behavior.
- Keep fixed-width opaque value types; explicitly do **not** attempt nethermind's inline zero-alloc structs on the JVM.
- Borrow erigon's profile-driven alloc-benchmark harness discipline for the serialization hot path once the codec shape is settled.

Authority reminder for SR-10: **go-ethereum** = canonical primitive *behavior* (RLP byte layout, keccak, secp256k1 low-S, EIP-2718/2537/4844) for both families; **core-geth** = ETC/PoW authority but a pure geth passthrough at the primitives slot; **besu** = JVM structural analog; **reth/alloy** = shared-lib + derive-macro model; **nethermind** = per-type decoder registry (adopt) + zero-alloc structs (JVM-caveat, do not port).
